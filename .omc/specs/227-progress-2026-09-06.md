## §5 Deviations from the design, and why

1. **New names are reached through in-function imports in the tests**
   (`import aelix_ai.oauth._resolve_config as rc`), not module-level ones: a
   module-level import turns the whole file into ONE collection error and hides
   case 11's behavioural RED. Precedented in this file (#226's cases) and in
   `test_powershell_classifier.py`.
2. **Case 1 is green on `main`** (§1) — the design's own demotion, recorded
   rather than "fixed".
3. **Cases 16/17 narrow `PATH` on the win32 arm only.** "`env` is ignored off
   win32" is true of *resolution* but not of the child's own lookup:
   `Popen(["sh", …])` still finds `sh` through the inherited `PATH`, so narrowing
   it on POSIX would break the case rather than leave it identical. Both also
   assert `spawned in _shell_argv_candidates("echo x")`, which is what makes them
   import-RED as the design claims and pins that what ran came from the chain.
4. 🔴 **Case 12 as drafted did not kill mutation (h).** With ONE injected
   candidate the pre-loop `failure.argv = candidates[0]` already holds the right
   answer, so dropping the in-loop assignment left the case green (measured).
   Strengthened to two candidates whose first cannot spawn; the message must now
   name the second and neither the first nor `sh`. (h) then dies.
5. 🔴 **Mutation (a) is killed by cases 2 and 3, not by case 18.** Case 18 lives
   in the bash-tool file and never calls `_shell_argv_candidates`, so it cannot
   see that branch being dropped (measured: `2 failed, 1 passed`). The design's
   table row is corrected here; the mutation is still killed.
6. **`_shell_argv` renders the `cmd` family with `shell.command_flag`** rather
   than a literal `/c`. Dispatch is still `shell_basename` (mutation (k) pins
   it); on every candidate the primitive produces that flag is `/c`.
7. **The stale "mirrors ``tools/bash.py:990``" line is in
   `packages/aelix-coding-agent/src/aelix_agents/tool.py`**, not in
   `docs/decisions/` as §F says — i.e. it is a *gated* citation. Restated by
   function name (`create_bash_tool`); the reflow shifted `tool.py` by one line,
   which is the second family of drift `--fix` relocated (`tool.py:*`, +1)
   beside the expected `bash.py:*` (-69).
8. Follow-up placeholders replaced with the filed numbers **#240 / #241 / #242 /
   #243** in the ADR-0238 amendment.
9. `bash.py`'s diff is **88 deleted / 19 added**, net **−69** (1002 → 933 lines),
   not the design's 86 out. The **84 / 15** first written here was the true numstat
   of the five *move* hunks at review time, staled by FIX 7(d)'s +4/−4 docstring
   reflow — line-count-neutral for the FILE, which is why item 7's `bash.py:*`
   (-69) drift still holds, but not for the diff's two counts. A stale number
   propagated by a "net-neutral" inference is exactly how this went wrong.
   Re-taken 2026-09-08:
   `git diff --cached --numstat -- packages/…/tools/bash.py` → `19	88`.
10. 🔴 **ADR-0140 is not in `docs/decisions/README.md` at all, and this change did
   not add it** (review DOC-7 / FIX 11, recorded rather than fixed because adding an
   index row is the owner's call). Measured on this worktree:
   `grep -c '0140' /tmp/wt-227/docs/decisions/README.md` → **`0`**, while
   `docs/decisions/0140-models-json-custom-model-loader.md`:3 now reads
   `Status: Accepted (**#227 amendment 2026-09-08** …)` — 2026-09-06 until round-2
