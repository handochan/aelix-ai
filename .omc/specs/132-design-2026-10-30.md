# #132 — the delegation panel: design (final, 2026-10-30)

Base: main `9d1517a8` (#610 merged). Issue: #132 (absorbs #26). B7 guaranteed item.
Owner scope (2026-10-28 comment on #132): one panel for one or many children; per child
the running tool and its arguments, recent tool calls (ok/FAILED), the last reply line,
elapsed time and time without output, tokens, model. Widen the `_publish` projection,
add a time-based throttle, sanitise like #178. Glyphs / aligned columns / "N agents"
header are in scope, second to the activity content. Done = `uv run aelix` checked by
hand (single, parallel, chain, Esc, narrow terminal), no flicker, separate verify pass.
Owner 2026-10-30: "ui작업 신중히" (be careful with the UI); layout **A — two rows per
child** chosen from three rendered options (A 2 rows, B 1-row table, C 3 rows).
Baseline (BEFORE): `132-baseline-2026-10-30.md`.

## 1. What is on screen today (main 9d1517a8) — see the baseline

- Single delegation: a per-child statusline segment that is never visible at 80/120 columns
  under a yolo parent (the disclosure row takes the line). No panel
  (`PANEL_MIN_CHILDREN = 2`, ADR-0199 S10).
- Batch: an aggregate statusline segment (also pushed off-screen) + a `▌` panel capped at
  78 cells whose numbers column is ~12 cells (`running · b…`).
- The tool-card partial (`ctx.on_partial`, `panel.format_card`) renders NOTHING in the TUI
  (`render.py` no-ops `tool_execution_update`; ADR-0199 §(l) correction) — model/event
  stream only. Its P2 byte-identity rule binds no visible surface; it stays as it is.
- Rows change only when the child writes stdout: `sleep 12` shows a frozen `2s`.
- `current_tool` is cleared only on `turn_start`/`agent_end`: a finished tool keeps
  showing as current while the model thinks.
- Esc: the panel vanishes; `✖ Operation aborted` and nothing of what the children did.

## 2. Decisions

**D1 — one panel for every delegation the model's `agent` tool makes.** Single, parallel,
chain and resume, N = 1 included: the extension opens a group for every call
(`PANEL_MIN_CHILDREN` becomes 1). Supersedes ADR-0199 S10's "a single delegation keeps
P2's surfaces exactly" for the LIVE UI (owner decision 2026-10-28). `/agents run`
(ungrouped) keeps its per-child statusline row, byte-identical.

**D2 — grouped members write no statusline row, and a group writes no aggregate row.**
The panel header carries those facts; the baseline shows the statusline copy was pushed
off-screen anyway. The yolo disclosure row (ADR-0231, #196) is unchanged.

**D3 — the projection is widened, additively.** `SubagentProgress` gains
`activity: tuple[SubagentToolActivity, ...] = ()` and `last_text: str | None = None`;
new frozen dataclass `SubagentToolActivity(name: str, args: str = "", status:
SubagentToolStatus = "running")`, `SubagentToolStatus = Literal["running", "ok",
"failed", "no_result"]`. Defaulted, so `CONTRACT_VERSION` stays 1 (precedent:
`model`/`provider`). The RPC host forwards a fixed field list
(`rpc/control.py:bind_progress`), so the RPC wire is unchanged (exposure is #612).
Both fields are CHILD-AUTHORED: every renderer flattens them (#178).

- `activity` = the child's last `ACTIVITY_MAX = 4` tool calls, oldest first, from a new
  bounded `_StreamState.recent` deque that EVERY `tool_execution_start` appends to (the
  trail stops at `MAX_TRAIL_ENTRIES = 200` and would freeze "recent"). The same
  `ToolCall` object is shared with the trail while the trail has room;
  `_close_trail_entry` closes the match in both. `args` is the trail's existing rendered
  primary argument (`_render_args`: path / command / pattern…, control-stripped, one
  line, ≤ 120 chars).
- Status: `failed is True` → `failed`; `False` → `ok`; `None` → `running` only while the
  call is in the child's CURRENT turn and the run is open and the child is live
  (`ToolCall` records the turn it opened in; `_StreamState` counts `turn_start`s);
  otherwise `no_result` (an end event that never came — what a stopped child leaves).
- `last_text` = the latest text-bearing assistant message, whitespace-collapsed to one
  line and bounded (≤ 512 chars), computed ONCE in `_reduce_message_end` where
  `summary` is set (not per publish). `message_update` stays ignored (O(n²)), so it
  changes per completed message.
- No idle field: the runtime publishes after every stdout line (including
  `message_update` and tool-update lines), so "time since the last snapshot arrived"
  IS "time since the child last wrote anything". The bridge stamps arrivals.

**D4 — layout A (owner's choice).** Pure functions in `panel.py`; raw SGR as the module
already does; every untrusted part `_flatten`ed on its own, widths in cells
(`rich.cells.cell_len`, `_cut_to_cells`), CJK-correct.

- Gutter `│ ` (dim) — the same gutter a transcript tool card's body uses (`render.py`
  `│ ` rows), so the panel reads as the live body of the `● agent(…)` header printed
  just above it. Replaces `▌ `.
- Width: the live terminal width (`tui.width.terminal_columns(chrome)`, the transcript's
  own cap, default 120), re-read on every render. No 78-cell ribbon.
- Glyphs (state): queued `○` dim · starting/running/thinking `●` cyan · done `✓` green ·
  failed `✗` red · stopped `■` yellow. Call marks: `✓` ok green, `✗` failed red,
  `■` no result yellow, `▶` running cyan. Last reply in `“…”` dim italic. Numbers dim.
- Time: `9s`, `1m12s`, `1h02m`. Idle shown as `idle 7s` only at ≥ 5 s.
  Tokens `1.5k` in rows, `1.5k tok` in the header. Cost only in the header.

N = 1 (single, resume) — 5 rows:
```
│ ● agent worker · s-1 · running                     idle 7s · 1m12s · 1.5k tok
│   ✓ read notes.txt
│   ✗ $ pytest -q tests/test_retry.py
│   ▶ $ sleep 12 · idle 7s
│   “Read the notes; one test fails, re-running the slow step.”
```
Header: glyph, `agent <profile>` (`(resumed)` for a resume), model, state word
(`starting` / `running` when a call is open / `thinking` when live with no open call /
`done` / `failed` / `stopped`); right-aligned elapsed, tokens, cost. Rows 1–3: the last
three calls, oldest at the top, filled top-down; rows not yet filled are gutter-only.
Row 4: the last reply, or `waiting for the first reply` (dim) before there is one.

N ≥ 2 — header + 2 rows per child (owner's choice A):
```
│ 3 agents · worker · s-1 · 2 running · 1 done                   14s · 1.2k tok
│ ● 1  Read notes.txt and wait six seconds, then report.              6s · 0.4k
│      ✓ ▶ $ sleep 6 · idle 4s
│ ● 2  Wait ten seconds, echo bee, then report.                       8s · 0.4k
│      ✓✓ thinking · “Waiting ten seconds before echoing bee.”
│ ✓ 3  Write c-out.txt, wait fourteen seconds, then report.          14s · 0.4k
│      ✓✓✓ “Wrote c-out.txt and waited fourteen seconds.”
```
- Header: `{N} agents` (`chain of {N}` for a chain) · profile · the batch model when the
  members agree (else each child row 1 carries its model before the numbers) · state
  counts in today's fixed order; right: max elapsed, max tokens (`tokens` is a level,
  never summed — §(i)), summed cost.
- Row 1: glyph, submitted index (1-based), the task label (cut with `…`), right-aligned
  `elapsed · tokens`. A chain step's `{previous}` placeholder renders as `‹previous›`.
- Row 2, indented under the label: up to 3 outcome marks of the calls before the
  current one, then NOW:
  - a call open → `▶ <call>` (+ ` · idle Ns` at ≥ 5 s);
  - live, no open call → `thinking` (+ ` · idle Ns`) (+ ` · “<last reply>”` if any);
  - done → `“<last reply>”` (or `done`); failed → `failed · “<last reply>”`;
  - stopped → `stopped` (+ the cut call as `■ <call> · no result`);
  - queued → `waiting to start` (parallel) / `waiting for step k` (chain); starting →
    `starting`.
- Call rendering (shared by both layouts): `bash` → `$ <command>`; any other tool →
  `<name> <args>` (args = the trail's primary argument). Flattened, cut to fit.
- Compact mode — 1 row per child, `● 1 <label…>  <marks> <now…>   <elapsed>` — when
  N ≥ 5, or when `1 + 2N` exceeds the height budget.
- Height budget = `max(5, terminal_rows // 3)`; hard cap `PANEL_MAX_ROWS = 9` stays (the
  widget has no downstream bound — F2). N = 1 → 5 rows, N = 2..4 → 1 + 2N (5/7/9),
  compact → 1 + N.

**D5 — fixed height for the life of a group.** The row count is decided at
`begin_group` (from N, the mode and the terminal's rows at that moment) and every frame
of the group — including the Esc frame (D7) — has exactly that many rows. A child's
first tool, first reply or end never changes the panel's height; a resize changes the
width only. (Height changes are what moved the input/status rows — `chrome.py`'s note
on the reverted widget gating.)

**D6 — refresh: throttle plus a 1 s tick.** Ingest every snapshot (bus channels
unchanged and still edge-triggered); never render from the publish path directly. A
snapshot marks the group dirty and schedules one render no sooner than 250 ms after the
previous render (`loop.call_later`) — N chatty children cost ≤ 4 panel writes/s. While
any member is live, a 1 s tick re-renders so elapsed and idle advance while a child is
silent. Writes still go through `_set_widget`'s line-tuple dedup. The scheduler and the
clock are injectable; with no running loop (tests, a sync caller) the bridge renders
immediately, as today. `end_group`/`clear` cancel every handle. Chrome is not touched:
it already repaints at 10 Hz for the spinner and its renderer writes only changed cells.

**D7 — Esc leaves the children's record on screen until the next prompt.** On cancel
the extension does not blank the panel: it hands the bridge each started member's
changed files (from the same `CallEnvelopes.snapshot()` the model's report is built
from, `SubagentResult.changed_files`) and the bridge renders a final frame — same
height (D5) — and keeps it until the next `before_agent_start`, a new group, or
`clear()` (session switch / teardown). The frame:
```
│ ■ agent worker · stopped — the turn was cancelled                2 turns · 3.6s
│   ✓ write notes.md
│   ■ $ sleep 97 · no result
│   changed: notes.md
│   Ask to continue it and the model can resume it.
```
(N ≥ 2: header `3 agents · stopped — the turn was cancelled · ask to continue them`;
row 1 per child as before with `■`/`✓`/`✗`; row 2 `marks ■ <cut call> · no result ·
changed: <files>` or the last reply for a member that had finished.) A member that never
started stays `○ … not started`. A normal finish still clears the panel: the result card
in the transcript is the record.

**D8 — not changing.** `chrome.py`, `shell.py`, `render.py` (B6 serial-integration
constraint; the flicker path ADR-0194 fixed three times), `format_card` and
`PartialThrottle`, the `subagent_*` channel semantics, the RPC wire, the disclosure row,
`/agents run`'s row.

## 4. Verification

- Unit: layouts against hand-built snapshots (CJK, hostile strings, widths 30–200,
  N = 1..8, chain, queued, stopped/Esc frame); the fixed-height invariant over a whole
  simulated group life; throttle/tick against a fake scheduler and clock; `recent`/status
  projection in the reducer; extension wiring (group for N = 1, no grouped status rows,
  linger on cancel, dismissed by `before_agent_start`).
- Live TUI (scripted provider, pty + pyte, the baseline driver): single, parallel, chain,
  resume, Esc, at 80x24 / 80x30 / 120x40 / 60x30; the baseline's flicker counters; rows
  above the input constant through each group.
- Real model once (OpenRouter `anthropic/claude-haiku-4.5`) in the TUI.
- Separate verify pass + Codex cross-review (round 1); at most two fix rounds.
