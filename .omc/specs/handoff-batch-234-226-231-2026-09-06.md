## 3. 이 레포에서 이번에 물린 것

1. 🔴 **`SendMessage`로 이미 반환한 워크플로우 레인에 답하면 그 레인이 *재개*된다** — 같은 worktree에
   두 번째 작성자가 생겼다(#226 수정 레인). 재개된 인스턴스가 스스로 알아채고 멈췄고 이중 적용은 없었다
   (마커 문자열 ×1, `ast.parse`, 인덱스 해시 불변으로 확인). 워크플로우 레인은 `ListAgents`에 안 보인다.
   답은 다음 레인의 프롬프트/수정 목록에 넣거나 `resumeFromRunId`로. 메모리에 저장함.
2. **`AELIX_AUTH_PATH`는 auth.json 저장 경로가 아니다** — 설계 §E.3의 그 arm은 아무것도 읽지 않았고
   `No API key found`만 냈다. 캐시 경로는 `$AELIX_CODING_AGENT_DIR/auth.json`에 파일을 두면 탄다(그러면
   설계가 예측한 `died with <Signals.SIGKILL: 9>. The command stopped …` 그대로).
3. **`models.json` 프로바이더에 `api`가 없으면 로드 자체가 실패한다** — 설계의 §E 스니펫에 빠져 있었다.
   `"api": "openai-completions"` 필요.
4. **tmux 캡처는 `tail`이 아니라 전체 페인에서 빈 줄을 걸러라** — TUI는 입력창이 바닥에 있어 `tail -8`이
   빈 줄만 잡는다(#234 첫 캡처가 그랬다). `clear` + `tmux clear-history` 없이 재시작하면 이전 TUI 출력이
   스크롤백에 섞여 판독 불가(#226 auth arm 첫 캡처).
5. **`pgrep -fl '<pattern>'`은 자기 bash -c 인자를 센다** — 백그라운드 스크립트의 명령줄에 패턴이 들어
   있으면 스트레이 29처럼 보인다. `ps -axo command | grep | grep -v 'bash -c'`로 세라.
6. **darwin의 호스트 pyright는 win32 typeshed에 없는 `os` 이름을 못 본다** — `WNOHANG`/`WUNTRACED`/
   `WIFSTOPPED`/`WSTOPSIG`는 `# pyright: ignore[reportAttributeAccessIssue]`가 필수이고,
   `.venv/bin/pyright --pythonplatform Windows`가 게이트 레그의 모델이다(#226 리뷰 TESTS-1, 그 레그에서
   pytest 전에 빨간 4 errors).
7. **`shutil.which`는 win32에서 PATHEXT를 대문자로 붙인다** — `fd.EXE` vs `fd.exe`를 문자열 비교하면
   windows 레그가 빨갛다; `Path` 동등 비교로(#231 리뷰 TL-1). 그리고 win32는 `path=`보다 CWD를 먼저
   찾으므로 부정 단언은 빈 디렉터리로 `chdir`한 뒤에.
8. **`tests/tui/conftest.py`의 autouse `_isolate_agent_dir`와 `tests/conftest.py`의
   `_no_real_tool_downloads`** — `get_bin_dir()`은 매 테스트 새 임시 디렉터리, `tools_manager._bin_dir`은
   세션 임시 디렉터리로 대체된다. `cli.config.get_bin_dir`만 패치하면 `get_tool_path`는 못 본다 — 두 seam
   다 패치(#231 케이스 5). `monkeypatch.setenv("HOME")`은 무력.
9. **`start_new_session=True` + `TIOCSCTTY`로 pytest 안에서 controlling terminal을 만들 수 있다** —
   pytest 인터프리터를 fork하지 않고(`os.openpty` + 자식 첫 줄 `ioctl`), 부모에 ctty가 없는 CI 조건에서도.
   `pty.fork`한 부모는 고아 세션 리더라 SIGTTIN이 EIO로 바뀐다(함정).
10. **정지 탐지 프로브는 exit한 리더를 reap한다** — `Popen._try_wait`가 `ChildProcessError`를 `sts=0`으로
    삼켜 `exit 7`이 `0`으로 보고됐다(실측) → `proc.returncode = os.waitstatus_to_exitcode(status)`로
    돌려준다. 그리고 그 사이트는 이제 pgid를 핀하지 않는다(ADR-0238 "hazard" 문장 교정).
11. **dash는 `-c`의 단일 명령을 exec하지 않는다**(darwin bash 3.2는 한다) — 게이트 레그에서 헬퍼는 항상
    리더 쉘의 자식이지만 신호가 그룹 배달이라 탐지된다. 테스트 명령은 `exec sleep 5`로.
12. **`ruff format`은 CI가 안 돌린다(589/844 파일이 대상)** — `main`의 `bash.py`·`test_abort_signal.py`·
    `completion.py`가 이미 format-dirty. 설계가 이름 붙인 파일에만, 또는 아예 돌리지 말 것.
13. **워크플로우 규모(이번 세션)**: 설계 43·4.9 M·64 min, 구현 36·4.4 M·103 min. 리뷰 BLOCKING은 이번에도
    전부 문서·주장의 거짓(ADR이 ADR-0235에 없는 규칙을 인용, CHANGELOG가 자기 측정을 뒤집음, 새로 쓴
    "절대" 문장이 측정에 반함)이었고 제품 코드 결함은 #226의 `if proc.returncode is not None` 가드 하나.

## 4. 반증된 것 — 다시 믿지 말 것

- ❌ "`Task.cancel()`이 `_log_traceback`을 지우므로 예외 회수가 불필요"(#234 rev 1) — 이미 실패한 watcher
  에만 해당; 취소 *중에* 실패하면 `set_exception`이 다시 켠다(3.11/3.12/3.13 실측). `finally` 안에서 회수.
- ❌ "#234의 창에 사람이 Esc로 닿는다" — 도구 호출·TUI `!command`는 `signal=None`(0/524). RPC `bash`만.
- ❌ "손실률 4.69 %(seed 234)" — 10회 재측정 1.6–3.6 %; `hi = median×1.6`을 매번 재측정해 seed가 결과를
  고정하지 않는다.
- ❌ "`run_cancellable`에 같은 suppress가 있다" — 없다(`suppress(Exception)`뿐, CancelledError는
  BaseException).
- ❌ "`process_group=0` 자식은 `/dev/tty`를 읽을 수 있다"(ADR-0238 원문) — 열 수만 있다. 읽으면 `T`.
- ❌ "`setsid`가 안전한 대안" — 경로로 연 tty에는 job control이 안 걸려 친 줄을 훔친다(`BYPATH_GOT:stolen`).
- ❌ "옵션 2는 ^C가 자식으로 가서 안 된다" — ^C는 프롬프트만 끊고 에이전트는 산다. 기각 근거는 경쟁·
  echo-off 잔존·TUI에서 Aelix 정지.
- ❌ "ADR-0235는 divergence를 사용자에게 알리라고 요구한다"(#226 설계 rev 1 한국어 문장 → ADR 초안) —
  ADR-0235에 그런 규칙 없음. 요구는 ADR 불필요뿐.
- ❌ "`!command`의 zombie가 pgid를 핀한다"(ADR-0238 hazard 문단) — #226 이후 프로브가 reap하므로 아니다.
- ❌ "fd와 walk는 `_EXCLUDE_DIRS` 덕에 같은 집합"(ADR-0193, `completion.py` docstring) — 다섯 가지로 달랐고
  predicate는 fd 출력에만 적용되고 있었다.
- ❌ "fd는 speed upgrade일 뿐" — ~5000 경로 아래서는 walk보다 느리고(spawn 8 ms), 무엇이 완성되는지를
  바꾼다.
- ❌ "`.gitignore` 계열은 repo 밖에서 무효이니 fd = walk" — `.ignore`/`.fdignore`는 어디서나, 부모
  디렉터리에서도 적용.
- ❌ "`_fd_binary`가 PATH를 먼저 봐야 한다"(#231 rev 1) — `find`와 다른 바이너리를 돌리게 된다. 관리 dir 먼저.
- ❌ "`get_tool_path`를 그대로 쓰면 된다" — PATH arm이 무한 `subprocess.run([cmd, '--version'])`(5.3 s 실측).
- ❌ "walk 폴백은 이 레포 클론에서 크게 다르다" — 클린 클론 1457 = 1457; 차이는 오너 checkout의 worktree
  사본(81 %)과 `.omc` 상태.
- ❌ "`AELIX_AUTH_PATH`로 auth.json 경로를 시험한다"(#226 설계 §E.3) — §3-2.
