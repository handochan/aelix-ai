## §5. 설계와 달라진 곳

1. **파일이 하나 늘었다 — `packages/aelix-coding-agent/src/aelix_coding_agent/docs/models-json.md`.**
   설계 §D.5는 `docs/guides/models-json.md`만 지목하는데, 이 레포는 휠에 실리는 사본을
   `tests/test_docs_bundle_sync.py`로 게이트한다(§4). 레포가 지시하는 스크립트로 재생성했다.
2. **`README.ko.md`도 고쳤다.** 설계 §D.6은 `README.md`만 말하지만 한국어 README가 같은 #202
   불릿을 그대로 갖고 있고 이 레포는 둘을 함께 움직인다. 같은 한 문장을 옮겨 적었다.
3. **pty 헬퍼가 `pty.openpty()` 대신 `os.openpty()`를 쓴다.** 같은 호출이고, 모듈 스코프에서
   `pty`를 import하면 안 되는 파일에서 조건부 import 하나를 없앤다.
4. **케이스 5의 POSIX arm이 `_stopped_by_the_terminal`을 직접 부르지 않는다.** pty 자식 안에서
   `_run_shell_command(..., failure=…)`를 통과시켜 `failure.reason is None` + rc 0 + stdout
   `ignored` + **실제로 ECHO가 꺼졌다**를 함께 확인한다. 직접 호출은 `stty`가 다른 이유로
   실패해도 공허하게 통과할 수 있다.
5. **케이스 3의 경과는 assert가 아니라 `warnings.warn`이다.** 설계 표의 "< 1.5 s"는 비용
   칸이고, 이 케이스는 인터프리터를 두 번 띄운다 — windows 레그에서 상한을 걸면 kill이 아니라
   러너 지연을 재게 된다(같은 파일의 `_TIMEOUT_S = 2.0` 주석이 이미 그 함정을 적어 두었다).
   핵심 assert인 `returncode == 7`은 그대로다.
6. **CHANGELOG에 end-to-end `time` 수치가 없다.** §E를 내가 돌리지 않았다(오케스트레이터 몫).
   본문은 0.052–0.059 s를 **리졸버 내부** 수치로 이름 붙여 적고 "plus Aelix's own startup"이라고
   쓴다. 숫자를 지어내지 않았다 — §6-2 참조.
7. **ADR의 hooks 잔여 불릿에 이슈 번호가 없다.** 없는 번호를 만들지 않았다. "a follow-up issue"로
   적혀 있고, 번호가 생기면 그 자리에 넣으면 된다(§6-3).
8. **`_run_shell_command` docstring의 첫 문단도 손댔다** — "단일 명령은 `exec`된다"가 darwin의
   bash 3.2 사실이라 플랫폼을 붙였다. 설계 §D.1이 "§B.2의 인용 규칙이 여기도 적용된다"고
   말한 그 규칙이다.

## §6. 오케스트레이터가 아직 해야 하는 것

1. **§E 라이브 체크 5건 전부** (규칙 9·10, 사람이 직접). 설계 §E의 스크립트 그대로.
   준비는 다 되어 있다 — 캐시 경로(`auth.json`)가 `_StoppedByTerminal`이 실제로 만들어지는
   유일한 경로이고, `resolve_config_value`의 프로덕션 호출자는 확인한 대로 둘뿐이며
   (`auth_storage.py:294`, `:630`) 그 위의 catcher는 `except Exception as exc`라 메시지가
   그대로 렌더된다. 기대 형태:
   `Command '['sh', '-c', "read x < /dev/tty"]' died with <Signals.SIGKILL: 9>. The command stopped reading the terminal (SIGTTIN): …`
   🔴 §E.1은 **두 arm 다** 돌린다 — (b)는 실패가 아니라 예상된 negative(rc 0 + echo off,
   `stty sane`으로 복구). §E.2의 gpg-agent NEGATIVE와 §E.5-c(약 250자 원인 문자열이 TUI
   화면에 온전히 도달하는지)도 마찬가지로 **기록이 산출물**이다.
2. **§E의 `time` 실측을 CHANGELOG 새 항목에 넣을지 결정.** 지금 본문은 리졸버 내부 수치만
   갖고 있다. 넣는다면 "resolver-internal 0.05 s"와 구분해서 적어야 한다(설계 §D.7).
3. **hooks 후속 이슈를 판다** — 본문은 ADR "What stays open"의 두 번째 불릿을 그대로 쓰면 된다
   (`ThreadedChildWatcher`의 블로킹 `waitpid(pid, 0)`, `timeout_ms` 기본 60 000/최대 600 000,
   이벤트마다 발화). 번호가 나오면 그 불릿에 넣는다.
4. **커밋.** 스테이징은 끝났다 — `git -C /tmp/wt-226 diff --cached --stat` = 11 files,
   936 insertions, 61 deletions. 본문에 **"Codex 교차 리뷰 없음(usage limit)"**을 명시.
5. **CI.** 게이팅 레그는 windows-latest이고 이 변경의 win32 절반은 **아무것도 측정되지 않았다**
   (호스트 없음): `_WAIT_STOP_OPTIONS == 0`, 케이스 1·4·5의 win32 arm, `CONIN$` 조항.
   호스트 pyright는 구조적으로 못 보므로 `--pythonplatform Windows`를 위에서 따로 돌렸다.
