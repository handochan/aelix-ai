## 1. 모델이 보는 것

**D1. 스키마와 파서.**
- `_ACTIONS = ("run", "resume")` 한 곳을 스키마 enum과 파서가 같이 쓴다(`_MODES` 선례, `A/tool.py:116`).
- 속성 추가: `action`(enum, default `"run"`), `id`(string). **`required`는 `["profile"]` 그대로 둔다.**
  - resume에서도 `profile`을 받아 저장된 이름과 **대조만** 한다. 호출자의 값으로 다시 구성하지 않는다(OpenHands가 호출자의 `subagent_type`으로 재구성해 생긴 버그의 반대 방향). 잘못 짚은 id를 잡는 정체성 확인도 된다.
  - `required` 핀(`T/agents_ext/test_tool_and_security.py:1446-1456`)이 유지된다. #611이 `status` 등에서 profile을 요구하지 않으려면 그때 `required`만 비우면 된다.
- `parse_agent_call`(:408-515) 맨 앞에 `_parse_action`:
  - `None`은 run이다. `_ACTIONS` 밖의 값은 거부한다: `action=… is not an action. Use one of: run, resume.` `""`도 거부한다(`mode=""`와 같은 규칙, :1191 테스트).
  - **run:** 지금 경로를 바이트 그대로 둔다. 단 `id`가 `_absent`가 아니면 거부한다: id는 resume 전용이다. 지금은 모르는 키가 조용히 무시돼서, 모델은 resume을 시켰다고 믿는데 새 스폰이 돈다(Part 1 §1).
  - **resume:** `profile`과 `task`는 필수다. `tasks`, `mode`(None·`"single"` 외), `cwd`, `background`는 거부한다. resume은 원래 디렉터리에서 한 자식에게 한 지시만 준다.
    - `id`가 경로 모양이면 거부한다: `/`·`\` 포함, `.jsonl`로 끝남, 절대 경로. ADR-0243 §5(모델 텍스트에 경로가 없다)와 같은 규칙이다.
    - **`id` 누락은 파서가 거부하지 않는다.** hook이 resume 가능 목록을 붙여 거부한다(D7).
    - **지시의 예산은 `MAX_TASK_BYTES - RESUME_PREAMBLE_RESERVE`(1 KiB)다.** 머리말(D13)이 붙어도 64 KiB를 넘지 않게 파서가 이 예산으로 거부하고, 거부 문장에 resume 지시의 한도를 적는다(비평 m7).
  - 모든 속성을 채워 보내는 provider는 run마다 `action: null`, `id: null` 또는 `""`를 보낸다. 없음으로 친다.
- `AgentCall`에 기본 필드 `action="run"`, `id=None`. resume은 `tasks=(instruction,)`, `mode="single"`.

**D2. id는 자식 세션 id다.**
- 모델은 이미 멈춘 자식에서 `Session: <child session uuid>`를 본다(`A/tool.py:993-994`, `A/aggregate.py:350`). 이 uuid는 같은 파일 위에서 몇 번을 resume해도 변하지 않는다. spawn key(`sub-…`)는 실행마다 새로 생기고 모델에게 보인 적이 없다.
- **성공한 자식에도 id를 보인다.** 지금은 없다.
  - single ok: 요약과 note들 뒤, 꼬리줄 앞에 `Session: <id>` 줄.
  - parallel·chain의 ok 멤버: 첫 줄이 `[i/N ok] <본문>`이라 머리줄에 붙이면 자식 글에 섞인다. 멤버 틀 안에 **자기 줄** `Session: <id>`로 둔다(비평 m2).
  - 세션 id가 없으면(세션 없는 부모, 할당 실패) 아무것도 붙이지 않는다.
- ADR-0276 D18의 "성공은 바이트 그대로"를 이 한 줄만큼 바꾼다. 갱신할 핀: `T/agents_ext/test_stopped_child_reports_604.py:733`, `:761`, `:1124`(실제 세션). `test_tool_and_security.py:1058`은 bench에 세션이 없어 그대로다. 경로는 여전히 모델 텍스트에 없다(`:575` 핀 유지).

**D3. 설명.**
- `_DESCRIPTION_HEAD`(`A/tool.py:193-216`)의 "There is no conversation: a child cannot ask you a question and you cannot steer it mid-run"에서 "There is no conversation:"을 뺀다. resume이 생기면 거짓이 된다.
- 단락 하나를 더한다(예산 2048 B 중 878 B 남음):
  - `action="resume"`은 끝났거나 멈춘 에이전트를 잇는다.
  - id는 그 결과의 Session 줄이다.
  - 같은 profile·모델 위에서, 넓어지지 않는 제한으로 자기 대화를 이어 간다.
  - 같은 일을 처음부터 다시 위임하지 말라.
- `task` 속성 설명의 "The child has NO conversation history"에 resume 문장을 더한다: action=resume이면 그 에이전트에게 줄 다음 지시이고, 에이전트는 자기 대화를 갖고 있다.
- 설명 예산 테스트에 `action="resume"`이 머리에 적혀 있는지 핀을 더한다(`:1795`의 mode 핀과 같은 방식).

**D4. single의 재위임 금지 문장을 resume 안내로 바꾼다.**
- `DO_NOT_REDELEGATE`(`A/tool.py:838-847`): 세션 id가 있으면 이렇게 바뀐다. "Do not delegate the same task again from scratch — it already did the work below. Check the changed files and its tool calls, then continue it with agent(action="resume", profile="<profile>", id="<id>", task=…)."
  - profile 이름은 파일 이름에서 온 값이라 줄바꿈이 있을 수 있다. `child_line`으로 정화해 넣는다(비평 m1).
- 세션 id가 없으면 지금 문장 그대로다. 출력 조건(가리킬 일이 있을 때만, #604 critique 5)도 그대로다.
- **배치 멤버 블록에는 넣지 않는다.** `_unfinished_member_block`은 일부러 재위임 줄이 없다(`A/aggregate.py:396-398`). 멤버의 `session` 표시와 설명(D3)으로 충분하다. rev 1의 "D12·D14가 따라 바뀐다"는 틀렸다(비평 m1). single의 Esc 보고는 single 렌더러를 쓰므로 따라 바뀐다.

## 2. 대상 찾기와 소유권

**D5. 영수증을 읽는 첫 제품 코드.**
- `A/child_session.py`에 reader를 둔다. 부모 세션의 **현재 branch**(`session.get_branch()`, 통계와 같은 범위, `K/harness/core.py:3159`)에서 `aelix.child_session` 레코드를 key별로 접는다. 마지막 줄이 이긴다(ADR-0243:160-164). compaction 앞의 기록도 branch에 있다(비평에서 확인).
- **대상은 모델 도구로 위임한 실행뿐이다.** `tool_call_id`가 null인 기록(`/agents run`, RPC `agents/run`)은 제외한다. 사람이 쓴 task를 모델에게 보이게 되고, 동의 화면의 "written by the model"이 거짓이 된다(비평 m4).
- 한 자식 세션(`child.session_id`)에는 실행이 여럿일 수 있다: 처음 위임(그 파일을 할당한 실행)과 resume들.
  - **모든 start 레코드에 `resumes`가 있다**(처음 실행은 null, resume은 처음 실행 key). 그래서 처음 실행 key(= first key)는 `resumes`가 null인 기록의 key이거나 resume 기록의 `resumes` 값이다. 둘이 어긋나면 손상이다.
  - 처음 실행 기록이 branch에 없으면 거부한다(그 위임이 이 대화의 기록에 없다).

**D6. 파일은 지금 부모 위치에서 유도하고, 소유권은 자식 파일의 origin으로 본다.**
- **경로는 레코드에서 읽지 않고 유도한다**(비평 B2): `place_children(지금 부모 파일).directory / f"{first key}.jsonl"`.
  - 지금 부모가 bucket 밖이면 거부한다(할당도 그 경우 자식 파일을 만들지 않는다, `A/child_session.py:433-438`). 세션 없는 부모도 거부한다.
  - first key는 `sub-[0-9a-f]{12}` 모양이어야 한다.
  - `lstat`으로 일반 파일이어야 한다. symlink는 거부한다.
  - 레코드의 `child.rel`은 대조에만 쓴다. 유도한 rel과 다르면, 그리고 그 rel이 다른 stem을 가리키면 fork 문장으로 거부한다. 절대 `path` 대체 경로는 쓰지 않는다.
- **자식 파일에서 확인할 것**(앞부분만 읽는다, 상한은 구현이 정하되 MiB 단위):
  - header가 `type: session`이고 `id`가 요청한 id와 같다.
  - `aelix.child_origin`의 `key`가 first key와 같다.
  - `aelix.child_origin.data.parent.session_id`가 **지금 부모 세션의 id**와 같다. 같은 세션을 `--continue`·`/resume`으로 다시 연 부모는 통과한다.
  - **user 메시지가 하나 이상 있다.** header와 origin뿐인 파일은 자식이 시작도 못 한 것이다. 원래 task를 받은 적이 없는데 "이어서 하라"가 되므로 거부한다: 시작하지 못했다, 새로 위임하라(비평 m5).
- fork(`/fork`, `--fork`, "fork and continue")는 영수증을 복사한다(`K/session/repo_utils.py:82-131`). 하지만 자식 파일은 원래 부모 아래에 있고, origin은 원래 부모를 가리킨다. 그래서 거부한다: this agent belongs to the conversation this one was forked from — resume it there, or delegate anew.

**D7. resume 가능 목록.**
- `/new`·`/resume`·`/fork`·종료로 끊긴 위임은 모델이 결과를 보지 못했다. 부모의 `agent` 호출은 결과 없이 남고, provider 변환이 "No result provided"(is_error)로 채운다. 기록(settle)은 남았지만 모델은 id를 모른다(오너 결정 2의 "resume할 수 있게 기록"이 모델에게 닿지 않는다).
- 그래서 `resume`에 id가 없거나 모르는 id면, 거부 이유에 **이 대화에서 resume할 수 있어 보이는 자식 목록**을 붙인다.
  - **레코드만으로 만든다.** 후보마다 파일을 열지 않는다. 실제 검증은 고른 id에만 한다(비평 cut). 훑는 후보 수에도 상한을 둔다.
  - 항목: id, profile, 마지막 상태(finished / stopped / failed / unknown — 이 branch의 기록 기준), 원래 task 앞부분(≤80자, `child_line` 정화, 따옴표). 레코드는 믿을 수 없는 입력이다(비평 B2·m4).
  - 최근 것부터 최대 10개, 2 KiB 안. 넘친 수는 센다.
  - 모델 도구 기록만(D5), `limits`가 있는 기록만(D9).
- 다음 턴에 자동으로 알리는 보고(D14 방식)는 하지 않는다. 같은 보고를 한 번만 하려면 상태를 더 기록해야 한다. 목록은 #611의 `status`가 넘겨받는다.

## 3. 위임할 때 저장하는 제한

**D8. 한 번 계산하고, 저장한 그 값으로 띄운다.**
- 지금 제한은 `PrintChannel.run` 안에서 계산된다(`A/print_channel.py:1063-1072`: `narrow_tools`, `narrow_context_files`, `inherit_thinking`). 모델 플래그는 argv를 만들 때 부모 모델을 live로 읽는다(`:1122-1136`; `child_model_flags`, `C/agents/resolver.py:307-339`). 어느 것도 저장되지 않는다.
- `ChildLimits`(frozen)를 `runtime._run`에서 한 번 계산한다. **admission 전에 계산한다**(비평 M4). registry 행을 넣은 뒤(`A/runtime.py:1082`) `try`(:1143) 전에 계산하다 예외가 나면 `_children` 행이 샌다(:1030-1036 docstring이 경고하는 바로 그것). 네 번 새면 `MAX_LIVE_CHILDREN` 때문에 세션 내내 위임이 막힌다. `_pin_route`·`resolve_route`가 live registry를 읽으므로 예외가 날 수 있다.
- 필드는 **타입이 있는 값**이다. argv 조각을 저장하지 않는다(비평 B2: 저장된 argv를 그대로 재생하면 위조된 기록이 `-e /tmp/evil.py`, 두 번째 `--session`, `--api-key` 같은 임의 argv가 된다).

  | 필드 | 값 | 읽을 때 검증 |
  |---|---|---|
  | `granted_mode` | 동의된 `grant.mode`. 배치 live floor 전의 값이다. resume의 천장(비평 m3) | `PermissionMode` enum |
  | `tools: list[str]` | `narrow_tools` 결과 | 모두 `ALL_TOOL_NAMES` 안, `agent` 없음 |
  | `context_files: bool` | `narrow_context_files` | bool |
  | `thinking: str \| None` | argv에 실제로 실린 `--thinking` 값(프로필 키든 상속이든) | `VALID_THINKING_LEVELS` 또는 null |
  | `model: {model, provider, route} \| None` | `child_model_flags`가 낸 `--model`·`--provider`·`--require-registration-route`의 값 | `-`로 시작하지 않음, 제어·공백 문자 없음, 길이 상한; route는 hex 64자 |
  | `cwd: str` | 자식 cwd(절대, resolve된 것) | 절대 경로 |
  | `profile_source: str \| None`, `profile_scope: str` | 정체성 | 문자열 |

  - 실제로 돈 권한(`permission_mode`, 배치 floor 뒤)은 지금처럼 레코드 최상위에 있다.
  - 하나라도 검증을 통과하지 못하면 손상으로 거부한다.
- `SpawnPlan`이 `limits`를 들고, 채널은 그 값으로만 argv를 만든다. 모델 플래그는 resolver의 한 함수만 만든다. 그 함수는 `--model`·`--provider`·`--require-registration-route`만 낼 수 있다.
  - limits 없이 만든 plan(채널 단위 테스트)은 같은 함수로 계산한다. 계산 함수는 하나다.
  - `_cancelled_envelope`의 `narrow_tools(...).dropped`(`A/runtime.py:1437`)도 plan의 limits를 쓴다.
  - RpcChannel(제품 호출자 없음, #123)은 지금처럼 다시 계산한다. **resume plan은 거부한다**(가드 하나와 테스트). 그대로 두면 저장값을 무시한 채 띄운다(`A/rpc_channel.py:311-319`, 비평 M4).
  - `T/agents_ext/test_host_late_binding.py:223`은 argv 빌더의 `kwargs["parent_model"]`을 읽는다. 갱신한다.
  - 이 refactor가 닫는 것은 receipt와 argv 사이의 창이다(`:1083`의 `requested_model` 대 `await receipt.open` 뒤의 argv). rev 1이 적은 `spawn()`의 대화상자-발사 창(`:765-777`)은 닫지 않는다(비평 M4에서 정정).
- 영수증: start 레코드(`_identity`, `A/child_session.py:491-508`)에 **모든 실행에** 두 키 `limits`·`resumes`를 더한다(비평 m8: 모양 하나).
  - JSON 값이어야 하므로 튜플 대신 리스트를 쓴다(ADR-0242 규칙 1.7).
  - `v`는 1 그대로다. 추가 키는 fork에서 살아남고 reader가 무시한다(규칙 1.3·1.6). `:101-103`의 "모르는 버전은 무시" 규칙과도 맞는다.
  - settle은 `_identity`를 다시 쓰므로 같이 실린다.
- 자식 파일의 `aelix.child_origin`은 바꾸지 않는다.
- 갱신할 레코드 키 핀: `T/agents_ext/test_child_session_records.py:92-137`(`_START_KEYS`, `_SETTLE_KEYS`).

## 4. resume할 때의 제한

**D9. 위임 시점의 것 ∩ 지금 새로 위임하면 받을 것.**
- 상한은 **처음 실행의 `limits`**다. 마지막 resume의 것이 아니다.
  - 이슈가 말하는 것은 "위임 시점의 제한"이다.
  - resume마다 좁아진 값을 상한으로 삼으면, 부모가 잠깐 plan이었다는 이유로 그 자식은 영원히 좁아진다. 같은 이유로 권한 천장은 배치 floor 전의 `granted_mode`다(비평 m3).
- 그다음 지금 부모 상태로 **새 스폰과 같은 계산**(프로필 재해석, clamp, 도구 축소 …)을 하고 항목별로 합친다.

| 항목 | resume 값 | 거부하는 경우 |
|---|---|---|
| 프로필 | 저장된 이름으로 `allow_project=False` 재해석(모델 경로와 같다). 호출의 `profile`이 저장된 이름과 다르면 거부 | 프로필이 없다, 프로젝트 프로필이다, `source_path`가 저장된 `profile_source`와 다르다 |
| 권한 | `resume_clamp(granted_mode, 지금 clamp)` = `_RANK` 최소(`A/posture.py:42-48`). 적용 위치는 D10 | — |
| 도구 | 저장 목록 ∩ `narrow_tools(지금 프로필, 지금 부모 grant)`. 저장 순서를 지킨다. 빈 집합이면 `--no-tools` | — |
| context files | 저장 AND 지금 | — |
| thinking | 저장 값으로 고정한다. 권한이 아니므로 교집합이 아니다 | — |
| 모델 | 저장된 `model`을 resolver의 한 함수로 플래그로 만든다. 지금 프로필·부모 모델로 다시 만들지 않는다(Codex #26718·#36433) | route digest가 있으면, 지금 부모 registry로 같은 route가 나오는지 hook에서 미리 본다. 다르면 거부한다(비평 m6: 아니면 동의와 예산을 쓴 뒤에야 자식이 `model_registry.py:403-412` 문장으로 죽는다) |
| cwd | 저장 cwd. 지금 부모 cwd 안에 있는 디렉터리여야 한다(`resolve_child_cwd` 규칙) | 밖이다, 없다 |
| trust 플래그 | 새로 계산한다(`child_trust_argv`, fail closed) | — |
| `--no-agents`, depth | 상수 그대로 | — |
| 시스템 프롬프트, skills, extensions, output_cap | 지금 프로필 | — |

- 같은 파일의 프로필 본문이 바뀐 경우에는 지금 본문을 쓴다. 정체성은 파일 경로다. 새 스폰도 지금 본문을 쓰므로 위험이 늘지 않는다(한계 4).
- 저장된 `limits`가 없는 옛 레코드(#610 이전)는 거부한다: delegated before aelix recorded an agent's limits; delegate it anew. 추측해서 복원하지 않는다(fail closed).
- 결과의 dropped-tools note는 저장 목록 대비 빠진 도구를 말한다.

## 5. 동의

**D10. 새 스폰과 같은 절차, 위임 시점의 권한이 천장이다. 천장은 세 곳에 건다.**
- **`resume_clamp(ceiling, live)` 하나**를 세 곳에서 쓴다(비평 B1).
  1. `_grant_for`(`A/extension.py:1057-1085`)의 `want`. 동의가 필요 없으면 이 함수는 `request_spawn_consent`를 부르지 않고 `mode=want`로 grant를 돌려준다. YOLO 부모는 늘 이 길이다(`A/consent.py:650-651`). 여기에 천장이 없으면 `-p --permission-mode yolo`의 resume은 처음 실행보다 넓게 돈다(비평 probe: 저장 plan, 지금 yolo → grant yolo).
  2. `request_spawn_consent` 안, UI 없음 return(`:1322`) 전. clamp를 스스로 다시 계산하는 곳이다(`:1300-1303`).
  3. `resume_granted`의 `permission_floor=granted_mode` → `_run`의 `_tighten(grant.mode, floor)`(`A/runtime.py:1106`). 안전띠다.
- yolo disclosure 줄은 교집합 권한으로 만든다. 실제로 도는 권한과 다른 말을 하지 않는다.
- **넓히기의 조건에 천장을 넣는다**(비평 M1). `_may_widen`(`:489-570`)에 천장 인자를 더하고, `consent_is_required`·모델 경로 pre-filter·`build_options`가 같은 술어를 쓴다.
  - 천장이 auto-accept-edits보다 낮으면 넓히기가 없고, 그러면 대화상자도 없다. "plan으로 실행 / 취소"뿐인 대화상자는 2026-07-27 오너 규칙이 없앤 모양이다.
  - 처음에 사람이 넓혀 준 자식은 다시 물어서 다시 넓힐 수 있다. plan으로 돌던 자식은 넓어지지 않는다.
- 천장 매개변수는 private이다. Protocol에는 올리지 않는다(`T/agents/test_subagent_contract.py:170`).
- 제목은 resume 전용 빌더가 만든다.
  - "Resume agent '<name>'?"
  - id, Profile(scope), Source, Directory, Permission(교집합), Model(저장된 것)
  - "Earlier task (written by the model):" 원래 task 앞부분(D5 덕분에 모델 도구 기록만이라 이 표기가 맞다)
  - "Next instruction (written by the model, not by you):" 전체
  - 모든 필드를 지금처럼 정화한다. 새 스폰 본문의 9줄 핀(`T/agents_ext/test_spawn_consent.py:1331`)은 건드리지 않는다.

## 6. 거부와 이유

**D11.** 프로세스를 만들기 전에 거부한다. 가능하면 대화상자 전, 곧 hook에서 거부한다. `_execute`와 `resume_granted`가 다시 확인한다(TOCTOU; 프로필 재확인의 선례가 `A/extension.py:1291-1299`). **`_run`의 admission 뒤에서는 거부하지 않는다.** 거기서 거부하면 예산이 깎이고 start·pending·settle이 쓰여 "실행"이 하나 더 생긴다(비평 M5).

| 경우 | 이유 문장(요지) |
|---|---|
| id 없음, 모르는 id | resume needs the id of an agent this conversation delegated. 그리고 목록(D7) |
| 경로 모양 id | 경로가 아니라 결과의 Session id를 달라 |
| resume에 tasks, single 외 mode, cwd, background | resume은 원래 디렉터리에서 한 지시만 준다 |
| run에 id | id는 resume 전용이다 |
| 지시가 resume 예산을 넘음 | 한도를 적는다(D1) |
| 모델 도구로 위임한 기록이 아님(`/agents run` 등) | 네가 위임한 에이전트가 아니다 |
| 처음 실행 기록이 branch에 없음 | 그 위임이 이 대화의 기록에 없다 |
| 지금 부모가 저장되지 않음 / bucket 밖 / 레코드의 `child`가 null | 이어 갈 세션이 없다 |
| 유도한 파일이 없음 | 세션 파일이 없다. 레코드 rel이 다른 stem이면 fork 문장 |
| symlink, header·origin 불일치, 저장 limits 검증 실패 | 세션 기록이 손상됐다 |
| user 메시지가 없음 | 시작하지 못했다, 새로 위임하라 |
| 다른 부모(origin) | D6 fork 문장 |
| 옛 레코드(`limits` 없음) | D9 |
| profile 불일치, 프로필 없음, 프로젝트 프로필, 다른 파일 | D9 |
| route가 바뀜 | 모델의 provider 등록이 바뀌었다 |
| cwd 없음, cwd 밖 | D9 |
| 이 프로세스에서 실행 중(registry 행) | 이미 돌고 있다 |
| 세션 파일이 다른 프로세스에 잡힘(lock) | 다른 프로세스에서 돌고 있거나 `aelix --session`으로 열려 있다 |
| lock 확인 자체가 실패(`lock.error`) | 그 오류를 따로 말한다 |
| 위임 불가, depth, 예산, 동의 거절 | 지금과 같다 |

## 7. 실행

**D12. private door와 붙이기(attach) 영수증.**
- `_SubagentRuntimeImpl.resume_granted(grant, target, instruction, on_event, record)`를 `spawn_granted` 옆에 둔다. Protocol 밖이므로 `CONTRACT_VERSION`은 그대로다.
- **busy 판정 = registry 행 + lock 확인**(비평 M5·cut).
  - registry 행: `_children`에 같은 자식 세션 id를 띄운 살아 있는 행이 있으면 실행 중이다. 행에 자식 세션 id를 들게 한다.
  - lock 확인: hook과 `resume_granted`(`_run` 전)에서 `SessionWriterLock(path, timeout=0)`(`K/session/session_lock.py:144-260`)을 잡아 보고 바로 놓는다. 기본 `try_acquire`는 0.25 s까지 동기로 막으므로 `timeout=0`이다. 경합과 `lock.error`를 나눠 말한다. lock을 지원하지 않는 파일시스템이면 확인을 건너뛴다.
  - check-then-act이므로 자식 자신의 lock이 진짜 방어선이다. 경합에서 진 자식은 "already open in another terminal"로 exit 1한다(`C/cli/entry.py:4912-4919`).
  - rev 1의 "프로세스 수명 동안 busy"는 뺀다. Esc는 reaper 없이 SIGKILL하고(`A/print_channel.py:1372-1379`, `:1554-1556`), `_run`이 끝나면 그 프로세스를 가진 것이 없다. 죽어 가는 자식은 lock이 잡아 준다. 같은 프로세스 안의 동시 resume은 #611 전에는 생기지 않는다(도구가 sequential, `/agents run`은 REPL을 막고, RPC는 idle runtime이 필요하다).
- `_run`을 공유하되 다음이 다르다.
  - **새 spawn key**를 만든다. 기록 key는 실행마다 새것이다(D15).
  - 영수증은 할당하지 않고 붙인다. `SpawnReceipt.open`/`_allocate`는 있는 파일을 거부하므로(`A/child_session.py:457-459`) attach 경로를 따로 둔다. `open()`처럼 `opening_attempted`를 센다(비평 m8).
    - start 레코드: `child` = 대상 파일, `resumes` = first key, `limits` = 이번 실행의 값, `mode` = `"single"`, `task_preview` = 지시 앞부분. pending도 새 key로 쓴다.
    - **자식 파일에는 아무것도 쓰지 않는다.** 자식이 lock을 쥐고 쓰는 파일이다. pi #8476·#8502에서는 끊긴 호출과 새 프롬프트 사이에 끼운 기록이 이후 모든 턴을 400으로 만들었다.
  - plan: `session_path` = 대상 파일, `limits` = D9, task = D13 머리말 + 지시.
  - 결과 뒤 `_with_run_facts`는 그대로다. 세션 id와 path는 대상 파일의 것이다.

**D13. resume 머리말 — 상태와 무관한 한 문장.** 자식에게 가는 task(argv `Task: …`, `C/agents/resolver.py:451-472`) 앞에 붙인다.
- "This continues your earlier work in this session. If your previous run stopped before it finished, pick up where you left off and do not repeat work that is already done. A tool call that shows no result may or may not have run — check its effect before relying on it."
- 그다음 빈 줄, "Next instruction:", 지시.
- rev 1은 마지막 상태(ok/아님)로 머리말을 골랐다. 버린다.
  - 그 상태는 이 branch에서 본 것이라, 다른 branch에서 이어 쓴 자식에게는 틀린 말이 된다(비평 M3).
  - "결과 없는 호출은 끝나지 않았다"도 틀렸다. 병렬 도구 경로가 취소 때 버린 형제 결과는 실제로 돌았다(`K/loop.py:905-907`, 비평 m7).
- OpenCode·Qwen 문구(survey §2 1단계)를 따랐다.

## 8. 끊긴 도구 호출

**D14. provider 변환의 합성으로 충분하다. 측정했다.**
- 자식이 도구 실행 중에 끊기면 파일 끝은 `assistant(toolCall)`이고, 결과도 aborted 표시도 없다(실측, Part 2 §3). SIGKILL로 찢긴 마지막 줄은 다음에 열 때 건너뛰고 줄바꿈으로 메운다(`jsonl_storage.py:571-590`, 비평에서 확인).
- 다음 요청에서 `AI/providers/_transform_messages.py:293-312`가 `ToolResultMessage("No result provided", is_error=True)`를 새 user 메시지 앞에 넣는다(`:329-331`).
  - 실측 요청: `tool(call_sleep_1, "No result provided")` 다음에 `user(Task: continue…)`.
  - 합성 결과는 파일에 남지 않는다.
- 기본 adapter 여섯이 모두 이 변환을 거친다(비평에서 다시 확인). wire에 오류 표시가 있는 곳(anthropic `is_error`, google `{"error":…}`)은 오류로 간다. 없는 곳(openai 계열)은 "No result provided" 텍스트로 간다. "사용자 취소 + 성공"은 어디에도 없다.
- 그래서 변환은 바꾸지 않는다. 대신 D13 머리말이 "결과 없는 호출은 돌았을 수도 있으니 효과를 확인하라"고 말해서, 텍스트만 가는 wire도 덮는다.
- 한계에 적을 것:
  - `register_api_adapter`로 등록한 확장 adapter는 날 메시지를 받아 합성을 거치지 않는다.
  - 병렬 도구 경로는 취소되면 이미 끝난 형제 호출의 결과도 버린다(`K/loop.py:905-907`). resume한 자식은 그 호출도 "결과 없음"으로 본다.

## 9. 기록과 비용

**D15. 실행마다 새 key를 쓰고 `resumes`로 잇는다.**
- 통계 fold는 key별 마지막 줄이다(`K/harness/_session_stats.py:298-305`; 핀 `T/harness/test_tool_usage_stats.py:175`). 원래 key를 다시 쓰면 첫 실행 비용이 사라진다.
- 새 key면 `/cost`, `/stats`, footer, History가 두 실행을 더하고 `runs`도 는다. 이것이 "원래 위임과 함께 집계"다.
- resume 실행의 usage는 그 실행의 스트림만 담는다(실측). 다시 보낸 기록의 input 토큰은 들어가고, 자식 compaction 비용은 빠진다(ADR-0243의 기존 한계).

## 10. 문은 모델 도구 하나

**D16.** resume은 `agent` 도구로만 한다.
- `/agents run`, RPC `agents/run`, ACP, `SubagentRuntime` Protocol은 그대로다(#612).
- `-p`에서도 같은 도구 경로라 동작한다. 대화상자가 없으므로 교집합 clamp로 돈다.
- `/agents run`·RPC로 띄운 자식은 대상이 아니다(D5).

## 12. 한계 (ADR Limits에 들어갈 것)

1. fork한 대화에서는 resume하지 않는다(D6).
2. **한 세션의 `/tree` branch 둘이 같은 자식을 차례로 이을 수 있다.** 사람이 `aelix --session <자식 파일>`로 이어 쓴 것도 부모는 모른다(비평 M3).
   - 자식 파일은 한 줄로 이어 붙을 뿐 망가지지 않는다. 자식 자신은 전부를 안다.
   - 그 branch의 부모 모델만 자식이 다른 곳에서 한 일을 모른다.
   - 머리말을 상태와 무관하게 만들어(D13) 틀린 말은 하지 않게 했다.
   - 지문(마지막 entry id)으로 감지하는 안은 Esc의 SIGKILL과 settle 사이 경합에서 거짓 양성이 날 수 있어 넣지 않는다.
3. 확장 adapter는 끊긴 호출 합성을 거치지 않는다.
4. 프로필 본문 변경은 resume에 반영된다. 정체성은 파일 경로다.
5. 병렬 도구 경로는 취소 때 끝난 형제 결과를 버린다(kernel의 기존 동작). resume한 자식은 그 일을 다시 확인해야 한다.
6. 자식 compaction 비용은 집계에 없다(기존).
7. kill -9된 부모의 자식은 macOS에서 살아남아 lock을 쥘 수 있다. 끝날 때까지 resume은 거부된다(#619 관련).
8. resume은 모델 도구로만 하고, 모델 도구로 위임한 자식만 대상이다. 사람용 명령과 호스트 노출은 없다(#612).
9. #610 이전 레코드는 resume할 수 없다.
10. 끊긴 위임을 다음 턴에 자동으로 알리지 않는다. 모델은 목록(D7)으로 찾는다.

## 13. 테스트

이슈의 "미리 넣을 테스트" 다섯과 설계·비평에서 나온 것들이다. 새 파일은 `T/agents_ext/test_agent_resume_610.py`이고, 실제 자식이 필요한 것은 POSIX 전용 파일로 분리한다.

1. **교집합.** 그 사이 부모가 좁아졌으면 좁은 쪽(권한, 도구, context files), 저장이 더 좁으면 저장 쪽을 쓴다. 사람이 넓혔던 자식은 대화상자에서 다시 넓힐 수 있지만 `granted_mode`를 넘지 않는다.
2. **천장은 hook에서도 건다(B1).** 처음 실행 plan, 지금 부모 YOLO — UI 있을 때와 `-p` 모두 — resume grant와 실제 argv가 plan이고 disclosure도 plan을 말한다.
3. **넓히기 없는 대화상자는 없다(M1).** 천장 plan, declaring 프로필(ask/auto), TUI → 대화상자 없이 plan.
4. **위조 레코드(B2).** model·provider·thinking·tools·cwd에 argv 모양 값(`-e …`, `--session …`, 제어 문자), route가 hex가 아님, rel이 bucket 밖·다른 stem, symlink인 자식 파일 → 거부, 프로세스 없음. 어떤 경우에도 argv에 저장 문자열이 플래그로 나타나지 않는다.
5. **거부.** 다른 부모(fork) 자식, 경로 id, 실행 중(registry 행), 잡힌 lock, `lock.error`, 모르는 id(목록 포함), `/agents run` 자식, 옛 레코드, 처음 실행 기록 없음, profile 불일치·없음·다른 파일·프로젝트, route 변경, cwd 없음·밖, 시작 못 한 자식, resume+tasks·mode·cwd, run+id, 모르는 action, `action=""`, 지시 예산 초과.
6. **자식 파일 없음·손상**은 이유를 말하고 프로세스를 만들지 않는다. 채널이 불리지 않았고, 예산이 깎이지 않았고, 레코드가 쓰이지 않았음을 확인한다.
7. **끊긴 도구 호출.** 실제 자식 + 기본 adapter(openai-completions) + wire 탭으로, resume 요청에 `No result provided`가 실리고 성공으로 보이지 않음을 본다. wire 탭은 `test_child_ownership_365.py`의 sitecustomize 방식이되 401 대신 스트림 응답을 준다. 변환 단위 테스트(`T/providers/test_transform_messages.py:148/169/179`)는 그대로 둔다.
8. **비용.** 원래 위임과 resume의 합이 `/cost`·`/stats`(`get_session_stats`) 총액이고 `runs`는 2다.
9. **모델·thinking 고정.** 위임 뒤 부모가 `/model`을 바꿔도 resume argv의 모델 플래그는 저장된 것이다.
10. **기록.** 모든 start에 `limits`와 `resumes`가 있다. resume 실행은 새 key이고 자식 파일에 쓰지 않는다(바이트 비교). 처음 실행 레코드는 변하지 않는다.
11. **렌더링.** single 성공에 Session 줄, ok 멤버의 Session 줄, single resume 안내 문장(id 있음·없음, profile 정화), 배치 멤버에는 안내 없음, 경로 비노출, 설명 예산과 action 핀.
12. **동의.** resume 제목과 본문, UI 없음 → 대화상자 없음.
13. **RpcChannel**은 resume plan을 거부한다.
14. **예외 안전(M4).** `ChildLimits` 계산이 예외를 내도 `_children` 행이 남지 않는다.

## 14. 라이브 (완료 조건)

- **TUI, 스크립트 provider로 격자와 wire.** `604-live-drivers/drive_tui.py`를 바탕으로 한다.
  - 부모가 위임 → 자식이 파일을 하나 쓰고 다음 요청에서 멈춤 → Esc → 사람이 "이어서 하라" → 부모가 `action="resume"`.
  - 자식 요청에 앞선 도구 결과와 `No result provided`가 실리고, 앞선 write를 반복하지 않는지 본다.
- **실제 모델(OpenRouter haiku) + wire 탭.** 같은 흐름을 실제 모델로 돈다. 자식 쪽 provider 요청은 sitecustomize의 `httpx` pass-through 탭으로 기록한다. 이슈의 "provider 요청으로 본다"(비평 M2).
- **`-p` 두 번.**
  - 1회: 위임 중에 자식 프로세스를 kill한다. 부모는 결과로 Session id를 받는다.
  - 2회: `aelix -p --session <부모 세션> "그 에이전트를 이어서 끝내라"`로 resume한다. 부모를 다시 시작해도 영수증으로 이어지는지 본다.
- **넓어지지 않음 실측(비평 M2).**
  - 처음 실행은 default posture(자식 plan).
  - 부모를 yolo로 넓히고 `--tools`도 넓힌 뒤 resume한다.
  - `ps`로 자식 argv를 본다: `--permission-mode plan`, `--tools`는 저장 목록의 부분집합.
  - 반대 방향(부모를 plan으로 좁힌 뒤 resume)도 한 번 본다.
- **resume 대화상자를 `uv run aelix`로 본다(CLAUDE.md 9).** 사람이 넓혀 준 declaring 프로필 자식을 resume해서 제목·본문·선택지를 80열에서 확인한다.
