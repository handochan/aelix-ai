## 3. 이 레포에서 이번에 물린 것

1. **`RpcChannel`은 제품에 배선돼 있지 않다.** agent 도구는 `PrintChannel`(`aelix_agents/runtime.py:370`). `RpcClient`를 만드는 제품 코드는 `rpc_channel.py`뿐이고 그건 주입으로만 쓰인다. 라이브 검증 B는 그래서 `RpcClient`를 직접 띄운 스크립트였다(`scratchpad/live_rpc.py` 모양 — progress 파일에 출력).
2. **워크트리에 `AGENTS.md`/`CLAUDE.md`가 없다** — 둘 다 main 체크아웃의 untracked 파일이라 `git worktree add`가 옮기지 않는다. 워크플로우 agent에게 `/Users/handochan/dev/aelix-ai/AGENTS.md`를 읽으라고 절대경로로 줄 것.
3. **`asyncio`에서 `returncode is None`은 "안 reap됨"이 아니다.** watcher가 자기 스레드에서 `waitpid`하고 returncode는 나중 루프 콜백이 채운다(루프를 1.5 s 막고 실측). pid 재활용 하자의 경계는 "그룹이 비어 있지 않으면 id가 고정된다(POSIX §3.293)"이지 "마지막 poll이 살아 있음을 봤다"가 아니다. ADR·docstring이 그렇게 고쳐졌다.
4. **Darwin `getpgid(zombie leader)`는 `ProcessLookupError`** — 그룹은 살아서 자손을 쥐고 있는데. `getpgid`를 kill 시점에 다시 푸는 코드는 macOS에서 "아무것도 안 죽임"으로 조용히 저하한다. attach 시점에 pgid를 잡아 두거나 `pgid = pid` 폴백.
5. **`tools/_subprocess.py::run_cancellable`은 asyncio가 이미 reap한 뒤에 `kill_process_tree`를 부른다**(최대 grep/find 타임아웃 30 s 뒤). "모든 호출자가 unreaped 상태"라는 문장은 틀렸었다 — 세 문서·세 테스트에서 고쳤다.
6. **`os.kill(pid, 0)`은 Windows에서 `GenerateConsoleCtrlEvent(CTRL_C_EVENT)`다** (`CTRL_C_EVENT == 0`). ADR-0238과 `prompt_file.py:161`이 맞고, **`tests/process_probe.py` 모듈 docstring(#203)이 틀렸다**("signal 0은 TerminateProcess로 떨어진다"). 결론(Windows에서 liveness probe로 쓰지 말 것)은 같으니 급하지 않지만 #203 쪽에 한 줄 고칠 것.
7. **windows 레그에서 처음 실행된 것들**: `taskkill.exe`(`test_kill_process_tree_ends_a_live_child_for_real`), kernel32 job 경로 전부, `IsProcessInJob`, `CTRL_BREAK_EVENT` 전달(`test_soft_kill_is_delivered_and_survivable`, #207 breadcrumb), rpc 자식의 `SIGBREAK` 핸들러(`test_the_real_rpc_child_answers_the_client_it_ships_with`). 전부 run 33910216667에서 통과(0 failed). 유일하게 빨갰던 것은 실제 rpc 자식의 finalization(§3-12)이었고 같은 커밋에서 고쳤다.
8. **Pi 로컬 클론(`~/dev/pi`)이 석 달 뒤처져 있었다**(032c01c vs origin/main 47236c8). 1차 리뷰의 "Pi는 taskkill을 안 고쳤다"가 그 때문에 틀렸다. `git fetch`는 해 두었다(작업 트리는 안 건드림); Pi 인용 전에 `origin/main`을 볼 것.
9. **macOS에 `timeout`(coreutils)이 없다.** 라이브 체크 스크립트에 `timeout 180 …`을 쓰면 exit 127.
10. **Workflow 규모**: 설계 반박 17 agent·1.88M·25 min, 구현 6·0.95M·50 min, 구현 리뷰 12·1.69M·36 min, 2차 수정 5·0.88M·44 min. BLOCKING을 잡은 것은 이번에도 전부 opus 반박 레인이었다 — 특히 **변이 테스트 레인**(hard_kill을 지워도 초록인 escalation 테스트, 사이트 정책 세 개가 전부 핀 없음). 모델을 내려 쓰지 말 것.
11. **`spawn_kwargs`라는 로컬 이름이 `RpcClient.start()`에 이미 있다.** 헬퍼를 같은 이름으로 import하면 `TypeError: 'dict' object is not callable`. `containment_spawn_kwargs`로 import하고 로컬 dict에 `.update()`.
12. **협조 종료는 Windows에서 새 코드 경로다.** #202 전엔 rpc 자식이 항상 `TerminateProcess`라 인터프리터 finalization에 도달한 적이 없다. 첫 windows 레그: SIGBREAK 핸들러가 돌고 teardown이 끝난 뒤 finalizer가 `sys.stdin`을 닫으려다 펌프 데몬 스레드가 쥔 BufferedReader 락에서 fatal error. `main_sync`는 `asyncio.run` 밖으로 새는 예외를 `raise`로 끝내므로 **미처리 예외와 `TerminateJobObject(…,1)`이 둘 다 exit 1**로 보인다 — 원격 레그에서 둘을 가르는 건 자식 stderr 꼬리뿐. 실패 메시지에 stderr 꼬리와 elapsed를 실어 두었고, 20 s grace 쌍둥이 테스트가 실제 종료 시간을 warning으로 찍는다(`-q` 로그에도 남는다).

## 4. 반증된 것 — 다시 믿지 말 것

- ❌ "`close()`가 남은 것을 죽이면 두 플랫폼이 대칭이 된다" — POSIX에서 그건 성공 경로의 hook이 일부러 백그라운드로 둔 헬퍼를 죽였고(실측), rpc 호출자에서 reap과 `close()` 사이는 **초 단위**(`_shutdown`: reap → `drain(2.0)` → `stop()`)라 빈 그룹 번호에 SIGKILL을 던지는 창이었다. `close()`는 release.
- ❌ "POSIX에서 rpc 자식의 그룹이 MCP 서버를 쥔다" — SDK가 `start_new_session=True`로 띄운다. 도구 자식도 전부 setsid. 실제 rpc 자식의 그룹에는 자식 자신뿐이다. POSIX 봉쇄는 그룹이고 그룹은 setsid 자손을 못 잡는다 — 그 walk는 reaper의 것(ADR-0197 I2). Windows Job Object가 **엄격히 더 강하다**.
- ❌ "hook·`!command` 셸도 `setsid`로 띄우면 된다" — `!command`는 자격 증명 헬퍼(`gpg`/`pass`/pinentry)가 `/dev/tty`를 연다. `process_group=0`.
- ❌ "`taskkill /T /F`면 Windows 트리가 죽는다" — 살아 있는 부모 링크만 따라간다(Pi #9129: MSYS 파이프라인 leaf가 70분 더 돌았다). Job Object가 정답이고 `taskkill`은 fallback + 창 탈출 대비 belt.
- ❌ "escalation 테스트의 `elapsed >= grace`가 hard kill을 증명한다" — `transport.close()`가 root를 죽여서 `hard_kill()`을 지워도 초록이었다. 인스턴스 스파이로 호출 1회를 단언해야 한다.
- ❌ "테스트가 `time.sleep(0.5)` 루프여도 시그널 핸들러가 곧 돈다" — Windows는 `time.sleep`이 CTRL_BREAK로 안 깨어난다(SIGINT 이벤트만). breadcrumb 지연이 grace(0.3 s)를 넘긴다. 스텁은 0.05 s.
- ❌ "실제 rpc 자식이 Windows에서 exit 1이면 CTRL_BREAK가 안 갔거나 핸들러가 안 돈 것" — 둘 다 아니었다. 전달·핸들러·루프 wakeup 전부 정상, 죽은 건 finalization(§3-12). 스텁 테스트가 전부 초록인데 실제 자식만 빨간 경우, 차이는 시그널이 아니라 **종료 경로**에 있다.
- ❌ "`ruff format --check .`는 게이트" — 아니다(ADR-0152, 591 파일이 재포맷됨). 새 파일에만 scoped.
