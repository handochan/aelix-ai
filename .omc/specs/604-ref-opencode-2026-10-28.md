## OpenCode reference report

**What I read.** OpenCode was read at `7b1e54a74f6201e725a50cba5d7fb383aa64e407` (2026-10-27, v2.2.0). `packages/opencode` no longer exists: delegation now lives in `packages/core`, is built on Effect, and runs in-process. I read the v1 `task.ts` at tag `v1.18.7` through `gh api`. oh-my-opencode was read at `dae75122`, opencode-background-agents at `46cfb3de`. All paths below are relative to those SHAs.

**History of #5887.** The issue was auto-closed for 60 days of inactivity on 2026-08-20; it was not closed as completed. The "SessionRunner" stack never merged; all three PRs were closed on 2025-12-30:
- #5996 added the runner abstraction.
- #6036 added a FIFO queue with concurrency 2, `session.background.{queued,started,completed,failed,canceled,timed_out}` events, and a timeout built on `Promise.race` plus `AbortController`, which kills the work.
- #6041 routed `task` through the runner.

What shipped instead is a generic **Job service**: added in #27033, replaced in #34559, restart recovery in #44844, shared completion delivery in #46054, command subagents in background in #47081, notifications kept across location eviction in #54072, steering moves running work to background in #57142, and locations kept alive while jobs run in #57416. It has no execution timeout and no concurrency cap.

### Q1 Delegation model
- **One tool, `subagent`** (named `task` in v1; the v1 config migrates it, `core/src/v1/config/migrate.ts:29`).
  - Input: `{agent, description, prompt, model?, sessionID?, background?}` (`core/src/tool/plugin/subagent.ts:29-48`).
  - Output: `{sessionID, status: completed|running, output}`, rendered as `<subagent sessionID=… state="completed">` (`:252-265`).
- **In-process.** The child is a durable Session with `parentID`, run by fibers in the same server.
- **What the child gets:**
  - Fresh context: `"You are a subagent spawned by another session.\n"+prompt` (`:205-213`).
  - Model: explicit > agent's model > parent's model (`:184`).
  - It inherits location, metadata and permissions from the parent (`core/src/session.ts:301-323`).
- **Guards:**
  - Depth limit `experimental.subagent_depth`, default 1 (`subagent.ts:117-133`).
  - Primary agents are rejected, and a `subagent:<agent>` permission is asserted (`:136-151`).
  - The list of available subagents is injected into the tool description each turn (`:282-309`).
  - v1 also denied `todowrite` and `task` to children (`v1 task.ts:140-153`).

### Q2 Waiting vs execution
- **No wall-clock limit on subagents in v2.**
- **Only limit: an optional per-agent `steps`, with no default.** At the limit:
  - The runner appends `MAX_STEPS_PROMPT` as an assistant message and sets `toolChoice:"none"`, keeping tool definitions "to preserve the provider's cached prefix" (`core/src/session/runner/llm.ts:225-245`). Tool calls are rejected (`step.ts:91-93`).
  - The prompt requires: a statement that the limit was reached, a summary of work done, remaining tasks, and recommendations (`runner/max-steps.ts:1-16`). This is a graceful final-summary step.
  - Open PR #56257 sends this as a user message instead; I did not verify why.
- **Waiting and cancelling are separate.**
  - `Job.wait(timeout)` only waits: on timeout it returns `{info: snapshot, timedOut: true}` and leaves the job running (`core/src/job.ts:300-316`). Cancelling is a separate `Job.cancel` (`:412-440`).
  - Foreground `Job.block` races `done` against `backgrounded` (`:329-356`), so a blocking call can move to background without restarting.
  - The shell tool shows the same idea: a 2-minute foreground default timeout that is dropped to 0 when backgrounded (`tool/plugin/shell.ts:24`, `:259-266`).
- **Crash-resume budget:** 10 resumes per turn (`session/execution/restart.ts:23-33`).

### Q3 Partial results
- **Completed:** the text of the last completed, non-error assistant message among the last 20 (`session/subagent-job.ts:53-61`). If there is none: "Subagent completed without a text response." (`subagent-completion.ts:8`).
- **Failed or cancelled:** `"Subagent failed (sessionID: X): <err>"` or `"Subagent cancelled (sessionID: X)"` (`subagent.ts:245-251`). No partial text, tool trail or files are returned.
- **Strategy: keep the handle.** The transcript persists and the parent can continue the child. In v1 failures carried no id; that was fixed in v2 (#39196).
- Per-turn file diffs exist for clients (`GET /api/session/:id/diff`, `protocol/src/groups/session.ts:519`) but are never given to the model.

### Q4 Background
- **Launch:** `background:true` returns at once with the sessionID and "DO NOT sleep, poll…; avoid working with the same files" (`subagent.ts:19-27`).
- **How completion reaches the parent:**
  - An observer forked in a global scope waits on the job; the code says jobs "outlive the plugin that launched them" (`subagent-job.ts:24-42`, deduped by `child:startedAt`).
  - `SubagentCompletion.deliver` then admits a synthetic input into the parent's durable inbox: `<subagent sessionID state description>…`, metadata `{source:"subagent", childID, state}` (`subagent-completion.ts:21-46`).
  - Delivery defaults to `steer` and calls `wake`. A busy parent takes it at the next step boundary (`inbox.ts:52-57`). An idle parent starts a new turn; a test asserts it is woken exactly once (`core/test/subagent-lifetime.test.ts:61-131`).
- **Exactly-once:**
  - A `notificationID` is minted at background time and persisted in KV under `job.background/<id>` with recovery data (`job.ts:199-209`, `:358-386`).
  - That id is reused as the injected message id, so admission is idempotent.
  - The KV marker is deleted on admission (`completeBackground`, `:462-473`).
- **Fetching results later:** there is no output tool. The parent continues the child by sessionID, or the user opens the child session.
- **oh-my-opencode (secondary):**
  - Each completion injects a `<\system-reminder>` "[BACKGROUND TASK RESULT READY] … N still in progress … Do NOT poll" via `promptAsync`.
  - It sends `noReply:true` (no new turn) unless `allComplete || isTaskFailure` (`manager.ts:2828`; `parent-wake-prompt-dispatch.ts:35-60`; template `:101-125`).
  - `background_output(task_id, block, timeout ≤600s wait-only, full_session, since_message_id)` (`tools/background-task/create-background-output.ts:106-136`); `background_cancel(taskId|all)`.

### Q5 Intervention
- **Parent model:** calling `subagent` again with a running child's sessionID admits a `steer` prompt. The code comment says "the default wake starts an idle child or steers a running one", and `Job.start` joins the running job (`subagent.ts:203-218`; `job.ts:262-265`).
  - Models don't realise they can do this; open PR #53615 only adds a hint.
  - The model has no stop action (#36423 and #38966 are open).
- **User or host:**
  - Prompt the child with `delivery: steer|queue`.
  - Switch inbox items between steer and queue, or cancel them (`PATCH`/`DELETE /api/session/:id/inbox/:inboxID`, `session.ts:544-598`).
  - `interrupt?resume=true` resumes pending steers while queued prompts stay parked (`:676-693`; `execution.ts:150-166`).
- **No "wrap up now"** primitive other than the step limit.

### Q6 Persistence and resume
- **Continue:** sessions are durable and event-sourced in SQLite. Continuing by sessionID checks `existing.parentID === caller` (`subagent.ts:164-167`).
- **Restrictions:** agent, model and permissions come back because they are fields of the child's `session.created` record. However, passing a different `agent` on continue switches the child's agent and model (`:169-182`).
- **Crash recovery:**
  - A write-ahead execution claim is written in the same transaction as `execution.started`. Deliberate stops release it; shutdown keeps it (`execution.ts:73-79`, `:125-131`).
  - The boot sweep (`restart.ts:192-231`):
    - delivers background shell outcomes first;
    - relaunches running background subagents and redelivers stored terminal results (`:138-190`);
    - resumes turns with "The server restarted while you were working. Continue from where you left off without repeating completed work." (`:15-16`, `:77-99`);
    - marks a turn failed after 10 attempts.
  - Side effects are explicitly at-least-once (`:51-53`).

### Q7 Lifecycle
- **Foreground:** a parent interrupt interrupts the child and cancels its job (`subagent.ts:234-240`).
- **Background:**
  - Not tied to the parent's turn.
  - A user interrupt of the child cancels its job, and the parent receives "cancelled" (`execution.ts:125-127`).
  - Deleting a session cascades to its children (`session.ts:396-405`).
- **Quit:** the TUI is a client of a managed server, so quitting it does not stop children.
- **Graceful restart:** according to PR #58261's description (open), it currently shows background subagents as "cancelled"; the PR resumes them instead.
- **ACP:** "Children outlive a cancelled turn" (`cli/src/acp/turn.ts:303-311`).
- **Limits:** depth defaults to 1. There is no concurrency or count cap (open PR #55983) and no cost cap beyond `steps`.

### Q8 Supervision UI
- **Keybindings** (`tui/src/config/v1/keybind.ts:103-109`):
  - `down`: subagent picker
  - `up`: parent session
  - `ctrl+b`: background blocking session tools
  - `escape`: interrupt
  - `<leader>q`: queued prompts
- **`ctrl+b`** calls `backgroundAll` and adds a synthetic message: "User requested that active blocking work be moved to the background… Do not wait, sleep, poll…" (`session.ts:513-530`).
- **Mini TUI footer** shows queued / subagents / bg chips (`tui/src/mini/footer.view.tsx:455-469`).

### Q9 Host and protocol exposure
- **HTTP (generated SDK):**
  - `POST /api/session/:id/prompt` and `/synthetic`, both with `{delivery, resume}`.
  - `/interrupt?resume`, `/background`, experimental `/wait`, inbox CRUD.
  - `GET /api/session?parentID=<id>|null` (`schema/src/session.ts:71-83`).
- **Events:**
  - The global SSE stream `GET /api/event` is "Volatile by contract: a slow consumer overflows and fails the stream, and events during disconnection are missed" (`protocol/src/groups/event.ts:61-71`).
  - The durable `GET /api/experimental/session/:id/log?after=<seq>&follow=true` replays, then emits `Synced` (`session.ts:656-674`).
  - `session.created` carries `parentID` (`schema/src/session-event.ts:39-50`). The subagent tool publishes ephemeral `session.tool.progress {sessionID, status}` (`:522-529`; `subagent.ts:201`).
- **ACP:**
  - Child events are projected into the parent's stream with `_meta["opencode/child-session"]={id,parentID,depth,title}`, tool call ids prefixed `${childID}:`, and prefixed titles.
  - An extension notification `opencode/session/child_update` carries `{rootSessionId, childSessionId, parentSessionId, depth, status: created|running|completed|failed|interrupted}`. It is sent only to clients advertising `opencode/child-session-updates` (`cli/src/acp/child.ts:3-66`, `capabilities.ts:3`, `translate.ts:199-215`).
  - Open bug: the auto-resumed parent turn after a background completion emits no ACP updates (#55760).

### Q10 Robustness lessons
1. **"First idle = done" (#48826, open, re-verified on 2.1.2).** A child starts a background shell and ends its turn; the parent is told "completed" with the premature reply, and the real answer is stranded. The same root cause makes `opencode run` exit while background subagents still run (#48361, open). `run` only awaits root-session idle (`cli/src/run/noninteractive.ts:761`). Fixes in review: a non-terminal `waiting` status (#53211), and waiting for the child's jobs (#57132, #57418).
2. **Lost notifications (#50751, #54658, open).** Continuation turns lose their completion notice. `interrupt?resume=true` sends "cancelled" at once and the later reply never arrives. The proposed fix is a durable obligation keyed by `(parent, child, turn)`, replayed idempotently.
3. **Empty "completed" results (#37852, closed by v1 triage; #52378, #59051, #59565, open).** Truncated streams, `MALFORMED_FUNCTION_CALL`, or a gateway cut are recorded as clean finishes, so the parent gets an empty "completed".
4. **Unresumable failures (#39196, fixed in v2).** The failure message dropped the child id, so the parent could not resume.
5. **Zero guards (#46461, #51291, #45442, open).** A stalled stream hung the parent for 20 minutes; identical tool calls looped for about 50 minutes. Timeout PR #20103 was closed by the v1 freeze, not on its merits.
6. **Restart recovery needs fencing and consent.** #44844 (merged) added it. But auto-resume now runs pending tasks without consent (#59635) and resumes sessions still live on another server sharing the database (#51213).

## Borrow (ranked, with phase)
1. **Job semantics** — `wait(timeout)` separate from `cancel`, `block` racing `done` vs `backgrounded`, `backgroundAll` (`job.ts`). Phases 2 and 0: replace today's kill-on-timeout with auto-background.
2. **Durable, idempotent completion delivery** — notificationID reused as the injected message id, marker deleted on admission, steer if the parent is busy, wake if idle. Phase 2.
3. **Every terminal output carries the child id and state** in a stable tag. Phases 0 and 1.
4. **The same tool with a sessionID continues or steers a child, with an ownership check.** Phases 1 and 3. Freeze the agent and permissions on continue, which OpenCode does not.
5. **A final no-tools summary step** (`MAX_STEPS_PROMPT`, `toolChoice none`, tool definitions kept). Phase 3 "wrap up now", and graceful stop in phase 0.
6. **Write-ahead claim, boot sweep, per-turn resume budget and a "restarted, continue" notice.** Phases 1 and 2.
7. **ACP child projection with the capability-gated `child_update`**, plus a durable cursor log next to the volatile stream. Phase 4.
8. **oh-my-opencode patterns:** batch the wake (inject intermediate completions with `noReply`, reply only when all are done or one failed), and judge staleness by inactivity rather than wall clock (45 min since last progress, at least 30 s runtime, re-check activity before interrupting; `task-poller.ts:286-335`). Phase 2 and robustness.

## Avoid
- Treating the first idle as done. Count nested background obligations, including when deciding when `-p` may exit.
- Emitting a terminal "cancelled" before the child has actually stopped (#54658).
- Returning only the last text. That produces the empty-"completed" bug class; aelix's planned tool trail plus files changed is strictly better.
- Plugin-side injection by polling. oh-my-opencode needs about 40 `parent-wake-*.ts` modules to handle its races.
- Wall-clock kills: SessionRunner #6036, and opencode-background-agents' 15-minute timeout that deletes the session (`background-agents.ts:235`, `:1169-1181`). Note that plugin also limits background delegation to read-only agents, citing undo (`:1091-1100`).
- Having no guard at all. Without a delegation timeout, aelix still needs a stream-idle watchdog and a loop detector, kept separate from delegation.
- Allowing the agent or model to change on resume.
- Auto-resume without fencing or consent.

## How much this reference helps each phase
- **Phase 0:** Moderate. It confirms the no-timeout approach, the step-limit summary and keeping the id in failures. But its "partial result" is only a handle, so aelix must go further.
- **Phase 1:** High. Continue-by-id with an ownership check, durable restrictions, and a claim-plus-budget crash-resume design that ports directly.
- **Phase 2:** Very high. The Job and delivery design, `ctrl+b`, and a ready list of bugs to pre-empt (nested background work, `run` exiting early, lost continuation notifications).
- **Phase 3:** Medium-high. Steering through the same tool and the inbox steer/queue/cancel already exist. It lacks a stop action and a wrap-up primitive (borrow `MAX_STEPS`).
- **Phase 4:** Medium-high. The ACP child projection and extension are directly reusable. The HTTP and SSE shape (delivery and resume flags, `interrupt?resume`, durable log) is a good template.
