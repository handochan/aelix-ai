## 1. Current state (measured)

**Settings**
- **The keys exist, but nothing reads them.** The fields are at `aelix_ai/settings/types.py:317-320`, with `packages` at `:311`. The getters and setters are at `settings_manager.py:1591-1675`. A grep for `get_(extension_paths|skill_paths|prompt_template_paths|theme_paths|packages)(` outside the settings package finds no production caller.
- **Merging:** a project list replaces the global list outright (`deep_merge_settings`, `:264-295`).
- **Persisting:** the whole list is written from the in-memory snapshot (`_persist_scoped_settings`, `:864-951`; the list branch is at `:943`). A hand edit made after load is overwritten, and so is a write by another session.
- **A write is silently skipped when its scope had a load error** (`_enqueue_write`, `:800-802` and `:811-812`). I probed this with `create` → `set_skill_paths(["-pdf-tools"])` → `flush()` → `drain_errors()`:
  - fresh file: the entry is written;
  - malformed file: nothing is written, `drain_errors()` comes back empty, and `get_skill_paths()` returns the new value;
  - read-only file: the same as malformed.

  `/scoped-models` reports "persisted" based on that in-memory read-back (`tui/scoped_models.py:615-650`).

**Discovery**
- **Skills.** `_resolve_skill_dirs` (`cli/entry.py:1454-1495`) collects the `--skill` paths, the bundled skills, `~/.aelix/agent/skills`, and `.aelix/skills` when the project is trusted.
  - They load once (`:3450-3456`) and are re-applied from a holder on every rebuild (`:3764`, and `skills_provider` at `:3599-3605`).
  - Only `/agents use` scans again (`agents/service.py:457-461`).
- **`/reload` does not rescan skills (live).** I edited a SKILL.md description and added a skill directory, then ran `/reload` and `/skills`. The old description was still shown, and the new skill was missing. `cli/resource_commands.py:30-31` says the opposite.
- **Same-name skills are not deduplicated.** I measured two directories that each hold a skill `x`: `load_skills` returns both with no diagnostic, and `/skill:x` expands the first one.
  - Because the bundled directory comes before the global one, a bundled skill beats the user's skill of the same name.
  - `entry.py:1473-1477` claims the reverse.
- **Prompts:** `entry.py:1498-1539`, loaded once at `:3463`.
- **Extensions:** `_discover_entries` (`extensions/loader.py:699-886`) imports nothing. It is shared by the loader and by `scan_extension_manifests` (`:889`), which dials manifest MCP servers before the first build.
- **Always-on extensions:** `extensions/always_on.py` (Guardrail, Permission, Status).
- **Extension-contributed skill and prompt paths:** these are collected (`harness/core.py:3971-4000`), but nothing loads them.

**Commands today (pty, 80x24)**
- `/skills` (`tui/commands.py:554-583`) commits a read-only Rich panel. It shows no source and no state, and each bundled description runs 4–6 rows.
- `/skill:<name>` goes through `cli/resource_commands.py:72-122` via `tui/shell.py:4240-4262`. An unknown name gives "Unknown command".
- `/extension` is read-only (`tabbed`, `tui/context.py:1201`). Its "refused" line is cut at the screen edge with no ellipsis.
- `match_command` matches the exact name or an alias (`commands.py:2350-2365`). So a `skill` command with a `skills` alias cannot swallow `/skill:x`.

**TUI pieces**
- **Modal slot:** `show_modal` (`overlay.py:273`) mounts into the chrome slot (`chrome.py:644`, `:1574`; ADR-0159). Its height is capped at rows − 5.
- **`multiselect`** (`context.py:1368-1560`) already has Space to toggle, a single-token type-to-filter, a viewport of 10 rows, and Enter/Esc. What it lacks:
  - it has no locks, sections or detail line, and it never renders the per-row description;
  - its width is capped by `_PICK_MAX_WIDTH = 78` (`:92`) instead of ADR-0219's reader.
- **#632 reproduced.** After Esc from `/extension` or `/scoped-models`, the footer sits on row 8 and rows 9–24 are empty.
- **Commands always run at idle.** They run from the serialized input loop, and anything typed during a turn becomes a steer (`shell.py:926-932`, `:3050`). A turn started by an extension or a background child can still begin while a panel is open.

**Rebuild between requests**
- `_rebuild_system_prompt` (`core.py:4457-4505`) builds `<available_skills>` through `skills_provider`:
  - the rebuild hook is at `entry.py:2150-2169` and the catalog at `:1770-1779`;
  - the catalog is shown only when the read tool is on (`skills_prompt.py:145-189`).
- **No event on change:** `set_skills` (`:1306`) and `set_active_tools` (`:2922`) emit nothing.
- **A dormant event:** `set_resources` → `resources_update` (`:3425-3450`) exists, and nothing in production calls it.
- **Only "between turns" is safe.** Tools and the system prompt are snapshotted per `_run` (`:5187-5240`), but one turn can run several `_run`s (retry, overflow recovery). `is_idle` is at `:1075` and `wait_for_idle` at `:3781`.

**Trust (ADR-0252):** an untrusted project scope is neither read nor written (§A). The mere existence of `.aelix/settings.json` makes the folder require trust (§B).

## 2. pi reference

**What pi has**
- **No in-session skill or tool toggle** (`core/slash-commands.ts:20-43`).
- **`pi config`** is a full-screen CLI tool (`src/cli/config-selector.ts`) built on `components/config-selector.ts`. In it:
  - items are grouped by source, with type-to-search;
  - Space or Enter toggles **and writes immediately** (`:492-498`);
  - Tab switches between Global and Project mode (`:488`);
  - Project mode cycles inherit → `+` → `-` (`:726`).
- **Pattern grammar** (`core/package-manager.ts`):

  | Entry | Meaning |
  |---|---|
  | plain | add a path |
  | `!glob` | exclude. Matches the relative path, the basename or the absolute path; for a SKILL.md it also matches the parent directory (`:715-746`) |
  | `+path` / `-path` | exact include / exclude (`:748-766`) |

  - Within one list, `!` is applied first, then `+`, then `-` (`:772-797`).
  - Each scope's patterns filter only that scope's own discovered resources, against its own base directory (`:2543-2620`).
  - Project entries are resolved first, and the first path seen wins (`:974-985`, `:2751-2761`).
  - Built-in extensions are turned off with `-builtin:<name>`, and a project entry overrides the user's (`:1024-1040`).
  - Paths given on the CLI are "temporary" and are never filtered.
- **Writes:** pi drops every entry that targets the same item, then appends `+X` or `-X` (`:525-570`).
- **`/scoped-models`:** toggles last for the session only, Ctrl+S persists them, and the panel shows an "(unsaved)" marker (`scoped-models-selector.ts:87-96`, `:141`, `:214`).
- **`defaultTools`:** `+name` / `-name`, where plain names replace the default set and the project list applies on top of the user's (`docs/settings.md:42-60`).

**Keep:** the grammar (so pi users' files keep working), grouping by source, search, minimal edits, unfiltered CLI items, and an honest "unsaved" marker.

**Diverge (ADR-0235):**
- one panel per resource kind, inside the session (owner decision);
- Enter saves a batch instead of writing on every keystroke (owner decision);
- `+name` / `-name` entries that match an item's identity, not only its path;
- a two-state toggle that falls back to inherit automatically, instead of a visible three-state cycle;
- global name and glob entries reach every item.

## 3. Storage and filter contract

**3.1 Format.** The same arrays exist in both settings files: `skills`, `prompts` and `extensions`, plus a tools key (decision 11). Entries:
- **A plain path** adds a source. It is resolved relative to that file's base directory (`~/.aelix/agent/` or `<cwd>/.aelix/`). This is also how a folder such as `~/.claude/skills` gets added (#509).
- **`!glob`** excludes, using pi's matching rules.
- **`+X` / `-X`** is an exact include or exclude. X may be one of pi's exact path forms, or (new in aelix) the item's identity:
  - a skill or prompt name;
  - an extension's manifest name, distribution name, entry-point name, or `builtin:<name>`;
  - a tool name.

  `-vue*` still matches nothing, as in pi.
- **One list** applies `!`, then `+`, then `-`. Each list yields on, off, or no opinion.

**3.2 Scopes.** An item's value is the project opinion if there is one, otherwise the global opinion, otherwise on.
- Global name and glob entries apply to every item, including items discovered in the project.
- Path entries resolve against their own file's base directory, so they only ever reach that scope's files.
- Locks (3.7) override both scopes.

**3.3 Trust.**
- **Untrusted project:** the project file is not read (as today), and "This project" cannot be chosen as a save target. The project's resources appear as one locked summary row with a count taken from a directory listing; no file is parsed.
- **No project file yet:** writing the first `.aelix/settings.json` makes the folder trust-gated. The next launch asks for trust, and `-p` runs then need `--approve`. The panel asks for confirmation once before creating the file.

**3.4 How the panel writes.** A new primitive, `SettingsManager.edit_list(scope, key, fn)`:
- it runs `fn` on the list **read from disk**, inside `storage.with_lock`;
- on a load error or an I/O error it raises, rather than recording the error and skipping the write;
- it then refreshes that in-memory scope from exactly what it wrote.

The edit for one item:
1. Remove every entry that targets exactly this item, whatever its prefix.
2. Evaluate what is left.
3. Append `-name` or `+name` only if the result still differs from the wanted value.

Toggling an item twice leaves the file byte-identical. Hand-written globs survive, and the file keeps `indent=2`.

**3.5 Headless and CLI.**
- **One resolver everywhere:** the same resolver runs at launch for the TUI, `-p`, json, rpc and delegated children.
- **Children:** they share HOME, so they see saved state. Unsaved panel edits never leave the panel.
- **CLI flags:** items given by `--skill` or `-e` are forced on, and `--no-skills` / `--no-extensions` force discovered items off.
- **Bad entries:**
  - an entry that matches nothing produces one stderr warning per launch;
  - a malformed value produces a warning and is ignored;
  - a non-empty `themes` or `packages` warns "not supported yet".
- **No new subcommand** in beta.3.

**3.6 Failure reporting.**
- **Unreadable file:** if a scope's file did not load, saving to that scope is refused up front, naming the file and the parse error.
- **After a save:** the panel reads both files again and re-evaluates. Any item whose saved value still differs from what was asked is reported, for example "saved, but the project file keeps it on here".
- **If the save fails:** the panel stays open with the edits intact and a red line, and nothing is applied.
- **If applying fails:** a transcript warning names `/reload`.

**3.7 States.**

| State | Meaning |
|---|---|
| *unsaved* | edited in the panel, not saved yet; lost on Esc |
| *saved* | a fresh evaluation of both files |
| *applied* | what this session is actually using |
| *pending* | saved ≠ applied, and not locked |
| *locked* | fixed by a constraint for this run; Space refuses and the detail line says why |

*Pending* arises in these cases:
- **Skills and tools:** the save happened while a turn was running, or another session or a hand edit changed the file. Pressing Enter applies it.
- **Extensions:** until `/reload`.
- **Manifest MCP servers:** until a restart.

*Locked* comes from:
- the CLI flags in 3.5, plus #510's tool flags;
- the always-on built-ins;
- the skill set of an agent profile;
- a same-name duplicate that is shadowed;
- an untrusted project.

A locked row whose saved value disagrees shows both, for example "saved off · forced on by --skill".

**3.8 When changes take effect, and the hook bus.**
- **Skills:**
  - Enter applies immediately if the session is idle.
  - Otherwise a task waits on `wait_for_idle()` and applies then; if several saves queue up, the newest wins.
  - The change reaches the next model request and never lands mid-turn.
  - Skill text already in the conversation stays, and the panel says so.
- **Prompts:** at launch and on `/reload`.
- **Extensions:** at launch and on `/reload`. The filter runs inside `_discover_entries`, so a disabled extension is never imported and its manifest MCP servers are never dialled.
- **Tools (#510):** at the same boundary as skills.
- **One choke point:** a single `effective_skills()` is used by the factory, the rebuild hook, `/agents use`, `/reload` (which now rescans) and the panel.
- **The apply sequence:** `set_skills` → `rebuild_system_prompt()` → emit `resources_update` with the previous and new name lists (decision 8). The save itself is an ordinary settings write.

## 4. Shared selection component

The headless part has no prompt_toolkit imports and lives in `aelix_coding_agent/core/`:

```python
# resource_filter.py: pure functions
def evaluate(item, entries: list[str], base_dir) -> bool | None
def effective(item, global_entries, project_entries) -> tuple[bool, Scope | None]
def edit(entries, item, want: bool, inherited: bool) -> list[str]

# resource_selection.py
@dataclass(frozen=True)
class ResourceItem: kind: str; key: str; label: str; description: str; group: str; path: str | None
@dataclass(frozen=True)
class Lock: value: bool; reason: str
@dataclass(frozen=True)
class ItemState: item: ResourceItem; saved: bool; applied: bool; decided_by: Scope | None; lock: Lock | None

class ResourceKind(Protocol):             # one per issue
    kind: str; settings_key: str; effect: Literal["next_request", "reload"]
    def items(self) -> list[ResourceItem]  # must never import disabled code
    def locks(self) -> dict[str, Lock]
    def applied(self) -> set[str]
    async def apply(self, enabled: set[str]) -> None

class ResourceSelection:
    def snapshot(self, kind) -> Snapshot   # fresh read of both files
    async def save(self, kind, edits: dict[Scope, dict[str, bool]]) -> SaveResult
    async def apply(self, kind) -> ApplyResult
```

The TUI part lives in `aelix_coding_agent/tui/selection_panel.py`:
- `SelectionModel` is pure state: rows, cursor, filter, target scope, edits and the dirty flag. `toggle()` returns a refusal reason for locked rows.
- `SelectionList(UIControl)` renders the model at `terminal_columns(chrome, max_width=render_max_width)`.
- `run_selection_panel(ctx, selection, kind, *, title)` is the modal host built on `show_modal`.

**How each issue reuses it:**
- **`/skill`** calls `run_selection_panel(..., SkillKind(...), title="Skills")`.
- **`/tool` (#510)** makes the same call with a `ToolKind`. Its groups are Built-in, Extension and MCP server, and a tool whose MCP server is off shows as locked.
- **`/extension` (#25):**
  - `tabbed` gains one interactive tab type: a body with `render(width)` and `handle(key)`.
  - The Installed tab becomes a `SelectionList` over an `ExtensionKind`; Discover and Sources stay plain line tabs.
  - Tab and Shift-Tab switch tabs, and ←/→ is the scope control inside the list, so no key collides.
  - #25 only has to write `ExtensionKind`.

**Recommendation: A.**
- **Why A:**
  - One row per item works for 100+ skills and down to 50 columns.
  - It extends the existing picker language (`multiselect`, rule-framed titles) and pi's grouping by source.
  - Enter-closes matches every other aelix picker.
  - The result lands in the transcript, so it is still there later.
- **Against B:** it is the most informative per item. But it needs about 75 columns, has to switch to a stacked layout below that, and the stay-open behaviour makes it unclear when a save has happened.
- **Against C:** it is the most honest about saved versus now, and it shows the exact JSON. But it costs an extra keystroke on every save, and the table loses the source grouping.
- **If saved ≠ now turns out to be common in #25,** add C's "Now" column to A only when at least one row is pending.

## 6. Risks

- **#632 anchoring.** Option A is 17 rows at 80x24. When it closes, the input stays where the panel's top was; I measured the same thing on `/extension` (footer on row 8, rows 9–24 empty). A fixed height bounds the gap but does not fix it (decision 12).
- **Flicker (ADR-0194).**
  - The height stays fixed while the filter narrows the list.
  - Closing is one frame: unmount and print the summary in a single `print_above_many(..., apply_before_redraw=unmount)`.
  - Only the visible window is rendered per keystroke.
- **The 120-cell cap (ADR-0219).** The panel width is read per render from `terminal_columns(chrome, max_width=render_max_width)`, not from `_PICK_MAX_WIDTH = 78`. The description column takes up any extra width.
- **Long names and descriptions.**
  - The name column is the longest name, clamped to 12–24 cells, cut with `…` by display width (CJK-aware).
  - The detail strip wraps to at most 2 rows at 80 columns and 3 at 50.
  - Names and descriptions come from files, so they go through `_picker_payload`, which names control characters (#179).
- **100+ skills.**
  - Only the visible window is rendered, the cursor's group header stays pinned, and a counter shows `(37/112)`.
  - PgUp, PgDn, Home and End work.
  - Opening the panel reuses the already-loaded skills and does not rescan.
  - #25's metadata scan runs via `to_thread` behind a "loading" row.
- **Already measured, and covered in §3:**
  - a stale write clobbering hand edits;
  - a silent failed write;
  - the trust flip when a project file is first created;
  - duplicate skill names;
  - MCP servers of disabled extensions being dialled.
- **Prompt cache.** Every applied change rewrites the system prompt, so the next request misses the cache. This needs one line in the docs.
- **Read tool off.** When the read tool is off, the skills catalog disappears entirely. The panel shows a banner, and toggles still save.

## 7. Decisions for the owner (each with my recommendation)

1. **Layout:** A.
2. **Grammar:** keep pi's grammar and add exact matching on identity (`+name` / `-name`). The panel writes the identity form, e.g. `"-pdf-tools"`.
3. **Precedence:** project, then global, then on. Global name and glob entries also reach project items (this diverges from pi).
4. **Project target:** use a ←/→ "Save to" control with a two-state toggle that drops the override when it equals the inherited value, rather than pi's three-state cycle.
5. **Creating `.aelix/settings.json`:** allow it after a one-time confirmation that names the trust consequence.
6. **Same-name skills:** the first wins in the order `--skill` > project > global > bundled, and the others are listed as locked "shadowed". This changes today's behaviour, where `/skill:` picks the bundled skill.
7. **`/reload` rescans skill directories,** as pi does.
8. **Bus event:** reuse the dormant `resources_update`, which is already in the extension API, instead of adding a new aelix-only event.
9. **`/skill:<off>`:** refuse with "pdf-tools is off — /skill to turn it on". Do not expand it, and do not say "Unknown command".
10. **Esc:** discard and close immediately, with a one-line transcript note. No confirmation prompt.
11. **Tools key for #510:** pi's `defaultTools`, with its name and grammar.
12. **#632:** land its fix before #511's live check, because all three panels inherit the problem.
13. **Prompts:** filtered through settings, but no panel (the owner's rule stands).
