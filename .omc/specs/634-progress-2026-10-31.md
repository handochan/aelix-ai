## What changed

- `aelix_agents/tool.py`, `AGENT_TOOL_PARAMETERS`: declared order `profile,
  action, id, mode, task, tasks, cwd` (was `profile, mode, task, tasks, cwd,
  action, id`). Every property's content byte-identical (checked by loading the
  old dict from `e19ab55e` and comparing each property's `json.dumps`), and
  `required` stays `["profile"]`. A comment on the schema states the rule.
- `_RESUME_NEEDS_TASK`: "action='resume' needs 'task': the next instruction for
  that agent, and this call arrived without one. It keeps its own conversation,
  so say what to do next rather than the whole job again. Send the call again
  once, with 'task'. If this refusal comes back, do not send it a third time:
  start a fresh agent() run for the work instead." No provider named. The bound
  is advisory wording, not a counter.
- `tests/agents_ext/test_agent_schema_order_634.py` (12 tests): the order pinned
  with why; the order as the OpenAI-compatible converter sends it; each measured
  call shape through an in-order decoder model read off the schema itself; that
  model reproducing Ionstream's failure on the old order; the refusal text; and,
  at the hook, nothing spent.
- Docs: ADR-0277 header line and amendment section, the ADR index row, a
  CHANGELOG Fixed entry.

## Live A/B through aelix (rule 10)

Method: a scratch HOME and `AELIX_CODING_AGENT_DIR` (the owner's `~/.aelix`
untouched); `models.json` `providers.openrouter.modelOverrides
["deepseek/deepseek-v4.1-flash-1017"].compat.openRouterRouting = {"order":
["Ionstream"], "allow_fallbacks": false}`; a scratch profile `w` ("answer with
exactly the text asked"); a scratch cwd per run; one `-p` prompt with `--agents
--thinking high` that delegates "Answer with exactly: ALPHA" and then resumes the
same agent with "Now answer with exactly: BETA". A read-only tap on the parent's
`_open_stream` logged the routing sent, the `agent` schema's declared order,
every chunk's `provider` and each tool call's raw arguments — never headers, the
key or messages. Counts are from the parent's session file and agree with the
tap. The key was loaded from `.env` into the driver only; every output was
searched for an OpenRouter key prefix, a bearer token and an authorization
header, and held none.

| `e19ab55e` | 5 | 47 (11, 12, 9, 9, 6) | 0 | 0 | a new delegation, every run |

All 133 parent requests across the 18 runs sent the pin and were served by
Ionstream (the round-1 verifier's recount). The wording rows chose the shipped
text: the uncounted one still drew 6–7 refusals per run, the counted one 2–3
(one run sent the call a third time). The order's runs met no refusal, so they
did not exercise either wording. Only single and resume calls were run on
Ionstream under the new order; parallel, chain and `cwd` rest on the decoder
model.
