## 4. S3(#137)의 설계 분기가 바뀌었다 — 실측 근거

독립 재현 완료(내 스크립트 + 에이전트의 실제 OS 프로세스 2개). 이슈 본문의 메커니즘은 **정확하다**.
하지만 본문이 제시한 두 선택지가 둘 다 문제가 있다.

- **A) 단독 쓰기 잠금** — 보이는 것보다 훨씬 비싸다. `repo.fork`가 호출자가 이미 쥔 파일을
  다시 열어 **자기 교착(실측)**, `--export`는 순수 읽기인데 쓰기 생성자를 타서 **거짓 거부**,
  그리고 **해제 seam이 아예 없다**(`SessionStorage`에 `close`/`dispose`/`__aexit__` 0개) —
  잠그면 프로세스 수명 내내 샌다. Windows 다리는 #46이 이미 "교체 대상 파일이 아니라
  **사이드카**에 잠가라"로 결론냈고, Windows CI 레그가 없어 검증도 불가.
- **B) tail 재읽기** — 아무것도 안 잃지만 **두 대화가 한 줄로 엮인다**. 터미널 A의 다음
  `--continue`가 터미널 B의 턴을 재생한다. 조용하기는 마찬가지.
- **C) 감지 후 분기** — append 전 파일이 커졌으면 새 세션 파일로 갈라진다. 잠금·Windows·해제 seam 불필요.
- **D) 감지 후 경고 + 도달 경로** — 막지 않는다. 잃은 턴은 **디스크에 있고 파싱도 된다**;
  없는 건 도달성뿐이다. 로드 시 다중 leaf를 알리고 그 가지로 갈 수 있게 한다.

**권장 = D + C.** D가 제목의 불만("silently")을 끝내고 **이미 디스크에 있는 세션 77개를 구제**한다.
C가 새 분기를 막는다. 둘 다 잠금·Windows 다리·해제 seam이 필요 없다.

근거 3개:
1. **pi 0.79.9는 같은 결함을 두 스택 모두에 갖고 있다**(실행 확인). 상속한 것이지 만든 게 아니다.
   그런데 **pi의 `/tree`는 고아 가지를 루트로 보여주고 선택하게 한다**(`session-manager.js:891`).
   aelix의 `/tree`는 다른 기능(부모-세션 계보)이다 → **탈출구 없이 스토리지만 포팅한 것이
   이미 존재하는 divergence**다. 고치는 게 divergence가 아니라 되돌리는 것.
2. **감지는 거의 공짜** — 로더가 이미 도는 루프에 `set` 하나. 🔴 단, 순진한
   "누구의 부모도 아닌 것" 규칙은 **과다 검출**한다(`set_leaf_id` 뒤 정상 rewind를 분기로 오인, 실측).
   올바른 규칙: `parented = {parent_id} ∪ {leaf 엔트리의 target_id}`, 후보에서 `type=="leaf"` 제외.
3. **aelix에는 두 번째 leaf에 도달하는 UI가 0개다**(슬래시 34개 중 0, RPC 0, CLI 플래그 0).
   🔴 그리고 `aelix --fork`와 `/import`는 고아의 바이트를 새 파일로 복사한 뒤 **거기서 다시 고아로 만든다**.

부수 확인: 서브에이전트는 안전(`--no-session` + `MemorySessionStorage`, 디스크 안 만짐),
`aelix status`는 세션 파일을 읽지 않는다.

### #137 "기반이 이미 있다" — 라이브 확인 결과 (절반만 맞음)

```
BUILD: 2ba3261
LEAVES (correct rule): ['d72334cd', '303e411c']   fork detected: True
plain --continue replays:  ['shared ancestor', 'TERMINAL A — the turn that wins']
[/clone seam]        repo.fork(entry_id=<고아>, position='at')
   new file replays: ['shared ancestor', 'TERMINAL B — the turn that vanishes']
[navigate_tree seam] Session.move_to(<고아>) in place
   replays:          ['shared ancestor', 'TERMINAL B — the turn that vanishes']
[control] 평범한 rewind — naive rule: 2 leaves (FALSE ALARM) / correct rule: 1 leaf
```

**있다**: 입양 기계는 이미 있고 빌트인 `/clone`이 이미 그 seam(`runtime.fork(id, position="at")`,
`shell.py:983`)을 쓴다. 고아 id를 넣으면 그대로 입양된다. `Session.move_to`로 제자리 복구도 된다.

**없다**:
- 🔴 **`/tree`는 그 tree가 아니다.** `parent_session_path`를 따라 **세션 파일**을 거슬러 오른다
  (`shell.py:1013-1023`). 한 파일 안의 엔트리 숲은 안 본다 — 분기된 파일은 **행이 하나**다.
  pi의 `/tree`는 엔트리 숲을 그리고 고아를 루트로 올린다(`session-manager.js:891`). **이름만 같다.**
- `/fork`는 가장 최근 user 메시지만 겨냥하고 `position="before"`로 **뒤로** 자른다.
- leaf를 열거하는 코드가 **0줄**.
- 🔴 `aelix --fork`와 `/import`는 고아 바이트를 새 파일로 복사한 뒤 **거기서 다시 고아로 만든다**.

남은 것은 배선 5개: ① leaf 열거(🔴 순진한 규칙은 위 대조군처럼 **오경보**) ② 로드 시 경고
③ 고아로 가는 빌트인 명령 ④ append 전 감지→분기 ⑤ `--fork`/`/import` 재-고아화 수정.
