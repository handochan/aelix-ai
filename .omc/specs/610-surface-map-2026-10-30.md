### 1. `agent` tool schema and parsing (A/tool.py)

**Schema** (`AGENT_TOOL_PARAMETERS`, :124-191)
- Properties are `profile`, `mode`, `task`, `tasks` and `cwd`.
  - `mode`: enum built from `_MODES = ("single","parallel","chain")` (:116), default `single`.
  - `tasks`: minItems 1, maxItems `MAX_PARALLEL_TASKS` = 8 (:103).
- `required` is `["profile"]` only (:190). The rule "task for single, tasks for the others" is enforced in the parser, because `if/then`/`oneOf` are not honoured by every provider (:178-189).
- There is no `additionalProperties`, and the `timeout_ms` property is gone (:172-176).

**How the mode is chosen** (`_parse_mode`, :328-343)
- `None` means `single`.
- Anything else outside `_MODES` is refused with "mode=… is not a mode. Use one of: single, parallel, chain."
- There is no case or whitespace forgiveness, and `mode=""` is refused.

**Refusals in `parse_agent_call`** (:408-515). Each raises `AgentCallError`, which the hook turns into a blocked call (extension.py:908-911):
- `profile` missing, blank or not a string (:428-430).
- `mode=single` with `tasks` present (:447-451); `mode=single` without `task` (:452-457). A single `task` is normalised to a 1-tuple (:459).
- `parallel`/`chain` with `task` present (:461-464).
- `_parse_tasks` (:375-405): not a list, empty, more than 8 (the whole call is refused, never trimmed, :389-395), or a blank member.
- Task too big: `check_task_size`, `MAX_TASK_BYTES` = 65536 (A/chain.py:51, :296), applied at :473-478.
- Chain step 1 uses `{previous}` (:484-489).
- `cwd` not a string or blank (:491-493). Containment is checked later, in the hook.
- `background` truthy (:503-508).
- `timeout_ms` is read nowhere and ignored (:495-502).
- Presence is judged by `_absent` (`None`, `""` or `[]`), but only for the `task`/`tasks` pair (:346-372).

**Unknown keys**
- The kernel validator keeps unknown keys ("additive, never strips", AI/tools.py:11, :252). The parser reads only the keys listed above, so every other key is silently ignored.
- **Consequence today:** `{"profile":…,"task":…,"action":"resume","id":…}` runs a fresh spawn and the model believes it resumed.
- Once `action` exists, an unknown action (for example #611's `spawn` sent to this build) must be refused, not treated as `run`. This is the same reasoning as the `background` refusal (:503-508).

**`AgentCall`** (:252-298)
- Frozen dataclass with `profile`, `tasks` (always a non-empty tuple), `mode="single"` and `cwd=None`.
- The `.task` property raises `TypeError` on a batch.

**`PendingSpawn`** (:301-325)
- Holds `grant`, `resolved`, `call` and the contained `cwd`.
- `_execute` never reads `args`; everything comes from this object (extension.py:1236-1247).

**Description**
- `_DESCRIPTION_HEAD` (:193-216) is 1170 bytes against a 2048 cap (`DESCRIPTION_HEAD_MAX_BYTES`, :91), leaving 878 bytes.
  - It says "There is no conversation … you cannot steer it mid-run" (:198-200). Resume needs that sentence reworded.
- `build_description` (:552-558) is the head, then "Available profiles:" plus the roster. The roster is capped at 4096 bytes, 24 profiles and 160 characters per entry (:77-89).
- The description is re-stamped on every `before_agent_start` through `with_description` (:601-619, extension.py:866-871).
- `create_agent_tool` (:561-598) sets `execution_mode="sequential"` and `delegation` provenance.

**Where `action`/`id` would fit with least churn (my suggestion)**
- **One spelling of the action set.** Add `_ACTIONS = ("run","resume")`, shared by the schema enum and the parser the way `_MODES` is.
- **Schema.** Add `action` (enum, default `"run"`) and `id` (string).
- **Parser.** Put a `_parse_action` at the top of `parse_agent_call`, mirroring `_parse_mode`:
  - `None` means `run`; an unknown value is refused, and `""` is refused like `mode=""`.
  - The `run` path then stays byte-identical.
- **Absent values.** Providers that fill in every declared property will send `action: null` and `id: null` or `""` on every `run` call, so those must count as absent (`_absent`).
- **`resume` branch.**
  - `id` is required and refused if path-shaped (an absolute path is ADR-0243 §5's no-path rule).
  - The instruction comes through the existing `task` field, which reuses the 64 KiB check and the `_absent` rules.
  - `tasks`, `mode` other than `single`, `cwd` and `background` are all refused. `id` together with `action=run` is refused.
- **`profile` and `required`.** One of two options:
  - Keep `required: ["profile"]` and require a resume to name the profile, cross-checked against the stored name. This keeps the T/ pin and adds an identity check.
  - Or change it to `[]` and enforce the rule in the parser. That breaks `required == ["profile"]` (test_tool_and_security.py:1455).
- **Data flow.** Add defaulted `action="run"` and `id=None` fields to `AgentCall`, with `tasks=(instruction,)` and `mode="single"`. `PendingSpawn` gets an optional frozen resume target. `_execute` dispatches on the action before the `mode == "single"` branch (extension.py:1405).

### 2. A fresh single spawn, from the tool call to the child argv

**Kernel**
- The `agent` tool is sequential, so the whole batch runs one call at a time: `tool_execution_start`, then the `tool_call` hooks, then execute, then the next call (K/loop.py:693-724, :727-802).
- Hook order is Guardrail, then Permission, then AgentsExtension (E:1933-1935). The first block wins.

**Hook `_on_tool_call`** (A/extension.py:873-981)
1. Keeps the context (:888).
2. Refuses if delegation is unavailable or another runtime took the seam (:891-904), or at depth (:905-906).
3. Parses the call (:908-911).
4. `runtime.resolve_profile(name, allow_project=False)` (:919).
5. `resolve_child_cwd(call.cwd, host cwd)` (:929).
6. Refuses the whole call if `len(tasks) > remaining_delegation_budget()` (:954-958).
7. `_grant_for` (:964, body :983-1101); a decline blocks the call (:967-974).
8. Stores `_pending[tool_call_id] = PendingSpawn(...)` (:978-980).

**`_execute`** (:1227-1491)
1. Pops the pending entry and refuses without one (:1259-1261); checks depth again (:1262-1266).
2. Re-resolves the profile by name and refuses if `source_path` differs from the grant's (:1291-1299).
3. Writes the disclosure row (:1381) and creates `CallEnvelopes` (:1403).
4. Single mode calls `runtime.spawn_granted(grant, resolved, call.task, cwd, on_event, record=SpawnRecordMeta(tool_call_id, mode, 0, envelopes))` (:1405-1424), then `render_subagent_result` (tool.py:1017-1064).
5. On `CancelledError`, `_report_cancelled` queues a report for the next turn (:1466-1476, :1176-1225).

**`spawn_granted`** (A/runtime.py:820-890)
- `_reject_unsupported` allows only `single` and no background (:1601-1607).
- Refuses a non-consented grant (:867-870), re-contains the cwd (:871-874), then calls `_run(..., charge_budget=True)`.

**`_run`** (:996-1232)
1. Warns once about an ignored `timeout_ms` (:1059).
2. Refuses while a `stop_all` holds the door shut (:1066-1067).
3. `_admit_live` (:1068-1070), then the budget charge (:1076-1079).
4. Mints `spawn_id = "sub-<12hex>"` (:1080, :1797) and inserts the registry row (:1081-1082).
5. Builds the `SpawnPlan` (:1088-1124):
   - `permission_mode=_tighten(grant.mode, floor)`
   - `parent_tools=host.active_tools()`
   - `parent_context_files=host.context_files()`
   - `parent_thinking=_parent_thinking()`
   - `parent_cwd=host.cwd()`
6. Builds the `SpawnReceipt` (:1129-1139).
7. `receipt.open(host.session(), cwd=child_cwd)` allocates `<parent stem>/<spawn_id>.jsonl` (:1153-1155; A/child_session.py:389-472).
8. `channel.run` (:1168), then `_with_run_facts` adds `started`, `session_id`, `session_path` and the written files (:1310-1356).
9. Writes the settle and final records (:1179-1181). The `finally` writes a shielded unsettled settle if needed, pops the row and publishes a terminal snapshot (:1186-1232).

**`PrintChannel.run`** (A/print_channel.py:1041-1273)
- `narrow_tools`, then `narrow_context_files`, then `inherit_thinking` (:1063-1072).
- Writes the 0600 prompt file (:1113).
- `build_child_argv` (:1122-1137, body :591-668). It reads `parent_model` live from the channel's getter (:1129-1131) and the registry (:1136).
- `build_child_env` (:671-717): inherited environment plus `AELIX_SUBAGENT_DEPTH` (:689-694) and `AELIX_STDIN_TIMEOUT=1` (:700); `AELIX_MCP_CONFIG` is removed (:705); `PYTHONPATH` is prefixed (:711-715).
- `create_subprocess_exec` with `cwd=plan.cwd`, stdin DEVNULL, a new session/process group and pdeathsig (:1140-1181).

Probed argv for a scout profile with no `tools:` key, under a parent holding `[read, bash, agent, an extension tool, an MCP tool]`:

```
-m aelix_coding_agent --mode json -p --session /s/sub-abc.jsonl --tools bash,read --no-extensions --append-system-prompt-file /tmp/p 'Task: go' --permission-mode plan --no-agents
```

**Other doors**
- **Parallel and chain.** extension.py:1427-1465 → `run_batch` (A/batch.py:200-270) → `_run_parallel` (:273-319) or `_run_chain` (:322-382). `_run_chain` renders `{previous}`, re-checks the size and stops at the first failure.
  - Each member goes through `_member` (:385-466) under a per-loop semaphore, `MAX_CONCURRENCY` = 4 (:70, :591-618), then `spawn_granted(..., permission_floor=_live_floor(batch), record=replace(record, index=i))` (:444-456).
  - `_live_floor` (:483-588) tightens later members when the parent's posture or UI tightened.
- **`/agents run`.** C/tui/commands.py:1270-1344 → `resolve_profile(name)` (a project profile gets a per-identity confirmation, then `allow_project=True`, :1285-1303) → `runtime.spawn(resolved, task, on_event)` under `ctx.run_cancellable` (:1320-1326).
- **RPC `agents/run`.** `run_agent` (C/rpc/control.py:763-804) → `runtime.spawn(resolved, task)` (:796).
  - It is a serialised mutation that needs an idle runtime (:89-104, :292-297).
- **`runtime.spawn`** (A/runtime.py:721-818) reopens the door, uses the parent cwd, takes consent itself through `request_spawn_consent(host.consent_context(), …)`, and calls `_run(charge_budget=False, record=None)`.
  - It still writes a receipt and a child file, with `tool_call_id`, `index` and `mode` all null.

**Contract** (C/subagent_contract.py)
- `CONTRACT_VERSION = 1` (:34-36) is bumped only for a shape change or a new required parameter; a defaulted field does not bump it. `bind_subagents` accepts MIN to CURRENT (:38-45).
- `SubagentRuntime` is a `runtime_checkable` Protocol (:343-427) and the bind does an `isinstance` shape check (C/extensions/api.py:612+, refusal 4). Adding a Protocol member would refuse existing v1 third-party runtimes (runtime.py:637-642 makes this argument for the budget).
- The grant must stay off the Protocol: `test_protocol_has_no_consent_parameter` (T/agents/test_subagent_contract.py:170).
- **So resume belongs beside `spawn_granted` on `_SubagentRuntimeImpl`, the private door. New `SubagentResult` fields are additive.**

### 3. Each restriction: where it is computed, how it reaches the child, whether it is stored

**What is stored today**
- Parent's start and settle records (child_session.py:491-505):
  - `profile` — the **name only**.
  - `task_preview` — 200 characters (:105; runtime.py:1135).
  - `child` — `{session_id, path, rel}`.
  - `requested_model` — the display id from `child_model_id` (runtime.py:1083, :1136).
  - `permission_mode` — after the batch floor (runtime.py:1138).
  - plus `tool_call_id`, `index`, `mode`, `aelix_version`.
- The settle adds the model and provider that actually ran, the status and the usage (:555-571).
- The child file's `aelix.child_origin` record (:476-489) has `key`, `parent {session_id, path}`, `profile` and `permission_mode`.
- The child file's header `cwd` is the child's cwd (:460-466).

**Not stored anywhere:** the narrowed tool list or the parent's grant, `source_path`, `scope`, `approval_mode`, `widened`, `context_files`, thinking, skills/extensions, the system-prompt body or a digest of it, `output_cap`. The issue requires storing profile, permission mode, narrowed tools, cwd, thinking, context-files and model.

**a. Profile, identity and system prompt**
- **Computed:** `resolve_profile` (runtime.py:670-717), which refuses path-shaped names (:691-696), via `discover_profile` (C/agents/discovery.py:303-375).
- **Inputs:** the call's name, `host.cwd()`, `host.project_trusted()` and `host.agent_dir()`. The model door always passes `allow_project=False` (extension.py:919, :1292).
- **To the child:** the body goes into a 0600 temp file passed as `--system-prompt-file` or `--append-system-prompt-file` (print_channel.py:1113; C/agents/resolver.py:416-419). The file is deleted after each run (print_channel.py:1244).
- **Can change before a resume:** the file can be edited, deleted, renamed or shadowed (a project profile wins a name collision), and the agent dir or the trust decision can differ.
- **Resume needs:** a stored `source_path` (and ideally a body digest) to compare, otherwise the child's identity changes mid-conversation. A deleted profile is the issue's "profile missing" refusal.

**b. Permission mode**
- **Computed:** `child_permission_mode(approval_mode, parent posture, scope, has_ui)` (A/posture.py:175-231), called from `_grant_for` (extension.py:1057-1064) or inside consent (A/consent.py:1300-1303).
  - A human may raise it to `AUTO_ACCEPT` (consent.py:1410-1415).
  - A batch member may be tightened by `_tighten` (runtime.py:1587-1598, :1106).
- **Parent posture source:** the shared `PermissionPosture` object (extension.py:477-483; E:2990).
- **To the child:** `--permission-mode` (print_channel.py:664-665).
- **Stored:** yes, in the records.
- **Can change:** shift+tab, a relaunch with another mode, `has_ui` (TUI versus `-p`), and the profile's `approval_mode`.
- **Intersection:** take the rank minimum over `_RANK` (posture.py:42-48: plan 0 < default 1 < auto-accept-edits 2 < auto 3 < yolo 4), not `CYCLE_ORDER`.
  - That is `_tighten(stored, live clamp)` (runtime.py:1587-1598). The live clamp maps DEFAULT to PLAN and AUTO to AUTO_ACCEPT (posture.py:54-60, :231).
  - `widened` is not stored. A human could re-widen only up to the stored mode, and only if `_may_widen` holds now.

**c. Tools**
- **Computed:** `narrow_tools(profile, plan.parent_tools)` (print_channel.py:386-419) gives `profile.tools ∩ parent grant ∩ ALL_TOOL_NAMES − {"agent"}`.
  - The parent grant comes from `_host_active_tools`: the live API first, then the hook context (extension.py:567-601), frozen at `_run` (runtime.py:1107).
  - `ALL_TOOL_NAMES` = bash, edit, find, grep, ls, read, write (probed).
- **Effect on extension and MCP tools:**
  - Every extension and MCP tool name is dropped from the grant and reported as "dropped".
  - After narrowing, `tools` is always an explicit tuple. The child therefore always gets `--tools a,b`, or `--no-tools` for an empty set (resolver.py:392-399). Under that allowlist, any extension or MCP tool registered inside the child is inactive (E:1109-1131).
  - The probe confirmed `tools=None` became `('bash','read')`, with `agent`, `mcp__x__y` and `my_ext_tool` dropped.
- **Stored:** no.
- **Can change:** `/agents use`, `set_active_tools`, a relaunch with `--tools`, a profile edit.
- **Intersection:** stored allowed set ∩ live parent grant (∩ the current profile's `tools`, if any) ∩ `ALL_TOOL_NAMES` − `agent`.
  - This is implementable by passing the stored set as `profile.tools` and the live grant as `parent_tools`.

**d. `--no-agents` and the depth guard**
- `--no-agents` is always appended (print_channel.py:667).
- The depth comes from the env var `AELIX_SUBAGENT_DEPTH` (print_channel.py:689-694; `MAX_SUBAGENT_DEPTH` = 1, subagent_contract.py:47).
- The parent itself is guarded three times: the extension is not loaded at depth (E:1934), the seam refuses the bind, and the tool refuses (extension.py:905-906, :1262-1266).
- These are constants. A resume that goes through `build_child_argv`/`build_child_env` re-applies them automatically.

**e. cwd and the trust flags**
- **cwd:** `resolve_child_cwd` (print_channel.py:538-588) requires containment in the parent, an existing directory and no control characters. It runs at the hook and again at `spawn_granted`.
- **To the child:** the subprocess `cwd` and the child file header.
- **Stored:** only in the child file header.
- **Trust flags:** `child_trust_argv(child_cwd, parent_cwd)` (A/trust.py:32-91) emits `--no-approve` unless the child shares the parent's cwd and that directory has no trust-requiring resources. It fails closed and is recomputed every time.
- **Can change:** the parent can be reopened from another directory (`repo.open(..., cwd_override=cwd)`, E:452), or the child's directory can be deleted.
- **Resume:** this is not an intersection. Re-contain the stored cwd against the current parent cwd and refuse if it fails (the issue's "outside cwd").

**f. Thinking level**
- **Computed:** `_parent_thinking` (runtime.py:1470-1484), from `host.thinking` (extension.py:721-753; E:3030).
- **To the child:** `inherit_thinking` (print_channel.py:470-535) emits `--thinking` only when the profile names neither model nor provider (resolver.py:293-304, :413-414).
- **Stored:** no.
- **On resume:** without `--thinking` the child restores the level its session recorded (E:3970-4004). With `--thinking`, argv wins.
- This is not an authority, so pin the stored value rather than intersect.

**g. Context files**
- **Computed:** `host.context_files()` is `not parsed.no_context_files`, read live (extension.py:603-636; E:3012).
- **To the child:** `narrow_context_files` (print_channel.py:422-467) produces `--no-context-files` (resolver.py:411-412). It only ever turns context files off.
- **Stored:** no.
- **Intersection:** boolean AND of stored and current (and the current profile).

**h. Model and provider**
- **Computed:** `child_model_flags` (resolver.py:307-339, including `_pin_route` and a possible `--require-registration-route`, :195-290), with the parent's model read live at launch (print_channel.py:1129-1131; E:3024).
- **Stored:** only `requested_model`, an id without a provider. The settle has what actually ran.
- **On resume:** an argv `--model` beats the session's restored model (E:3520-3562). A `/model` before the resume would therefore switch the child's model — the bug class the issue cites from Codex. Pin the stored model.

**i. Skills, extensions, output cap, role**
- These come from the profile only (resolver.py:401-410; profile.py:179-229; `output_cap` at print_channel.py:1076). None is stored.
- `extensions:` loads code (`-e`), so a profile edited between spawn and resume would add code.

### 4. Consent (A/consent.py)

**When the dialog is skipped**
- No live UI: `-p`, `--mode json`, RPC without a UI, during bootstrap, after the TUI exits. The result is the clamp, consented, not widened, with no disclosure (:1322-1329, :1509-1514). `ask` becomes PLAN (posture.py:201-202).
- YOLO parent: never asked (:650-651). A disclosure line is shown instead (:657-701), written at extension.py:1381 and removed at :1490.
- Nothing at stake — `consent_is_required` (:573-654) is false because the clamp grants no write authority (:102-120) and `_may_widen` (:489-570) does not hold. `_may_widen` needs all of:
  - mode is `single` or `parallel` (not `chain`);
  - `approval_mode` is `auto` or `ask`;
  - the profile is not project-scoped;
  - there is a live UI;
  - `AUTO_ACCEPT` is above the clamp.
- The model door pre-filters with the same predicate (extension.py:1057-1085).

**What it shows** (`build_consent_title`, :704-761)
- "Delegate to agent '<name>'?"
- Profile (name and scope), Source (`source_path`, the one line the model cannot influence), Directory, Permission, Model (optional).
- "Task (written by the model, not by you):" followed by the whole task.
- Options (`build_options`, :970-985): "Run read-only (plan)" or "Run with the inherited posture (<m>)"; optionally "Allow file edits for this run (auto-accept-edits)"; "Cancel".
- Every field is sanitised. `_decide` (:1362-1415) accepts only rendered answers. There is one per-loop lock (:124-136). A batch of two or more uses its own title and a height check (:1418-1585).

**How a grant reaches the spawn**
- `SpawnGrant` (:264-306) → `PendingSpawn` → `_execute` → `spawn_granted` → `_run` uses `grant.mode`.
- `grant.source_path` feeds the identity re-check; `grant.disclosure` feeds the statusline row.

**What a resume needs**
- `request_spawn_consent` recomputes the clamp itself and **has no ceiling parameter** (:1300-1303). Capping its grant afterwards would make the dialog show a posture different from the one that runs, possibly including a widening option that is then removed.
- So the stored mode has to be passed into the clamp, the options and the title.
- Use a separate title builder, because `test_the_p2_dialog_body_is_nine_rows_for_every_input` (T/agents_ext/test_spawn_consent.py:1331) pins the fresh-spawn body. It would show:
  - a "Resume agent …" heading and the child id;
  - profile, `source_path` (current versus stored), the stored and contained cwd, the intersected permission and the pinned model;
  - the original `task_preview` (≤ 200 characters, model-written, sanitised);
  - the instruction, labelled as written by the model.
- **Open design question:** whether to offer widening at all. The replayed history was never on screen, which is the chain-mode argument of constraint 6 (:545-559).

### 5. Tracking running children in memory, and the double-resume guard

**What exists**
- `_children: dict[spawn_id, RunningChild]` (runtime.py:579), inserted at :1080-1082 and popped at :1210. It holds live children only (subagent_contract.py:400-416); `status`/`stop` look up by spawn id (runtime.py:899-916).
- `MAX_LIVE_CHILDREN` = 4 (:175, `_admit_live` :661-666) and `MAX_DELEGATIONS_PER_PROMPT` = 12 (:199, charged :1076-1079, reset per prompt at extension.py:861-862).
- The `_draining`/`_closed` door (:583-591).
- The batch semaphore, per loop at module level (batch.py:102); `_pending` per tool call (extension.py:335-340, cleared :855 and :1165); the consent lock.
- **The registry is per harness build.** `AgentsExtension.__call__` creates a new `_SubagentRuntimeImpl` every time (extension.py:360), and the factory runs on every build (E:1933-1935, :1964-1968). The old build is torn down before the new one is created (K/runtime/agent_session_runtime.py:752-753).
  - This contradicts comments that say the runtime survives `/new` (runtime.py:152-154, :611-616, :746-750; extension.py:193-197). I read this from the code; I did not measure it.

**Where to enforce "not resumed twice at once"**
- Inside `_run`'s admission block, which has no `await` (:1066-1082). Keep a map from child key to live spawn id, popped in the `finally`.
- Extra synchronous statements are allowed by `test_the_admission_window_in_run_contains_no_await` (T/agents_ext/test_batch_executor.py:483), which requires the order admit → charge → `_children[spawn_id]=` with no `await`.
- Add a hook-time pre-check as well, so the model reads a refusal before any dialog (the precedent is extension.py:954-958). Today the hook does not check the live cap.

**Can it happen today?**
- **In one process: not through any shipped door.** The tool is sequential (prep then execute per call), `/agents run` blocks the REPL, and RPC `agents/run` needs an idle runtime. It becomes possible with #611's background spawn.
- **Across processes: yes, today.** Examples: a forked parent session in another process (I did not confirm that forks copy the records), or a human running `aelix --session <child file>` (E:4737-4771).
- **A guard already exists: the child's own writer lock.**
  - `SessionWriterLock` (K/session/session_lock.py:144-260) is an flock or LockFileEx on `<child>.jsonl.lock`, released by the kernel when the process dies (:54-58).
  - A non-interactive second child prints "Error: this session is already open in another terminal." and exits 1 (E:4830-4919).
  - It does not hold on filesystems without locking, where it only warns (session_lock.py:208-218; E:4860-4867).
  - The parent sees this as a confusing exit-1 failure. A parent-side `try_acquire` + release before spawning would give a clean refusal but is a check-then-act race; the child's lock stays the real guard.

### 6. Things that make resume risky

1. **Restrictions are not on disk.** Only the name, the permission mode, `requested_model` and the child cwd are stored (§3). Children spawned before #610 lack every new field, so a resume should fail closed rather than guess.
2. **Usage records are folded by key, last line wins** (K/harness/_session_stats.py:266-305; child_session.py:24-27). A resume written under the original `sub-…` key would replace the first run's `final` record and its spend in `/cost` and `/stats`.
   - A resume needs a new key, plus a field linking it to the original child.
   - Note `/stats` reads only the current branch (K/harness/core.py:3134).
3. **`SpawnReceipt.open` always creates a new file** and refuses an existing path (child_session.py:418-472, :457-459). A resume needs a way to adopt the existing file without rewriting its header or origin record.
4. **The model sees a session UUID, not the spawn id.** Today it sees `session_id` only on unfinished children (`Session: <uuid>`, tool.py:993-994; aggregate.py:350). A success shows no id at all, and adding one changes the byte-for-byte pins in §1.
   - The session UUID is stable across resumes (same file). The spawn key is what `status`/`stop` and the records use, and a resumed run gets a new one.
   - Turning an id into a file must go through this parent's start records, preferring `rel`, then `path` (child_session.py:226-230), because `--session <id>` lookups skip child directories.
5. **The resumed envelope covers only the resumed run.** The parent's reducer folds only `message_end`; `agent_end` is just a terminator (A/stream.py:821-878, :940-985), and JSON mode prints only a header followed by new events (C/modes/print_mode.py:348-363).
   - So the summary, tool trail, changed files and usage cover the resumed run only, not the whole child. I read this from the code; I did not measure it.
6. **Interrupted tool calls.** The provider-side transform answers a tool call with no result as `"No result provided"` with `is_error=True`, and drops assistant turns that ended in error or abort (AI/providers/_transform_messages.py:285-330). Anthropic, Google, OpenAI Responses and OpenAI Completions all use it; its docstring at :31-33 still says only Completions does.
   - What is on disk differs by how the child died. Esc sends SIGKILL (print_channel.py:1533-1556), so nothing more is written. `stop` sends SIGTERM, and the child disposes and records its abort (print_mode.py:495-555). Unmeasured.
7. **Records only in memory and lost:** the grant (including `widened`, `scope`, `source_path`), the plan (`parent_tools`, context files, thinking), the argv (including the route digest), the prompt file (deleted after each run), the tool trail and the changed-file list. The cancel report is memory-only as well; extension.py:1206-1209 says #610 reads the settle records instead.
8. **Docs that contradict resume:**
   - ADR-0243 §8, "A child file is a record, not a resumable identity" (docs/decisions/0243-…md:399-410), and the stderr warning at E:4765-4769.
   - The retry sentence in ADR-0276 D11 (:435).
   - Both copies of agent-profiles.md: `docs/guides/agent-profiles.md` and `C/docs/agent-profiles.md`.
9. **Children started from `/agents run` are recorded too** (`mode: null`), possibly under a project profile a human confirmed. A model-driven resume must re-resolve with `allow_project=False`.
10. **Exact record-key pins will change when fields are added:** `_START_KEYS`, `_SETTLE_KEYS`, `_FINAL_KEYS` and `_ORIGIN_KEYS` (T/agents_ext/test_child_session_records.py:92-137), used by `test_the_ok_path_writes_the_four_records_in_their_exact_shapes` :635 and `test_the_parent_publishes_the_childs_header_and_origin_before_it_runs` :374.
11. **Stale or contradictory comments:**
    - E:2960 and :3575 mention a "session consent memo" that consent.py:234-261 says was removed.
    - consent.py:139-151 and T/agents_ext/test_spawn_consent.py:374 call `consent.TASK_PREVIEW_CHARS` (300) the receipt's budget, but the receipt uses `child_session.TASK_PREVIEW_CHARS` (200) (runtime.py:69, :1135).

# Part 2 — session file and receipt

## #610 survey: resume a delegated child on its own session file (tree `claude-610` @ f3e76fbb)

**Answer up front:** `aelix --mode json -p --session <existing child file> "Task: …"` already works as a resume primitive. I ran it against a real child and a mock model, details in §2–3. Four things are missing:
- **No reader:** nothing reads `aelix.child_session` receipts back.
- **Restrictions not stored:** the receipt doesn't hold the restrictions a resume must re-apply.
- **No id for finished children:** the model never sees an id for a child that finished `ok`.
- **Usage fold:** reusing the spawn id as the record key would lose the first run's spend from `/cost`.

Extra prefixes used below: K/ = `packages/aelix-agent-core/src/aelix_agent_core/`, AI/ = `packages/aelix-ai/src/aelix_ai/`.

The worktree is untouched (`git status` clean, HEAD still f3e76fbb). Probe artifacts are only in `/tmp/610-survey-probe/`: the mock server, setup and run scripts, `requests.jsonl`, `run{1,2,3}.std*`, and the session files.

### 1. Receipt format (ADR-0243, `A/child_session.py`)

**On-disk shape**
- Each record is one ADR-0242 `CustomEntry` line: `{"type":"custom","id","parentId","timestamp","customType","data":{…}}`.
- Measured parent file: header, then `aelix.child_session` start, then `aelix.usage` pending.
- Type constants: `CHILD_SESSION_TYPE` :85, `USAGE_TYPE` :88, `CHILD_ORIGIN_TYPE` :95, `RECORD_VERSION=1` :101-103.
- `key` is the spawn id `sub-<12 hex>` (module doc :24-27).

**The four records**
- **Start** (`_identity` + `error`, :491-508): `{v, key, phase:"start", tool_call_id, index, mode, profile, task_preview (200 chars), child:{session_id, path, rel}|null, requested_model, permission_mode, aelix_version, error}`.
- **Pending:** `{v, key, state:"pending"}` (:510).
- **Settle:** a complete record, not the second half of the start (:536-572, :574-619). It carries the `_identity` fields plus `phase:"settle"`, `status`, `model`, `provider` (what actually ran), `usage{input, output, cache_read, cache_write, cost}`, `cost_known`, `context_tokens`, `turns`, `elapsed_ms`, `exit_code`, `stop_reason`, `truncated`, `summary_bytes`, `details_bytes`, `error`.
- **Final:** `{v, key, state:"final", usage, cost_known}` (:524-534).
- `bare_records` (:621-658) is the fallback when building a record raises.
- Readers fold each type by `key`, last line wins (ADR-0243:160-164). A start with no settle means the outcome is unknown.

**When each record is written** (`A/runtime.py _run`)
- The receipt object is built synchronously after the await-free admission block (:1129-1139).
- `receipt.open()` (:1153; `child_session.py:389-402`) allocates the child file, then appends start and pending. This is before `channel.run` (:1168), so before any child process exists.
- Settle and final are written after the envelope comes back (:1179-1180).
- On a cancel or exception they are written in the `finally`, from the live stream, under `asyncio.shield` (:1186-1203). `stop_all` joins those writes, up to `SETTLE_JOIN_SECONDS=5` (:1540).
- The parent session is captured once per spawn (`child_session.py:354-357`, `runtime.py:389-404`). A late settle therefore lands in the session that ran the child.

**Settle statuses**
- `ok` / `error` / `aborted` / `cancelled` / `timeout` (timeout appears on old records only, ADR-0276 D7).
- `cancelled` is settle-only (`runtime.py:1286`). The envelope for the same cancel says `aborted` with `REASON_CANCELLED` (:1439).
- `CUT_BY_THE_PARENT = {"cancelled","aborted","timeout"}` (:272-275). It makes `cost_known` false for any run the parent cut (:298-302).

**Allocation, `_allocate` (:418-472)**
- Placement is `<bucket>/<stem>.jsonl` → `<bucket>/<stem>/<spawn id>.jsonl` (`place_children` :183-216).
- One atomic publish of the header (cwd = the child's cwd, no `parentSession`) plus `aelix.child_origin` (`parentId:null`; data `{v, key, parent:{session_id, path}, tool_call_id, index, mode, profile, permission_mode, aelix_version}`, :476-489).
- **An existing file is refused** (`os.path.lexists` → `child_error`, :457-459). A resume therefore cannot go through `open()`/`_allocate`; it needs its own "attach to an existing file" path.

**Parents that get no child file**
- No-session parent (`Session(MemorySessionStorage())`, C/cli/entry.py:442-443): `session_file` is None, so there is no `child` and `error:null` (:433-434). Records stay in memory and the child runs with `--no-session`.
- Parent outside a bucket: `error:"parent outside a bucket"` (:435-438).
- Failed create: `error:"could not create the child session file: …"` (:467-469).
- In all three cases the child runs `--no-session` (resolver.py:455-456), `session_id` is None, and there is nothing to resume.

**Finding a receipt again**
- **No production reader or index exists.** `grep` finds only writers of `aelix.child_session`. The only reader of any of these records is the kernel's usage fold (`aelix.usage`).
- A test-only reader exists: T/agents_ext/test_child_session_records.py:271-282.
- A reader would scan `session.get_branch()` (stats use the branch, K/harness/core.py:3159) or `get_entries()`, fold by `key`, and match either `key` or `child.session_id`. It should resolve `child.rel` against the parent file's directory first, then `child.path` (:226-230).

**Least-churn way to add fields**
- Add defaulted fields to `SpawnReceipt` and emit them from `_identity()`. Start and settle then both carry them with one edit.
- Keep `v: 1`. Optional unknown `data` keys survive forks (ADR-0242 rule 1.3) and readers ignore them (rule 1.6). The stats fold never reads `v` (K/harness/_session_stats.py:288-289).
- Bumping `v` is unnecessary, and conflicts with this module's own rule that readers ignore an unknown version (:101-103).
- Values must be JSON: lists, not tuples (rule 1.7).
- **Old v1 receipts lack these keys, so the reader must fail closed:** not resumable.

**Timing problem for the new fields**
- The receipt is built before the channel computes the narrowed values:
  - `narrow_tools`, `narrow_context_files` and `inherit_thinking` run in `PrintChannel.run` (print_channel.py:1063-1072).
  - The model flags come from `child_model_flags` with a *live* parent-model read at argv build (print_channel.py:1122-1136).
- So `_run` would compute them once with the same pure functions and hand the frozen values to both the receipt and the plan.
- `requested_model` is display-only. It holds the `--model` id only: no `--provider`, no `--require-registration-route` (resolver.py:283-290, 342-368). It can also diverge from the actual argv in a `/model` race (runtime.py:772-783).
- Not stored today, beyond the profile **name**:
  - the profile's scope, source path or body;
  - the cwd (only the child header's `cwd` has it);
  - skills, extensions and trust flags.

**History, model and thinking on reopen**

**Header (measured):** `{"type":"session","version":3,"id":<uuid>,"timestamp","cwd":<child cwd as allocated>}`. The parent link lives only in `aelix.child_origin.data.parent`.

**Compaction:** a resumed long child can auto-compact in `-p` mode, appending a `compaction` entry to the child file. The compaction's own LLM spend is not in the stream (ADR-0243:326-331). Not measured.

**Measured, working resume.** I used real `SpawnReceipt.open`, a real child via `python -m aelix_coding_agent`, and a local openai-completions mock.

### 4. What the parent model sees (#604)

**Where the session fields are set:** `session_id`/`session_path` are set in one place, `_with_run_facts` (runtime.py:1310-1356, facts :1339-1346), from `receipt.child`. | Case | Id shown to the model |
|---|---|

| Single, started and not ok | `Session: <child session uuid>` (tool.py:993-994) |
| Parallel/chain member, ok | **none** (aggregate.py:244-305) |

### 5. Parent lifecycle

**What stops children**
- `/new`, `/resume`, `/fork`, `/reload` and quit all go through `_teardown_current`, which emits `session_shutdown` (K/runtime/agent_session_runtime.py:615-667, emit :643; reload :1140).
- Teardown calls `_shutdown()` (A/extension.py:1124-1137), then `stop_all` (:1150-1172; runtime.py:918-994): kill the children, join the reapers, join the shielded settles.

**Is the stop recorded?**
- Yes. The settle `aborted` (reason `REASON_STOPPED`, envelope.py:472) or `cancelled` lands in the **old** session, because it was captured at spawn.
- A parent killed with kill -9 leaves start and pending only. The child file exists, but its process may still be alive (pdeathsig is Linux-only) and hold the lock. Not checked.
- The runtime survives the swap (extension.py:193-197). The delegation door stays shut until the next prompt (runtime.py:598-632).
- After `/new` the new session holds no receipts, so nothing is eligible. `/resume` back to the old session makes its children eligible again.

**`/fork` and ownership**
- In-session `/fork` calls `repo.fork(cwd=metadata.cwd)` (agent_session_runtime.py:1321-1328), which copies the path-to-root entries (K/session/repo_utils.py:82-131), receipts included.
- The fork's receipts point at the **old** parent's child files: `child.path` is absolute, and `child.rel` = `<old stem>/sub-x.jsonl` resolves in the same bucket. New children of the fork go under `<new stem>/`.
- `--fork` and the "fork and continue" choice use `fork_from` (all entries, maybe another bucket; entry.py:459, 4936). There `rel` may not resolve, but `path` still does.
- The child's `aelix.child_origin.parent` names the *original* parent. So a receipt-only ownership rule accepts a fork's resume, and an origin-based rule rejects it.
- The child file lock blocks concurrent resumes from two parents. **Sequential resumes from both would interleave runs in one child file.**
- A fork taken mid-delegation keeps start and pending forever (ADR-0243:528-535).

### 6. Cost and stats

**How child spend reaches the totals**
- Only through the parent's `aelix.usage` records on the branch (K/harness/core.py:3133-3172), folded by `fold_usage_records` (K/harness/_session_stats.py:266-346). The fold is last-line-wins **per key** (:298-305), with `runs = len(keys)`.
- That one total feeds the footer, `/cost` (C/tui/commands.py:494-495, row "tools & agents"), `/stats` (C/tui/stats_dashboard.py:209, 233-306), History (TUI only, C/tui/shell.py:903) and RPC.
- **Child files are never read for totals,** so a second run appended to the child file cannot double count by itself.

**What a resume's records would do**
- **Same key:** the resumed run's pending supersedes the first run's final (cost becomes unknown during the run), then its final *replaces* the first's. The first run's spend is lost, `runs` does not grow, and the first run's settle facts are lost too.
- **Fix:** a new key per run, with an optional link field such as `resumes`. Alternatively, cumulative usage under the same key.
- The resumed run's usage reflects only its own stream (measured). It includes re-sent history input tokens, but not compaction calls.

**Listing children:** `/agents` has only list (profiles), show, use and run (C/tui/commands.py:593-596). `runtime.list()` is live children only (:894-897). RPC `agents/list` lists profiles (C/rpc/control.py:738-751). **Nothing lists past children** (the viewer is #296).
