## 1. (A) 시간 제한 제거

**D1. 모델 인자 `timeout_ms`를 없앤다.**
- 스키마 속성(`A/tool.py:172-180`)을 지운다. `parse_agent_call`은 이 값을 읽지 않는다(:500-514, :528).
- 이 인자가 남아 있는 호출은 거절하지 않고 무시한다. 커널 validator가 인자를 지우지 않으므로(:97-100) 그대로 통과한다.
- 지울 것: `MIN_TIMEOUT_MS`, `MAX_TIMEOUT_MS`, `AgentCall.timeout_ms`, `__all__`의 두 이름.

**D2. 프로필의 `timeout_ms`는 받아들이되 효과가 없다.**
- **필드:** `AgentProfile.timeout_ms`(`C/agents/profile.py:234-237`)는 지우지 않는다. docstring에 deprecated·읽지 않음을 적고 남겨 둔다. RPC `agents/show`가 `asdict(AgentProfile)`를 내보내므로(`C/rpc/control.py:753-754`) 호스트가 보는 키를 바꾸지 않으려는 것이다.
- **알려진 키 목록:** `"timeout_ms"`를 `_KNOWN_KEYS`(:110)에 남긴다. 빼면 일반 루프(:311-315)가 경고를 한 번 더 낸다.
- **파싱:** `_parse_positive_int(..., _err)`(:398) 대신 관대하게 읽는다. 값이 무엇이든 프로필을 버리지 않는다.
  - 키가 있으면 `_warn("unknown_field", "timeout_ms is ignored: delegated agents run without a time limit (#604)")`를 남긴다.
  - 값이 정수가 아니면 경고에 그 사실을 덧붙인다. 필드에는 정수일 때만 저장한다.
- **spawn 시 경고:** `resolved.profile.timeout_ms is not None`이면 프로필 경로별로 한 번 `logger.warning`을 쓴다. 기록은 모듈 수준 set에 둔다.

**D3. 작업 마감을 지운다.**

| 파일 | 지울 것 |
|---|---|
| `A/print_channel.py` | `DEFAULT_TIMEOUT_MS`(:132-135), `SpawnPlan.timeout_ms`(:283), 해석(:1076-1080), 마감과 첫 대기의 timeout(:1327, :1340-1344), 마감이 먼저 오는 분기(:1376-1379), `outcome="timeout"`(:1421-1423), post-kill drain(:1407-1416, 마감 분기에서만 도달) |
| `A/rpc_channel.py` | 해석(:313-317), 매개변수(:576, :602, :698), 남은 예산(:709-711), `TimeoutError`를 timeout으로 바꾸는 부분(:723-724) |
| `A/batch.py` | `MAX_BATCH_WALL_MS`, `KILL_LEG_RESERVE_MS`, `_BATCH_BUDGET_EXHAUSTED`, `_Batch.deadline`, 멤버 시계(:471-496), `_kill_leg_reserve_ms` |
| `A/runtime.py` | `spawn`(:607→:681)은 Protocol 호환을 위해 인자를 받되 넘기지 않는다(D6). `spawn_granted`(:703→:762)와 `_run`(:880→:997)에서는 지운다. |
| `A/extension.py` | :1354 |

`wall_ms` 측정은 남긴다. 비평이 확인한 바로는 `_Batch.deadline`은 멤버 시계에만 쓰인다.

**D4. 작업 마감에서 상한을 빌려 쓰던 대기에 각자 상한을 준다.**
- **EOF 뒤 종료 대기**(`A/print_channel.py:1358-1370`).
  - 새 상수 `POST_EOF_EXIT_BOUND_SECONDS = 30.0`을 고정 상한으로 쓴다. 상한을 넘기면 지금처럼 reap한다.
  - 이미 끝난 자식이 판정에서 실패로 바뀌지 않게 한다. 채널은 이 경우 `lingered=True`를 넘긴다. `build_result`는 다음 두 조건이 모두 참이면 ok로 둔다:
    - `saw_agent_end`가 있다.
    - `stop_reason`이 error·aborted가 아니다.

    결과에는 "the agent finished but did not exit within 30 s; it was stopped"라는 note를 붙인다. 위 조건이 하나라도 거짓이면 `error`로 판정하고, 이유는 D10의 lingering 문장이다.
  - 근거: 자식은 프로세스가 끝날 때 stdio를 닫는다. MCP·확장 정리는 EOF 전에 일어나 메인 대기 안에서 끝난다.
- **RPC 명령 응답:** 새 상수 `RPC_COMMAND_TIMEOUT_MS = 180_000`을 쓴다. real-child pin과 같은 값이다. 비워 두면 30초가 되는데, ADR-0201:563이 cold boot ~25초를 이유로 거부한 값이다.
- **RPC 턴 대기:**
  - `RpcClient.prompt_and_wait`에 keyword-only `unbounded: bool = False`를 더하고, `True`면 `_await_terminator(done, None, …)`로 기다린다. `_await_terminator`의 타입은 `float | None`으로 바꾼다.
  - 기본값은 pi parity(None·0 → 60초)를 그대로 둔다.
  - 자식이 죽거나 호출자가 취소하면 대기는 지금처럼 끝난다.
- **배치 세마포어**(`A/batch.py:468`): 앞선 멤버를 기다리는 것이 의미이므로 상한을 두지 않는다.

**D5. 작업 시간의 상한은 사람이다. 사람이 실제로 끊을 수 있어야 한다.**
- **TUI Esc:** `_safe_abort` → `harness.abort()` → `turn_task.cancel()` → `_eager_abort`. 비평이 확인했다.
- **`-p`:** SIGINT는 `asyncio.run`이 메인 태스크를 취소한다. SIGTERM·SIGHUP은 print_mode가 처리한다. 비평이 확인했다.
- **새로 막는 구멍 두 곳.** 지금까지는 10분 상한이 가리고 있었다.
  - **D15. `/agents run`을 Esc로 취소할 수 있게 한다.**
    - 지금은 핸들러가 REPL 루프 안에서 직접 await된다(`C/tui/shell.py:4131`). Esc는 `_running`일 때만 동작하고(`C/tui/chrome.py:945`), `set_running(True)`은 `harness.prompt`만 감싼다(:4293). 그래서 멈춘 `/agents run`은 TUI를 붙잡는다.
    - `CommandContext`에 셸이 주입하는 `run_cancellable(coro)`를 둔다. 이 함수는 task를 만들고 `set_running(True)`를 켠 뒤, 인터럽트를 harness abort가 아니라 이 task의 cancel로 보낸다. 끝나면 원래대로 되돌린다.
    - `/agents run`만 이것을 쓴다(`C/tui/commands.py:1280`). 취소되면 "stopped" 결과를 출력한다.
  - **D16. TUI의 SIGTERM·SIGHUP 핸들러(`C/tui/shell.py:2217-2224`)가 실행 중인 턴도 abort한다.** 지금은 EOF를 요청하고 chrome을 닫기만 한다. 그러는 동안 루프는 `await harness.prompt`에 있어서, 위임이 끝날 때까지 프로세스가 남는다.
- **설명 바꾸기:** `A/batch.py:97-99`와 ADR-0199:1310은 "마감이 사용자가 묶이는 유일한 상한"이라고 적고 있다. 이것을 위 사실로 바꾼다.
- **RPC `agents/run`:** 취소할 수 있지만(`C/rpc/control.py:108`), 도는 동안 mutation lock을 쥔다(ADR-0275 §2). ADR-0276에 이 사실을 적는다.

**D6. Protocol `SubagentRuntime.spawn(timeout_ms=None)`(`C/subagent_contract.py:295`)은 받되 무시한다.**
- deprecated로 표시하고 `CONTRACT_VERSION`은 유지한다. 이 인자는 `T/agents/test_subagent_contract.py:180`이 고정하고 있다.

**D7. `"timeout"` outcome은 새로 만들지 않는다.**
- 옛 기록을 읽어야 하므로 다음은 유지한다: literal(`C/subagent_contract.py:67`), `CUT_BY_THE_PARENT`(`A/child_session.py:273-275`), sanitizer 분기, 렌더러.

## 2. (B) 멈추거나 실패한 자식의 결과

**D8. `SubagentResult`에 기본값 필드를 맨 뒤에 추가한다.** 추가만 하므로 `CONTRACT_VERSION`은 유지한다.

| 필드 | 내용 |
|---|---|
| `started: bool = False` | 채널이 자식을 실제로 띄웠는지. `_run`이 channel 호출 뒤에 True로 바꾼다. 거절(`_error_result`)·decline·드레인은 False다(D18). |
| `reason: str \| None = None` | D10 |
| `session_id: str \| None = None` | `_run`에서 `channel.run` 직후(:1033, `_settled_records` 앞)에 `dataclasses.replace`로 `receipt.child.session_id`를 넣는다. |
| `session_path: str \| None = None` | 호스트와 UI용이다. **모델이 보는 텍스트에는 쓰지 않는다**(ADR-0243:315, `A/envelope.py:46-49`의 "경로를 쓰지 않는다" 규칙). |
| `changed_files: tuple[str, ...] = ()` | 아래 수집 규칙 |
| `unconfirmed_files: tuple[str, ...] = ()` | 아래 수집 규칙 |
| `files_overflow: int = 0` | 아래 수집 규칙 |

- **쓰기 도구:** `edit`, `write`, 그리고 `C/builtin/guardrail.py:47` `_WRITE_TOOLS`의 `create_file`·`write_file`이다. 목록은 import해서 공유한다.
- **수집:** 리듀서(`A/stream.py`)에서 trail과 따로 모은다.
  - `tool_execution_start`의 원본 `args["path"]` 또는 `file_path`를 `call_id`와 함께 기록한다.
  - 경로는 `_strip_control`로 정리한다. 이 함수는 줄바꿈도 접으므로 위조를 막는다.
  - 경로당 512자, 서로 다른 경로는 64개까지 모은다. 넘치면 `files_overflow`로 센다.
  - 끝 이벤트가 `is_error=False`이면 changed, 끝 이벤트가 없으면 unconfirmed, `is_error=True`이면 제외한다. 같은 경로가 둘 다면 changed가 이긴다.
- **경로 기준:** `_run`이 `child_cwd`를 기준으로 경로를 해석한 뒤 **부모 cwd 기준 상대 경로**로 바꾼다. 부모 cwd 밖의 절대 경로는 그대로 둔다.
- **bash로 바꾼 파일은 보이지 않는다.** 결과에 이 한계를 한 줄로 적는다.

**D9. 실패·중단일 때 `_select_summary`의 순서를 바꾼다.**
- 바뀐 순서: `state.summary`(부분 답변) → `final_error`(D17) → 정리된 stderr → `NO_OUTPUT`. 성공일 때 순서는 그대로다.
- 부분 답변을 앞에 두는 대신 진단은 `error`로 옮긴다. 이것은 D17이 보장한다. rev 1의 "이미 error로 간다"는 사실이 아니었다(비평 3).
- docstring :278-282를 고친다.
- `no_terminator` 게이트(:441-447)는 이미 있으므로 회귀 테스트만 둔다.

**D17. 오류를 다시 정한다.**
- **`final_error`:** 리듀서에 `state.final_error`를 둔다. 마지막 assistant `message_end`의 `stop_reason == "error"`일 때만 그 오류를 담고, assistant 메시지가 올 때마다 지운다. 재시도로 회복한 429 같은 지난 턴의 오류는 이유나 note가 되지 않는다. 지난 오류(`error_message`)는 `details`에만 남긴다.
- **`build_result`의 `resolved_error`:** 실패이고 요약이 stderr가 아닐 때, 첫 번째로 값이 있는 것을 쓴다:
  1. 인자로 받은 `error`
  2. `final_error`
  3. `stderr_clean`
  4. 종료 설명: "exited with code N", 또는 음수면 "killed by signal SIGKILL"
  5. `STREAM_ENDED_EARLY`
- 단일 모드 `Error:` note에는 4 KiB 상한을 둔다. RPC `RpcServerExited`가 stderr 64 KiB를 통째로 싣기 때문이다.

**D10. `reason`은 `build_result`가 만든다. 실패·중단일 때만 만든다.**

| 경우 | reason |
|---|---|
| `aborted`이고 `row.stopped` | "stopped by the session (stop, /new, /resume, /fork or quit)" |
| `aborted`이고 취소 경로(D14) | "the turn was cancelled (Esc)" — D14가 직접 넣는다 |
| `aborted`이고 자식 자신의 stop reason(`A/envelope.py:456-457`) | "the agent's own run was aborted" |
| `error` | `resolved_error`의 첫 줄, 300자 상한 |
| lingering 실패(D4) | "the agent closed its output but did not exit within 30 s" |

**D11. 모델이 보는 텍스트(`render_subagent_result`). `started`이고 실패·중단일 때만 이 형태를 쓴다.**
- 성공 결과와 미시작 결과는 한 바이트도 바꾸지 않는다(D18).

```
The delegated agent did not finish: <reason>
Do not delegate the same task again from scratch — it already did the work below. Check the changed files and its tool calls first.

Partial result:
<summary | "(it wrote no text before it stopped — see its tool calls)">

Error: <resolved_error, 4 KiB 상한 — 요약이 이미 말한 내용이면 생략>

Tool calls (<n>):
<render_tool_trail, 4 KiB, … N more>

Files changed:
  a/b.py
  c.py
Unconfirmed (stopped mid-write):
  d.py
(+N more files; files changed through bash are not listed)

Session: <session_id>
<도구 미부여·초과 줄 note — 지금과 같음>
[agent … footer]
```

- 파일 목록은 한 줄에 하나, 합쳐서 2 KiB 상한이고 넘치면 "+N more"로 적는다.
- 전체 상한: 요약(output_cap) + 오류 4 KiB + trail 4 KiB + 파일 2 KiB + 머리·꼬리.
- 재시도 문구는 0단계용이다. #610이 resume 안내로 바꾼다.

**D12. 병렬 결과(`A/aggregate.py::_member_block`)는 `started`이고 실패·중단인 멤버만 바꾼다.**
- 멤버 예산을 이렇게 나눈다. 넘치는 항목은 "+N"으로 줄인다.

| 항목 | 상한 |
|---|---|
| 이유 + 세션 id | 300 B |
| Error note | 예산의 1/4. 지금의 budget//2에서 줄인다. |
| 마지막 도구 호출 5개 | 예산의 1/8 |
| 파일 | 예산의 1/8 |
| 요약 | 나머지 |

- 전체는 `BATCH_OUTPUT_BUDGET_BYTES`(64 KiB, :63)를 넘지 않는다.
- 미시작 멤버(:138-142)와 성공 멤버는 바꾸지 않는다.
- 체인은 첫 실패에서 멈추므로(`A/batch.py:397-399`) `{previous}`에는 성공 요약만 간다. 바꿀 것이 없다(비평 12).

**D14. Esc로 취소된 위임도 모델에게 보고한다.** rev 1의 가장 큰 구멍이었다(비평 1).
- **지금:** 취소는 `_stream_and_reap` → `_run` → `_execute`로 그대로 올라간다. 결과는 만들어지지 않는다. 다음 턴에 provider 변환이 고아 tool_use에 "No result provided"를 채운다(`aelix_ai/providers/_transform_messages.py:306`).
- **어디에 담나:** harness의 `abort()`는 steer·follow-up 큐만 비우고 **다음 턴 큐(`_next_turn_queue`)는 비우지 않는다**(`H/core.py` abort; 다음 `prompt()`가 :1482에서 꺼내 그 턴 앞에 붙인다). 여기에 보고를 넣는다.
- **방법:**
  1. `_run`의 `finally`는 이미 취소일 때 실시간 스트림으로 settle 기록을 만든다(`_unsettled_records`). 같은 자리에서 `build_result(outcome="aborted", …)`로 envelope를 만들고 D10의 취소 reason과 세션 id를 넣는다. 이 envelope를 확장이 넘긴 수집기(`record`에 붙인 tool_call_id 키)에 남긴다. await는 하지 않는다.
  2. `_execute`의 `except asyncio.CancelledError`는 수집기에 envelope가 하나 이상 있으면 D11 형태로 렌더링한다. 배치면 멤버별 D12 형태다. 앞에는 다음 머리말을 붙인다:

     "[aelix system report — not user input] The `agent` call you made was stopped when the turn was cancelled. What it had done:"

     이것을 `api.send_message(text)`로 다음 턴 큐에 넣고(`trigger_turn=False`, 동기) 다시 raise한다.
  3. 시작한 자식이 없으면 아무것도 넣지 않는다.
- **한계:**
  - `-p`는 다음 턴이 없으므로 의미가 없다. 해도 없다.
  - 다음 턴 큐는 메모리에만 있다. 세션을 닫았다가 `--continue`로 열면 이 보고는 없다. 대신 settle 기록이 세션에 남아 있고, #610에서 resume이 이 기록을 쓴다. 이 한계를 ADR에 적는다.

**D18. `started == False`인 결과는 지금의 렌더링을 그대로 쓴다.**
- 대상: 거절(드레인, 동시 자식 상한, 예산), decline, 시작하지 못한 배치 멤버.
- 이런 결과에 "이미 일을 했다"는 문구가 붙으면 틀린 말이다(비평 5).
- `session_id is None`은 이 판별에 쓸 수 없다. `--no-session` 부모도 None이기 때문이다.

## 6. 위험

- **메인 대기에는 상한이 없다.** 의도한 것이다. 사람이 끊을 경로(Esc, 신호, `/agents run`)는 L2·L3·L6·L7로 확인한다.
- **D15·D16은 TUI 변경이다.** 이 저장소에서 가장 자주 깨진 표면이므로 직접 띄워서 확인한다. B6도 `tui/shell.py`를 건드리지만 아직 시작하지 않았으므로, #604가 먼저 들어가면 충돌이 없다.
- **Windows:** 30 s 상한을 둔다. 테스트 타이밍은 상대 비교를 쓰지 않는다.
- **D14의 취소 경로:** await 없이 동기로만 한다. 취소된 태스크 안에서 await하면 #351 계열 문제가 생긴다.
