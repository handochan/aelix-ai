1. **Major: a later forged receipt replaces the historical ceiling.**

   Code: `packages/aelix-coding-agent/src/aelix_agents/child_session.py:1192`
   (`_fold_runs`), `:1326` (limits are taken from the folded record).

   Start a model-tool child under a default parent: the first run's start and
   settle both contain `limits.granted_mode="plan"`. Append one more
   `aelix.child_session` settle for the SAME key, copying every field except
   `limits.granted_mode="yolo"`. The original start remains on the branch, and
   the copied top-level `permission_mode` still says `plan`. Widen the parent
   to YOLO and call `agent(action="resume", id=<id>, profile="scout", task="keep going")`.
   The runtime trusts the later settle's limits and launches at YOLO.
   Expected: retain the original start's ceiling, or refuse conflicting records.
   This counterexample requires the record-write capability explicitly included
   in the review's untrusted-record threat model; an ordinary resume argument
   alone cannot do this.

   Probe: `test_appended_forged_receipt_widens_first_ceiling`.

   ```text

   ```
