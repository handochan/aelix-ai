## §0 What is true today (details and file:symbol evidence in the map and the critique §V)

- A child runs `python -m aelix_coding_agent --mode json -p --no-session … "Task: <task>"` (print channel; `--no-session`
  comes from product-core `agents/resolver.py` `profile_to_argv`, oneshot prefix) or `--mode rpc … --no-session` (rpc
  channel `build_rpc_child_argv`; no production caller — #123). Nothing forwards `--session-dir`; the env var
  `AELIX_CODING_AGENT_SESSION_DIR` *is* inherited.
- The parent persists only the toolResult **text** (capped summary + a usage footer whose fields can be dropped for
  width). `loop._to_tool_result_message` drops `details` (#168); no spawn id, no usage as data, no child transcript reaches
  disk. A Ctrl+C-cancelled delegation writes nothing; `/agents run` writes nothing.
- Keys: `spawn_id = "sub-<12hex>"` (`runtime._new_id`, minted inside `_run`'s await-free admission block, 48 random bits);
  `tool_call_id` is one per `agent` call and not unique on the Google adapter across restarts; batch index / chain step
  exist only in `batch._member`.
- `_run` order today: drain gate → `_admit_live` → budget → `spawn_id` → registry insert → `SpawnPlan` (frozen) → first
  `_publish` → `try: channel.run` / `finally: pop row + terminal publish`. The admission block is await-free by design and
  AST-pinned (`tests/agents_ext/test_batch_executor.py`).
- Stats (`harness/_session_stats.py` `aggregate_session_stats` over `_state.messages`) never see child spend and would not
  see `custom` entries. `SubagentUsage.tokens` is a context LEVEL; `SessionStatsTokens.total` is a FLOW. `SubagentUsage`
  has no `cost_known`; `print_channel.apply_cost_fallback` returns `None` on every path.
- Compaction never cuts at a `custom` entry and never separates a `toolResult` from its call
  (`session/compaction.py` `find_valid_cut_points`), so records between a tool call and its result are safe.
- `/agents show` renders `profile_to_flags` only (`tui/commands.py` `_render_agent_profile`) — not `profile_to_argv`. The
  docstrings that say otherwise (`resolver.py` "P1 uses this ONLY for /agents show", `build_child_argv` "the same call the
  /agents show dry-run renders") are stale.
- Pi records no child session file either (its example spawns `--no-session`); it keeps the child transcript in the
  persisted tool `details` and, since #6671, sums tool-reported `usage` over every entry of the file. Pi pico3 models a
  child as an owned conversation linked from `details` — ownership, not fork lineage.

## §A Decisions

### A.1 Where a child's session lives

- Next to its parent, in a directory named after the parent file: parent `<dir>/<stem>.jsonl` → children
  `<dir>/<stem>/<spawn_id>.jsonl` (`sub-<12hex>.jsonl`, 22 characters). The directory is derived from
  `os.path.abspath(parent_path)` **in the parent**; every path in every record is absolute (a parent opened with a relative
  `--session` would otherwise break every child that runs in a subdirectory). The child name is the spawn id, not
  `<ts>_<uuid>`: the header already carries the timestamp and id, pickers never see these names, and the short name keeps a
  111-character cwd under Windows' 260-character `MAX_PATH` including the `.tmp` staging name (critique item 5 table).
- Pickers never see it: `JsonlSessionRepo.list` / `find_most_recent` take only `*.jsonl` directly in a bucket and skip
  directories; `_list_session_dirs` returns top-level buckets only (verified, probe P.2 [1]).
- Edge placements (critique item 16): strip only a `.jsonl` suffix, otherwise append `.children`; when the parent file sits
  **directly in the sessions root** (its `<stem>/` would become a top-level bucket that the global `list()` scans), the
  child runs `--no-session` and the record says `child: null, error: "parent outside a bucket"`.
- A parent with no session file (`--no-session`, `MemorySessionStorage`, or a session whose metadata has no `path`) spawns
  children with `--no-session` as today; its records still go to its in-memory session (stats for the process lifetime).
- Files 0600, directory 0700 (the #294 `LocalFileSystem`). No retention policy — sessions have none today. Every
  delegation now keeps a full child transcript (up to 12 per prompt); deleting a parent by hand leaves its directory.

### A.2 The parent allocates the child's session before spawning it

- In `_run`, inside the `try` (§A.3 order): create the child file with
  `JsonlSessionStorage.create(fs, path, cwd=<child cwd>, session_id=<new uuid4>, entries=[origin])` — one atomic publish
  (ADR-0242), so an early-exit child still leaves a findable header + origin, and the parent knows the path before anything
  runs. Header `parentSession` stays unset (that is fork lineage).
- `origin` = `CustomEntry(id=<new>, parent_id=None, customType="aelix.child_origin", data={v:1, key:<spawn_id>,
  parent:{session_id, path}, tool_call_id, index, mode, profile, permission_mode:<.value>, aelix_version})`.
  **`parent_id` must be `None`** — the child's startup `get_branch()` walks to the root.
- The child runs with `--session <abs path>` instead of `--no-session`. Verified path: `_resolve_session_metadata` treats a
  path-like argument as a file → `load_jsonl_session_metadata` → `repo.open(meta, cwd_override=cwd)` (in-memory override;
  a child cwd ≠ header cwd is harmless); the session is built before the model/key gate, so an early-exit child still opened
  it; `parse_args` accepts the argv with no unknown flags (probe P.5). The rpc channel swaps its own `--no-session` for the
  same `--session <path>`.
- Allocation failure (`OSError`, a too-long path, a root-placed parent) never fails the delegation: the child runs
  `--no-session` and the records say `child: null` + a short error.

### A.3 What the parent session records, and the exact order in `_run`

**Which spawns:** records exist for **admitted** spawns only — those that got a registry row. Hook refusals and human
declines on the model door, `/agents run` declines, in-`_run` refusals (drain, live cap, budget), batch-wall and
`TaskTooLarge` refusals and chain NOT-RUN steps get no record: they spent nothing, and the toolResult text already persists
them.

**Records** (ADR-0242: one record = one `aelix.` `CustomEntry` line, everything inside `data`), written by the extension
band only:

- `aelix.child_session` **start** — `{v:1, key:<spawn_id>, phase:"start", tool_call_id, index, mode, profile,
  task_preview (first 200 chars), child:{session_id, path, rel} | null, requested_model, permission_mode, aelix_version}`.
- `aelix.usage` **pending** — `{v:1, key, state:"pending"}`, right after the start and **before** the child can spend.
- `aelix.child_session` **settle** — start's identity fields + `status` (`ok` / `error` / `timeout` / `aborted` /
  `cancelled`), `model` and `provider` from the envelope (what actually ran), `usage:{input, output, cache_read,
  cache_write, cost}`, `cost_known`, `context_tokens` (the level), `turns`, `elapsed_ms`, `exit_code`, `stop_reason`,
  `truncated`, `summary_bytes`, `details_bytes`, `error` (short).
- `aelix.usage` **final** — `{v:1, key, state:"final", usage:{input, output, cache_read, cache_write, cost}, cost_known}`.

| Exit path | Writer | Records |
| --- | --- | --- |
| ok / error / timeout / aborted / exec failure | `_run` `try` | start, pending, settle, final |
| raised before or inside `channel.run` (e.g. `write_prompt_file`) | `_run` `finally` | start, pending, settle (`error`), final |
| cancel (Ctrl+C, `stop_all`) | `_run` `finally` | start, pending, settle (`cancelled`), final |
| process killed mid-run | — | start, pending (stays unknown) |
| not admitted | — | none |

A reader folds by `key`, last wins. A `start` with no `settle` means **interrupted / outcome unknown** (docs/05 §5 stage 2);
a `pending` with no `final` means **unconfirmed spend**.

**`_run` order** (critique item 3; the admission block stays await-free and the AST gate stays green):

1. Admission block, unchanged (drain, `_admit_live`, budget, `spawn_id`, registry insert), then `SpawnPlan` and the first
   `_publish` exactly as today (`batch._member`'s `admitted` flag depends on that first publish).
2. `try:` capture the parent session **once** (§A.3a) → allocate the child file (§A.2) → append start + pending →
   `plan = dataclasses.replace(plan, session_path=…)` → `channel.run` → append settle + final → `settled = True`.
3. `finally:` if not `settled`, build a settle from `child.stream` (`cancelled` for `CancelledError`, `error` with the
   exception text otherwise), after calling `apply_cost_fallback(child.stream, …)` so cancelled spend is priced, and append
   settle + final under `asyncio.shield`; then pop the row and publish the terminal snapshot as today.

No per-runtime lock: `JsonlSessionStorage` already serializes appends, `LocalFileSystem` never yields inside a write, and a
lock adds a suspension point where a second cancel lost both settles in the critic's probe (P.3 case C vs E). Every record
append is wrapped so a storage failure is logged (DEBUG) and never fails or changes the delegation's result.

**A.3a — the parent session is captured once per spawn.** `AgentsExtension` gains `session: Callable[[], Session | None] |
None`, wired in `cli/entry.py` to the runtime host's **current** harness session through the same late-bound pattern the
other `AgentsExtension` arguments use. `_run` reads it once, at step 2; every record of that spawn goes to that captured
object and it is never re-read. `ctx.session_manager.get_session()` is only a fallback, read under
`suppress(ExtensionError)`. This keeps a settle that arrives after `/new` / `/resume` / quit (`stop_all` then invalidate)
in the session that ran the child, and makes `/agents run` record even before any hook fired.

**A.3b — `cost_known`.** `apply_cost_fallback` returns `bool` (priced). `cost_known` = usage complete **and** ((any
`message_end` carried a provider cost) or (the fallback priced it) or (every token counter is zero)), where usage complete =
the child's run reached its own `agent_end`, or never began (`agent_start`). **Amended after the Codex review of the
implementation (codex-1):** without the completeness clause, a Ctrl+C before any usage arrived recorded zeros as a
confirmed `$0`; a run cut short (cancel, timeout, `stop_all`, mid-turn death) is now always a floor. A cancelled or errored
settle still calls the fallback first. **Refined after a second Codex review of the lead's delta:** completeness is status-aware — a run the parent cut (`cancelled` / `aborted` / `timeout`) is never complete once it began, even with an `agent_end` (the child's abort path emits one without a `message_end`); any other run is complete only when its latest run closed (`_StreamState.run_open`, last-event-wins, so an auto-retry cut mid-way stays open).

**A.3c — plumbing.** A private `record: SpawnRecordMeta(tool_call_id, mode, index) | None` keyword on `spawn_granted` and
`run_batch` carries the three into `_run`. The `SubagentRuntime` Protocol's `spawn` is untouched (S2,
`test_protocol_has_no_consent_parameter`). `/agents run` passes `None` → nulls.

### A.4 Stats count child spend exactly once (kernel, no delegation vocabulary)

- `AgentHarness.get_session_stats` reads the branch once (it already does for `_cost_is_complete` — share the read),
  collects `custom` entries with `customType == "aelix.usage"`, and passes their `data` to `aggregate_session_stats`.
- The fold (kernel): group by `key`, last line wins. A `final` adds `input/output/cache_read/cache_write` to `tokens` (and
  `total`) and `cost` to `cost`; `cost_known: false` clears `SessionStats.cost_known`. A key whose last line is `pending`
  adds nothing and clears `cost_known` (unconfirmed spend renders as `≥ $X`, which `format_session_cost` already does).
  Lines without a `key` count once each. Non-finite or negative numbers are ignored and clear `cost_known`. A context level
  is never summed.
- `SessionStats` gains Aelix-only `tool_usage: ToolUsage(tokens: SessionStatsTokens, cost: float, cost_known: bool, runs:
  int, pending: int)`, off the RPC wire (`rpc_mode._session_stats_to_dict` enumerates keys). The pi_parity pin
  `tests/pi_parity/test_phase_4_10_strict_superset.py` (Aelix-additive fields set) moves deliberately to
  `{"cost_known", "tool_usage"}`.
- Semantics, stated exactly: the ledger is read over the **whole root→leaf path**, including entries before the latest
  compaction, while parent messages are the post-compaction `_state.messages`; `/tree` moves stop counting records that are
  off the path, like messages; a fork copies the records on its branch. Divergence from pi (which sums every entry of the
  file, all branches) is recorded under ADR-0235. Residual under-counts: child compaction calls, null-usage retry attempts,
  an in-flight turn at timeout.
- `aggregate.roll_up_usage` keeps only its display role (the `[total]` line, `tokens` = max); a test pins it equal to the
  kernel fold on the flows.
- Consumers: footer, `/cost`, `/session`, `/stats`, History (`stats-history.jsonl`) and RPC all read `get_session_stats`,
  so all get the merged totals; `/cost` and the `/stats` session tab show one extra line for `tool_usage` (TUI live check).
  History totals rise from #199 onward — CHANGELOG says so.

### A.5 The truncation marker tells the truth

"Full output preserved in tool details" is false after the call. With a child file: `… The full output is recorded in the
delegated session.` — no path (keeps home directories and usernames out of the model's context); the marker also flows into
a chain's `{previous}`. Without a child file: no claim. The exact wording is pinned in a test.

### A.6 Both channels, both doors, the dry run

Print (production) and rpc (stub-tested only, #123 — say so) take `plan.session_path`. `profile_to_argv(...,
session_path=None)` emits `--session <p>` or `--no-session`. The model door (single / parallel / chain) and `/agents run`
both go through `_run`, so both record. `/agents show` keeps rendering the profile flags only; `--session`, like
`--permission-mode`, the trust flags and `--no-agents`, is spawn-time state and is not shown. Fix the two stale docstrings
(`resolver.py`, `print_channel.build_child_argv`).

### A.7 Fork, tree moves, import, delete

`/fork` copies the records on the branch; both parents then point at the same child files (absolute `path` + `rel`
(`<stem>/<name>`, relative to the parent file's directory) + `session_id`; readers try `rel`, then `path`). `/tree` moves
leave records off-path. `import_from_jsonl` copies only the parent file; links may dangle — documented. Nothing deletes
sessions today; nothing here does either.

### A.8 What stays out of the parent's context

Nothing new enters it: the records are `custom` entries; the only content change is the marker text (§A.5). Live
`ToolResult.details` stays the uncapped summary string that `_join_details` and the tool card consume; the persisted link
is the record (details are never persisted — #168). Live `ToolExecutionEndEvent` consumers get nothing new here; the future
web viewer reads the records.

### A.9 `output_cap` — **DECIDED by the owner 2026-09-19: (c)** (shared per-call budget)

Today 51,200 bytes per child and no per-call cap. Worst case 8 × 51,200 → a 410 KB toolResult ≈ 102,579 estimated tokens —
92% of gpt-4o's 111,616-token compaction threshold, 56% of claude-haiku-4.5's; a toolResult is never a cut point, so that
turn cannot shed it. Typical reports are far smaller (the owner's live check: 129 characters total; bundled profiles ask
for "a paragraph or two"). Options: (a) keep; (b) lower the per-child default to 16 KiB; (c) keep 51,200 for single mode and
give a parallel/chain call one shared rendered budget of 64 KiB split evenly across members, applied in
`aggregate.render_batch_result` (re-capped with `envelope.cap_summary`), so the chain `{previous}` hand-off keeps each
step's own capped summary; the constant lives in `aelix_agents` (band gates forbid caps in product-core). Under (c) 8
members get 8,192 bytes each (≈2,048 tokens); the worst case per call drops ≈6.3×; the full text is in each child file.

### A.10 A child-session viewer — **DECIDED by the owner 2026-09-19: follow-up issue** (not in #199)

Recording alone satisfies "자식 세션이 기록될 것". A read-only view already exists: `aelix --export <child.jsonl>` renders
HTML and writes nothing to the session — the ADR and CHANGELOG point there. A TUI surface (`/agents runs`) is its own
issue with its own live check.

### A.11 A child file is a record, not a resumable identity

`aelix --session <child.jsonl>` would run it as an ordinary top-level session without the child's clamp (permission mode,
tool narrowing, `--no-agents`, depth — all argv/env state). `_build_session` (product-core `cli/entry.py`) prints a
one-line stderr warning when the opened file's first entry is `aelix.child_origin`, naming `aelix --export` as the
read-only way to look at it. Not a refusal.

## §D Live verification (rules 9 and 10) — the lead runs these, not only the implementer

   pending).
3. Ctrl+C mid-delegation: settle `cancelled`, pending → final, `--continue` resumes the parent.
4. Quit mid-delegation: the settle lands in the parent.
5. `/agents run` right after `/new`: recorded.
6. A `--no-session` parent with `AELIX_CODING_AGENT_SESSION_DIR` set: no file anywhere.
7. An early-exit child (a profile with a bad `--model`): the child file holds header + origin, settle `error`.
