## #604 phase 0: delegation-timeout survey of `fix/604-no-delegation-timeout` @ 7e76f925

This was read-only. I ran no tests and changed no files.

Path prefixes used below:
- `A/` = `packages/aelix-coding-agent/src/aelix_agents/`
- `C/` = `packages/aelix-coding-agent/src/aelix_coding_agent/`
- `T/` = `tests/`

Three findings matter most for the design:
- **The RPC client brings its own deadlines back.** In `prompt_and_wait`, `None` or `0` becomes 60 s (`C/rpc/rpc_client.py:1014`). An unset send timeout becomes 30 s (`:390-393`). If the channel simply stops passing a value, every RPC delegation will cut off at 60 s.
- **The tool trail and the child session path never reach the model in single or parallel mode.** Today only chain mode and RPC `run_agent` carry the trail.
- **On a failed or stopped child, stderr comes before the partial answer.** Leftover stderr replaces the child's partial text.

### 2. Waits whose bound comes from the deadline, with a proposed bound each
1. **Post-EOF exit wait**, `A/print_channel.py:1358-1370`: `max(deadline-now, POST_EOF_EXIT_GRACE_SECONDS)`.
   - Proposal: `POST_EOF_EXIT_GRACE_SECONDS` alone. Its docstring (:160-176) already calls it the floor for child-watcher latency.
   - When it expires the child is reaped (:1368-1370) and `build_result` reports `error` from the signal exit code. It needs a reason string, since `timeout` goes away.
2. **RPC command response**, `A/rpc_channel.py:479`.
   - Proposal: its own constant — either 600_000 (today's effective default) or 180_000 (what the real-child pins use, `T/agents/test_rpc_sprint_pins.py:275,390`).
   - Leaving it unset gives 30 s, which ADR-0201:563 rejects because a cold child takes about 25 s to boot.
   - The child-death leg still ends the wait early (`C/rpc/rpc_client.py:1070-1078`).
3. **RPC turn wait**, `A/rpc_channel.py:709-722`.
   - This one is the work itself and should become unbounded, but today it cannot be expressed: `prompt_and_wait` turns `None` and `0` into 60 s (`C/rpc/rpc_client.py:1014`).
   - Proposal: call `prompt()` and then `_await_terminator(done, None, …)`. `asyncio.wait(timeout=None)` (:1074-1078) still ends when the child dies or the caller cancels.
4. **Batch member clock**, `A/batch.py:471-496`: delete; no replacement bound.
5. **Post-kill drain**, `A/print_channel.py:1407-1416`: it has its own bound but is only reached when `timed_out and not pumps.done()`, i.e. through the deadline-first branch. It becomes dead code once that branch is gone (pumps are already done on the post-EOF path).

### 3. Waits that hang once the deadline is gone
- **`A/print_channel.py:1340-1344`** hangs while the child neither exits nor closes fd1/fd2 — a stalled provider stream, or a tool or extension blocking inside the child. A grandchild holding the pipes cannot cause this, because the `exited` leg fires.
  - What is left to end it: cancellation (:1379-1386), `stop`, `stop_all`.
  - `A/batch.py:97-99` documents the deadline as "the only bound on how long the user is locked out": there is no mid-turn stop overlay, and Enter goes to `steer()`.
  - Check that Esc/Ctrl+C actually cancels a running `agent` call. In `-p` mode nothing can end it.
- **RPC turn wait** (after 2.3): hangs under the same condition.
- **RPC `prompt` acknowledgement**, if it were made `None`: hangs on a child that is alive but never reads stdin.
- **Post-EOF wait**, if `None` replaced the `max(...)`: hangs on a child that closed its stdio and then wedged (:172-176).
- **Batch semaphore**, `A/batch.py:468`: waits as long as the running members do.

### 4. How the result reaches the parent model
- **`_select_summary`, `A/envelope.py:238-292`.** Order when the run failed: `error_message` (:288) → sanitized stderr (:290) → `state.summary` (:292) → `NO_OUTPUT`.
  - Any stderr line that survives sanitizing replaces the partial answer on `aborted` and `error`.
  - The sanitizer only runs for `aborted` and `timeout` (:93-105) and only strips traceback lines (:83-90).
  - The docstring at :278-282 says that tail is "usually" empty, but :64-70 records that a real child's SIGTERM stderr is "Request aborted", which the filter keeps. `C/modes/print_mode.py:34-41` says JSON mode writes nothing to stderr on the exhausted-retry path; I did not verify the SIGTERM path in JSON mode.
  - `error_message` is the last non-empty one (`A/stream.py:617`), so an error from an earlier, retried turn also displaces the answer.
- **`build_result`, :388-529.** A non-ok outcome is kept as the status (:455-456); `stop_reason=="aborted"` becomes `aborted` (:456-457). On `aborted` and `timeout` the error stays `None` unless the stream carried an `error_message` (:475-488), so **there is no reason sentence**.
- **`render_tool_trail`, :322-361.** One line per call, `name(args) ok|FAILED|(no result)`. Capped at 4096 bytes (:295) with a "… N more" line (:309, :356-358), and at 200 entries (`A/stream.py:308`).
- **`render_subagent_result`, `A/tool.py:847-884`.** What the model sees, in order:
  - the summary, or `(no output)`;
  - `Error: …` — not capped in single mode (:867-868);
  - notes on dropped tools and dropped lines;
  - the footer from `_usage_line` (:712): `[agent <profile> · <model> · <status> …]`. So the status comes **last**.
  - The **trail, session id/path and changed files are all absent**. `details` goes to `ToolResult.details`, which the model never sees.
- **Parallel rendering**, `A/aggregate.py:204-272`: `[i/N <status>] body` (:219), then `Error:` capped at half the member's budget, and no trail. The trail reaches a model only through chain `{previous}` (`A/batch.py:410`) and RPC `asdict`.
- **`SubagentResult`** (frozen), `C/subagent_contract.py:100-188`: id, profile, ok, status, summary, truncated, usage, error, exit_code, stop_reason, elapsed_ms, dropped_tools, details, dropped_lines, tool_trail, permission_mode, model, provider, output_recorded.
- **The `"timeout"` outcome.**
  - Produced at `A/print_channel.py:1423` and `A/rpc_channel.py:711,724`.
  - Declared in `SubagentOutcome` at `C/subagent_contract.py:67`. `SubagentStatus` (:74) is a TypedDict, not this literal.
  - Consumed by the sanitizer (`A/envelope.py:102`) and by `CUT_BY_THE_PARENT` in `A/child_session.py:273-275` (doc :38), which decides cost completeness.
  - `/agents run` (`C/tui/commands.py:1076`), the parallel renderer and `_usage_line` print the status without special-casing it. TUI, panel and progress use `SubagentState` (:66).
  - Keep `"timeout"` in the literal: settle records already on disk can contain it (ADR-0243).

### 5. Child session id and path
- `SpawnReceipt._allocate` (`A/child_session.py:418-472`) creates `ChildSessionFile(session_id, absolute path, rel)` (:220-233).
- `_run` opens the receipt (`A/runtime.py:1018`) and copies only the path into `plan.session_path` (:1019-1020).
- The channels reduce that to the boolean `output_recorded`. **Nothing in `SubagentResult` identifies the file**; the truncation marker only says the output is "recorded in the delegated session" (`A/envelope.py:51`).
- **Smallest change:** add defaulted `session_id` and `session_path` fields (additive, so no version bump). In `_run`, right after `channel.run` (:1033) and before `_settled_records` (:1037), copy them in with `dataclasses.replace` from `receipt.child`.
  - That one site covers both channels, both entry points, and batch members (they go through `spawn_granted` → `_run`).
  - Refusals stay `None`. RPC `run_agent` picks the fields up through `asdict` (`C/rpc/control.py:795-803`).

### 6. Tool-trail entries and changed files
- **Entry shape:** `ToolCall(name, args: str, failed: bool|None, call_id)`, `A/stream.py:344-358`.
  - Opened on `tool_execution_start` (:410-430); closed on the matching end event by `tool_call_id` with `failed=bool(is_error)` (:433-450).
- **What `args` keeps:** the first non-empty string among `path, file_path, command, pattern, query, url, cmd` (:324), otherwise scalar `k=v` pairs.
  - Control characters become spaces and the result is stripped (:361-376).
  - Clipped to 120 characters with "…" (:317, :404-407); the name is also clipped to 120 (:426).
- **Tools that write files:** `edit` (`C/tools/edit.py:217`, `path` at :68, :101) and `write` (`C/tools/write.py:104`, `path` at :41, :50). A wider set exists: `_WRITE_TOOLS` in `C/builtin/guardrail.py:47` also lists `create_file` and `write_file`. Files written through `bash` are invisible.
- **The trail cannot reliably give back file paths:**
  - paths over 120 characters are clipped;
  - leading and trailing whitespace is stripped;
  - entries past 200 are dropped;
  - the render is cut at 4 KiB;
  - the line format is ambiguous to parse.
- **Proposal:** collect `event["args"]["path"]` for writer tools in the reducer, into a separate bounded set. `failed is False` means changed; `None` means "maybe" (killed mid-tool). The paths are as the model wrote them, relative to the child's cwd.

### 7. Profile `timeout_ms` and warnings
- The key is parsed at `C/agents/profile.py:398`. An invalid value is an error, and an error drops the whole profile (:400). Decide whether `timeout_ms: -5` should still do that (`T/agents/test_profile_parse.py:303`).
- **Mechanism to reuse:** `_warn` (:284-289) creates a warning diagnostic. The precedent is the "unknown frontmatter key … (ignored)" warning (:311-315). The codes literal (:69-76) needs a new code, or reuse `unknown_field`.
- **Where warnings show today:**
  - `/agents list` (`C/tui/commands.py:700-720`, described there as "their ONLY surface");
  - RPC `agents/list` (`C/rpc/control.py:749`).
  - `resolve_profile` (`C/agents/discovery.py:353-370`) only escalates `missing_path`, so nothing warns at spawn time.
- **There is no warn-once facility** anywhere in `aelix_agents`. "Once" would need a module-level set of profile paths plus a log line or UI notice at spawn.

### 10. Other surprises
- **RPC errors carry the whole stderr.** The `RpcServerExited` message embeds the full stderr snapshot (`C/rpc/rpc_client.py:1125-1130`), up to 64 KiB (`A/print_channel.py:144`). It becomes `result.error`, and single mode prints it uncapped next to a summary that is itself stderr. That is the "diagnostics displace the partial" case on RPC `error`.
- **The partial answer is only the last finished message.** `state.summary` is set only at `message_end` (`A/stream.py:627`), so text still streaming when the child is killed is lost.
- **Stale docstring:** `_select_summary`'s docstring (:278-282) contradicts `envelope.py:64-70`.
- **The deadline was the documented user-lockout bound** (`A/batch.py:97-99`, ADR-0199:1310).
- **One print test pins the deadline itself:** :1048-1075 records the armed `asyncio.wait` timeout through a seam.
