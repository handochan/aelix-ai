## Things that looked wrong, surprising or ugly

1. **Esc leaves the child's `bash` command running.** The child's `sleep` outlived the child, reparented to PID 1, in L1 (both wires) and L2. Killing the child with SIGKILL (an extra run) left it too; SIGTERM did not. In the SIGKILL run the leftover `sleep 99` was still alive when the parent resumed the child; the resume was not refused. My drivers killed each leftover.
2. **The resume tool card wraps and drops the instruction.** It shows `● agent(action='resume', id='<uuid>',` and then `profile='writer', t…)` on a second line starting at column 0. The cut is made by the renderer: `_compact_args` in `tui/render.py` caps the arguments at 80 cells, and the 36-character id uses up the room. Under a yolo parent there is no dialog, so a user never sees the instruction at all.
3. **The yolo notice row on a resume reads "delegating to writer at yolo — 1 task, from /tmp/610-live/runs/l1-openai/agent/a".** It is cut at column 80 with no `…`. The ADR says the "delegating" wording is intended.
4. **At 80x24 the resume dialog loses its bottom rule and the `↑/↓ move · … Esc cancel` hint row.** The fresh-spawn dialog at 80x24 keeps both. The options still show and the answer works.
5. **After Esc the screen shows only `✖ Operation aborted`.** The agent's id and the resume guidance go only to the model, with the next prompt. The user first sees the id on a later result.
6. **Real model, `-p`:** after the killed child's result, haiku resumed the agent itself in the same run, even though the prompt said "Call the agent tool exactly once".
7. **Real model, TUI:** haiku's final summary told the user "✓ Ran sleep 47 and waited for it to finish". That is false. The `sleep` was cut by Esc and never re-run, because haiku's own resume instruction skipped that step.
8. **Anthropic wire:** the `tool_result` carrying `is_error: true` is followed by a separate user text message, so two consecutive user-role messages are sent.
9. **A `-p` restart without `--permission-mode` resumes at `plan`.** So the brief's exact second command gives a child that cannot write. That is the intended intersection, but a user may not expect it.
10. **The resume dialog never says what the first run was granted.** It shows `Permission: plan`; offering "Allow file edits" is the only sign the first run had more.
11. **The #604 drivers never answer the terminal's cursor-position request.** That hides the yolo notice row and the status bar. The first grid I captured without answering it (kept as `l1-openai-nocpr`) shows a CPR warning and no bottom rows. All other grids answer it.
12. **A bug in my own driver.** Once, my cleanup matched and killed the shell that had started the driver, because that shell's command line contained the scratch path. No aelix process and no other agent's process was hit, and that run's captures were already complete. I fixed the filter before every later run.
