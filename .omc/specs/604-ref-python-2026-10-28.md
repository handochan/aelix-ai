## Q1 Delegation model
- **K:** A single `Agent` tool with these parameters (`tools/agent/__init__.py:21-57`):
  - `description`, `prompt`
  - `subagent_type` (default `coder`)
  - `model`
  - `resume` (an agent_id)
  - `run_in_background`
  - `timeout` (30–3600)
  - Children run **in-process**: a new `KimiSoul` on the same event loop, built via `copy_for_subagent` and `load_agent(type_def.agent_file, mcp_configs=[])`, so children get no MCP (`subagents/builder.py:19-36`).
  - The child gets only the prompt. The explore type also gets git context prepended (`subagents/core.py:72-79`).
  - Tools come from a per-type allowlist, and the model resolves param → type default → parent.
  - Nesting is refused: `if self._runtime.role != "root"` → "Subagents cannot launch other subagents" (`:121-125`).
  - Child approval requests are forwarded to the parent's wire (`subagents/runner.py:403-426`).
- **OH:** The `task` tool takes `description`, `prompt`, `subagent_type` and `resume=task_id`. Its `max_turns` field is deprecated and ignored (`openhands-tools/.../task/definition.py:48-73`).
  - The child is an in-process `LocalConversation` that runs synchronously inside the parent's step.
  - It gets a copy of the parent's LLM (streaming off, its own metrics), the parent's MCP config, delegation tools scoped down, the confirmation policy from its definition or else the parent's, and the parent's workspace (`task/manager.py:376-408, 484-498`).
  - Two variants exist:
    - `delegate`: spawn ids, then delegate a dict of tasks; runs threads and joins them all; `max_children=5` (`delegate/impl.py:44,155-160,361-371`).
    - `start_child_conversation`: non-blocking server-side child via `POST /api/conversations/{id}/children`, with optional git-worktree isolation (`child_conversation/definition.py`).

## Q2 Execution limits
- **K:**
  - Foreground has no default timeout. With `timeout`, `asyncio.wait_for` kills the run and returns `ToolError("Agent timed out after Ns")` with **nothing partial** (`tools/agent/__init__.py:143-155`).
  - Background default is 900 s, cap 3600 (`config.py:98-119`).
  - `max_steps_per_turn=1000`. Hitting it gives "Max steps N reached… split the task" (`runner.py:88-100`).
  - There is no grace turn at limits. There is a quality turn: if the final text is under 200 chars, one extra "provide a more comprehensive summary" turn runs (`runner.py:40-48,142-173`).
- **OH:**
  - No wall-clock limit. `max_iteration_per_run` defaults to 500; a child inherits its definition's value or the parent's. There is an optional `max_budget_per_run` in USD (`manager.py:262-278`).
  - At a limit it stops hard: status ERROR plus `ConversationErrorEvent` with `MaxIterationsReached` or `MaxBudgetReached` (`sdk/conversation/impl/local_conversation.py:742-764, ~2058-2105`).
  - The stuck detector sends **one nudge** user message on a streak of action errors, then stops with STUCK (`:766-790`). Thresholds: same action+observation 4, action-error 3, monologue 3, alternating 6 (`types.py:148-160`).
  - Its subprocess child, `ACPAgent`, uses an **inactivity** timeout `acp_prompt_timeout=1800` that "resets on every update". Separately there is a hard `acp_startup_timeout=90` for spawn, handshake and new/load_session (`sdk/agent/acp_agent.py:1399-1415,1810-1832`).

## Q3 Partial results
- **K:**
  - A foreground failure returns only the error message (`runner.py:289-292`).
  - The partial transcript stays on disk at `subagents/<id>/output`, as `[stage]` / `[tool] name` / `[tool_result] status: brief` / text lines (`subagents/output.py`).
  - Background notifications include the last 20 lines / 3000 chars of output, so a failed or killed background agent does deliver evidence (`notifications/llm.py:31-54`).
- **OH:** PR #3742 (merged) fixed a bug where a stuck, paused or run-limited child was reported as an **empty success**.
  - Now `_run_stop_detail` returns the last error detail, then `"\nPartial result:\n{last agent message}"` (`manager.py:420-461`).
  - The child's metrics are folded into the parent under `task:<id>` even on failure (`:500-508`).

## Q4 Background
- **K:** Yes.
  - Background agents are in-process `asyncio` tasks, root only, at most 4 active (`background/manager.py:209-283`).
  - Background *bash* jobs are detached worker processes with heartbeats.
  - Completion becomes a **durable notification**: per-sink pending→claimed→acked, stale claims recovered, dedupe key `background_task:<id>:<reason>` (`manager.py:487-606`; `notifications/manager.py:55-145`).
  - **If the parent is busy:** a `<notification>` user message is injected before every LLM step (`soul/kimisoul.py:~1132-1160`).
  - **If idle:** the shell races user input against `completion_event` and auto-starts a turn. User input wins, and nothing auto-triggers after a resume until the first user turn (`ui/shell/__init__.py:119-166`).
  - On restore, notification ids already in history are acked, so nothing is delivered twice after a crash (`kimisoul.py:283`).
  - **`-p` mode:** reconciles, re-enters the agent with a synthetic `<\system-reminder>Background tasks have completed…` that bypasses prompt hooks, and drains notifications on failure so the original exit code survives. At a 3600 s ceiling it calls `kill_all_active` (`ui/print/__init__.py:151-292`).
  - **Quit:** kills everything unless `keep_alive_on_exit`.
  - **Waiting never kills:** `TaskOutput(block, timeout≤3600)` returns `retrieval_status: timeout` (`manager.py:337-345`).
- **OH:**
  - `task` and `delegate` both block.
  - `start_child_conversation` is fire-and-forget with no report back. Children are "orphaned, not cascaded" when the parent is deleted (`agent_server/conversation_service.py:1868`).
  - Background tasks exist only as open **PR #4503**: `run_in_background`, `task_output`, `task_stop`, states queued→running→completed|error|cancelled, cooperative `interrupt()`, "never force-kill threads", settled exactly once.

## Q5 Intervention
- **K:** A running child cannot be messaged.
  - Only the root has a steer queue, drained as user messages between steps (`kimisoul.py:622-646`), plus a wire JSON-RPC `steer` method (`wire/jsonrpc.py:143`).
  - Children can only be stopped (`TaskStop`, which needs approval) or resumed once idle. A concurrent resume is refused (`runner.py:357-364`).
- **OH:** The parent *model* cannot message a running `task` child. The SDK primitives are:
  - `send_message` while running: picked up at the next iteration, and the loop deliberately does not exit on FINISHED so the message is not lost.
  - `pause()`: takes effect at the step boundary, after any in-flight LLM call.
  - `interrupt()`: cancels `arun()` even mid-LLM call → PAUSED (`local_conversation.py:2777-2810`).
  - `ask_agent`: a stateless side question that touches no state (`:2917`).
  - The server exposes `/pause`, `/interrupt`, `/run`, `/events` (`send_message` with a `run` flag) and `/ask_agent` (`conversation_router.py:366,380,414,758`; `event_router.py:213`).

## Q6 Persistence & resume
- **K:**
  - Each child lives in `<session>/subagents/<agent_id>/` with `meta.json` (written atomically), `context.jsonl`, `wire.jsonl`, `prompt.txt` and `output` (`subagents/store.py:72-123`).
  - Resume works after completed, failed or killed. It restores the context and **reuses the persisted system prompt** (`core.py:58-68`). Type (and so tool policy) and model come from the stored record (`runner.py:357-369`).
  - On restart, `recover()` marks orphaned agent tasks `lost` and the instance `failed`, which keeps it resumable (`background/manager.py:420-444`).
- **OH:**
  - Child events persist under `<parent>/subagents/<conv_id>`, but the `task_id→task` index exists only in memory.
  - PR #3698, which would have persisted it, was closed as stale.
  - Open issue #5074: after a server restart the child stays `running` forever and the mapping is lost.
  - Resume builds the agent from the **caller-supplied** `subagent_type`, not the stored one, so restrictions can drift (`manager.py:210-244`).
  - Top-level crash recovery is worth copying. A conversation loaded as RUNNING is marked stale → ERROR, and an `AgentErrorEvent` is created for the first unmatched action ("A restart occurred while this tool was in progress…"), parented to that action. A lease stops two processes resuming the same conversation (`agent_server/event_service.py:1421-1465`).

## Q7 Lifecycle & cancellation
- **K:**
  - Strong references live in `_live_agent_tasks` with a done-callback pop, because the loop references tasks weakly; a GC'd pending task showed up as "Exception None" (`manager.py:262-283,381-391`).
  - The runner pops that entry in its own `finally` as well (`agent_runner.py:115-132`).
  - `running_background` is set synchronously before `create_task`, so the resume guard has no race (`tools/agent/__init__.py:220-226`).
  - Pending approvals are cancelled per source.
  - Bash workers: `start_new_session`, 5 s heartbeat, stale after 15 s → `lost`, SIGTERM to the process group with 2 s grace.
  - **Bug class (my reading of the code; maintainers have not confirmed it):** `run_soul` awaits `asyncio.wait([soul_task, cancel_event_task])` **before** entering its `try/finally` (`soul/__init__.py:206-220`). `asyncio.wait` never cancels its tasks, so cancelling the outer runner (wait_for timeout or TaskStop) orphans `soul_task`.
    - This matches **#2615**: an agent kept calling the LLM for about 26 min after being marked terminal.
    - `kill()` then returns early on the persisted terminal status (`manager.py:373-375`).
- **OH:**
  - Uses threads plus `threading.Lock`.
  - A blocking `task` holds the parent's state lock for the child's whole run (open **#4537**: the host UI freezes and the executor pool saturates).
  - Server interrupt does `await asyncio.wait_for(asyncio.shield(self._run_task), timeout=5.0)`, so cleanup is never force-cancelled.
  - `_explicit_interrupt_generation` makes sure a later Stop beats an automatic restart (`event_service.py:255-261,2106-2135`).
  - Cost controls: run slots (429), budget, stuck detector.

## Q9 Host / protocol exposure
- **K ACP:**
  - The Agent call is an ordinary ACP tool call, and **child events are dropped** (`case SubagentEvent(): pass`, `acp/session.py:203-204`).
  - `session/cancel` sets the turn's cancel event → `stop_reason: "cancelled"`. MaxSteps → `"max_turn_requests"` (`:233-238,307-312`).
  - Kimi's own JSON-RPC wire does carry `SubagentEvent` and per-subagent approvals.
  - Lesson from `wire/server.py:1035-1043`: never await an approval inside the event pump, or every concurrent subagent's output stalls and the cascade deadlocks.
- **OH:**
  - The server is REST plus WebSocket, and conversations are the unit; children link via `parent_conversation_id`.
  - It has **no ACP server**. OpenHands is an ACP *client*, and `acp_router` only does model discovery. I did not check the main OpenHands repo.

## Q10 Robustness lessons
1. **K #2615 (open):** a stopped or timed-out background agent kept spending; terminal state was written while execution was still alive. **Lesson:** settle terminal state only after the process or task is confirmed dead, and make stop act on the live handle.
2. **K #2408 (open):** the model always passed `timeout: 120`, so 120 s became the real default despite "no default". **Lesson:** never give the model a kill timeout.
3. **K #2578 (open):** a 403 or timeout mid-batch left half-written files that broke sibling agents' builds, and resume re-spent tokens re-exploring. **Lesson:** return a digest on stop; quota errors should park the child, not kill it.
4. **K #1768:** many in-process background agents stalled the CLI, cascading into provider timeouts. aelix's process-per-child design avoids this, but still needs a concurrency cap.
5. **OH #3742 (merged):** a non-finished child was reported as success; fixed to error plus partial result.
6. **OH #5074 / #3698 and #4537:** an in-memory index means no resume after restart; blocking under the parent lock freezes the host.

## DeepSeek and goose (quick check)
- `lessweb/deepcode-cli` (TypeScript) has no subagent or task tool (`packages/core/src/tools`). `surf1k/deepseek-cli` (Rust, 0★) is trivial. Nothing to borrow from either.
- **Codewhale (ex-DeepSeek TUI) is worth borrowing from.**
  - `crates/tui/src/tools/subagent/budget_handback.rs` `fallback_partial_text`: when a child dies, the parent gets a bounded digest — "the parent gets evidence, never a report". It is the last non-empty assistant text (≤4000 chars), or else up to 12 tool entries as `name target` plus ≤1500 B of thinking.
  - It also has `repair_stopped_tool_calls`, a private `subagent-results/` artifact, and caps of 64 concurrent / 1024 admitted.
  - Its per-step API timeout was raised from 120 s to 600 s because slow reasoning calls were tripping it (`crates/runtime/src/config/subagent_limits.rs:13-28`).
- **goose** (`crates/goose-agent/src/subagent.rs`): stopping the parent delivers finished children, cancels running and queued ones with "Subagent X was cancelled before it finished.", and records the outcome as an operation note so a replay does not restart them (`tests/subagent.rs:292-330`).

## Borrow (ranked)
1. **P0 – stop digest.** Combine OH `_run_stop_detail` (reason + partial result), Codewhale's bounded digest and Kimi's notification tail. Add aelix's session id and changed files. Mark it as an error, not a success (#3742). Small amount of code.
2. **P0/P1 – repair dangling tool calls before resuming.** Copy OH's synthesized "restart occurred" error result, parented to the action (`event_service.py:1421-1465`), or Codewhale's `repair_stopped_tool_calls`.
3. **P1 – Kimi instance record.** Atomic `meta.json` holding status and launch spec, with type, policy and model taken from the record on resume, the persisted system prompt reused, concurrent resume refused, and running set before spawn. Near-direct port of `subagents/models.py` and `store.py` (~250 lines).
4. **P1/P2 – startup reconcile.** Kimi `recover()`: an orphan becomes `lost` and stays resumable. Use child pid/pgid in aelix's case.
5. **P2 – Kimi notification pipeline.** Durable claim/ack with stale-claim recovery, dedupe keys, ack-on-restore, injection between steps when busy, and an idle watcher where user input wins. Near-direct asyncio port of `notifications/manager.py`, `llm.py` and `ui/shell/__init__.py:119-166`. It matches pi durable's "follow-up if busy, new turn if idle".
6. **P2 – Kimi `-p` loop and non-destructive wait.** Re-enter with a system-reminder, bypass hooks, drain on failure so the exit code is kept, reconcile twice before exiting. Drop the 3600 s ceiling kill. `TaskOutput(block, timeout)` returns a snapshot and never kills.
7. **P2/P3 – stop semantics.** OH's two tiers (pause at the step boundary vs. interrupt), a shield-bounded wait during cleanup, a generation counter, and goose's "deliver finished, cancel queued, record so replay doesn't restart".
8. **P2 – asyncio hygiene.** Kimi's strong-ref dict plus done-callback and per-source approval cancellation. Avoid its `run_soul` bug: use a `TaskGroup`, or cancel and await child tasks inside `finally`.
9. **P3 – stall detection without killing.** OH's idle clock (reset on any child JSONL event; separate hard startup deadline) should mark a child "stalled", never kill it. OH's stuck patterns plus a single nudge map naturally onto steer and "wrap up now".
10. **P4 – event tagging.** Kimi's `SubagentEvent` envelope for aelix RPC. For ACP, map child progress onto the parent tool call's `tool_call_update` — something neither reference does.

## Avoid
- Kill timeouts the model can choose, and kills that return nothing.
- Writing terminal status before the process is dead.
- `asyncio.wait` outside `try/finally`.
- A child registry that lives only in memory.
- Resuming with the caller's type instead of the stored one.
- Holding the parent session lock while a child runs.
- Blocking the event pump on approvals.
- Reporting a non-success as an empty success.
- Hiding child events from hosts (Kimi ACP, OH stream).
- Kimi's `-p` ceiling kill.
- Unbounded fan-out (Kimi caps at 4 active, Codewhale at 64).

## Speed-up per phase
- **P0:** High. Three independent partial-result designs plus a known bug class.
- **P1:** Medium-high. Kimi's store and resume port almost directly; OH supplies both the crash repair and the pitfalls.
- **P2:** High. Kimi is a complete asyncio reference (notifications, idle trigger, `-p` wait, non-killing wait) with race fixes documented in comments. Remove its timeouts.
- **P3:** Low-medium. Neither project lets you message a running child; there are only primitives (steer queue, pause/interrupt, nudge). "Wrap up now" is new design work.
- **P4:** Low. Kimi drops child events from ACP and OH has no ACP server; only Kimi's wire envelope carries over.
