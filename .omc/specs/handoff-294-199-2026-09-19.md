## 이 레포에서 실제로 물린 규칙

- **오너에게는 한국어로 답한다.** 영어로 AskUserQuestion을 냈다가 "한국어로 다시 알려주세요"로 반려됐다. 메모리에 저장했다. 코드·커밋·ADR 제목은 기존 언어를 그대로 쓴다.
- **워크플로우 레인 구성이 잘 맞았다.** #199는 파일이 겹치지 않는 두 레인(K: 커널 통계와 표시, D: 위임 기록)을 병렬로 돌리고 통합자 하나를 뒀다. 레인 K는 줄 수를 보존해서 레인 D 파일의 인용이 흔들리지 않게 했다. 에이전트는 이슈당 설계 비평 1, 구현 1–2, 통합 1, 리뷰(opus와 Codex) 2, 수정 1을 썼다.
- **Codex는 작은 델타 프롬프트가 잘 먹힌다.** 600줄 이하, `-c model_reasoning_effort=high`, `--sandbox read-only -C <worktree>`, `-o <file>`, `< /dev/null`, 한 번에 하나씩 돌리면 5–6분에 끝났다. 네 번 모두 실제 결함을 찾았다(publish temp 공유, 취소가 확정 $0이 됨, 래치된 `agent_end`, 합성 `agent_end`).
- **Edit 도구는 Read를 먼저 해야 한다.** 거부된 Edit와 같은 호출 묶음에 있던 sed가 먼저 적용되어, `__all__`에만 새 이름이 들어간 채로 테스트가 통과했다. 편집이 거부되면 같은 묶음의 다른 편집부터 되돌아본다.
- **zsh heredoc 안에서 파이썬 replace를 쓸 때 조심한다.** 따옴표 없는 heredoc(`<<EOF`) 안에서 `$S`가 확장되면서 `\\x03` 같은 이스케이프가 바뀌었고, replace가 매칭에 실패했다. `<<'EOF'`나 Edit 도구를 쓴다.
- **pty 드라이버의 좀비 착시.** 종료한 자식은 reap 전까지 좀비라서 `os.kill(pid, 0)`이 성공하고, 그러면 "안 끝났다"는 거짓 경보가 난다. `os.waitpid(pid, os.WNOHANG)`로 재야 한다. 실제 `/quit`은 일반 턴 뒤든 위임 뒤든 main과 #199 모두 **0.6 s**다. #294 수정 레인이 본 "5 s"도 같은 착시다.
- **`gh run rerun --failed`는 run 전체가 끝나야 된다.** flake는 실패한 잡만 재실행하고, 재현은 해당 이슈(#261, #303)에 기록한다.

## 반증된 것 — 다시 믿지 말 것

- **"세션 파일은 Windows에서도 LF다"** — 아니었다. `os.open`이 텍스트 모드 fd라서 CRLF였다. #294부터 `O_BINARY`로 LF만 쓰고, 옛 CRLF 파일도 읽힌다.
- **"로더가 모르는 키는 무시하니 기존 타입에 필드를 더해도 하위 호환이다"** — 읽기만 그렇다. 출시된 fork는 header·entry·message·content block의 모르는 키를 **버린다**. `CustomEntry.data`만 그대로 남는다(ADR-0242 규칙 1.3, 비평이 측정했다).
- **"pi v4가 Aelix 파일을 import한다"** — `leaf` 레코드와 빈 줄을 거부한다(`legacy-v3.ts`를 읽어서 확인했고, 실행하지는 않았다).
- **"취소된 자식의 사용량 0은 '안 썼다'는 뜻이다"** — 아니다. 진행 중이던 요청이 과금됐을 수 있으므로 **하한**이다. 라이브에서도 확인했다: 모델 호출 중 Ctrl+C → settle `cancelled`, `cost_known: false`.
- **"`agent_end`를 봤으면 사용량이 다 왔다"** — 아니다. 자식의 abort 경로는 `message_end` 없이 `agent_end`를 내고, 자동 재시도는 두 번째 실행(`agent_start` → `agent_end` → `agent_start`)이다. 그래서 완결 판정은 `run_open`(마지막 이벤트 우선)과 부모가 끊었는지로 한다.
- **"`/agents show`는 `profile_to_argv`를 렌더링한다"** — `profile_to_flags`를 렌더링한다. 두 docstring이 틀렸었고, 고쳤다.
- **"`SubagentHost`의 live getter로 부모 세션을 읽으면 된다"** — `_ctx`는 마지막 훅의 것이라 `/new`·종료 뒤에는 stale이고, 첫 `/agents run` 전에는 None이다. 그래서 스폰마다 한 번 캡처하고 `cli/entry.py`에서 배선했다. **모델 getter는 아직 이 문제가 남아 있다(#304).**
- **"위임 뒤 `/quit`이 안 끝난다"** — 드라이버의 좀비 착시였다(0.6 s).
- **"rename 재시도는 필요 없다"** — Windows는 스캐너나 인덱서가 방금 닫은 temp를 잡고 있으면 rename을 거절한다. 그래서 약 1초 동안 재시도한다(pip도 같은 이유로 재시도한다). POSIX에서는 즉시 실패로 처리한다.
- **"publish temp는 `<path>.tmp` 하나면 된다"** — import 목적지는 원본 이름을 따르므로 두 프로세스가 같은 temp를 쓰게 된다. 그래서 `copy_file`만 호출마다 고유한 이름을 쓴다(Codex가 스레드로 재현했다).
