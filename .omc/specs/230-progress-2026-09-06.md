## 5. Deviations, and why

1. **Mutation row (d) dies on C.2's `wedged=False` arm, not `wedged=True`.** The design predicted the
   wedged arm on the ground that it is "the one leg where `_finished` is false while `aborted` is
   true". True, but the polarity is backwards: reading `._finished` makes clause (d) fire the *instant
   the drain is entered* on the REAPED path, because the handle was just finished there — so the
   post-kill drain collapses to zero and the abort timer never gets to run. Measured:
   `assert aborted_at, "the abort never fired — the case measured nothing"` → `assert []`, both arms.
   On the wedged arm the mutant simply never fires clause (d), and that arm carries no timing pin, so
   it passes. Suite-wide it is killed **5 of 109** — C.1 ×2, C.2 `wedged=False` ×2, C.3 (§7's
   re-measured table) — so the row's *conclusion* stands and its *arm* is corrected.
2. **`DRAIN_CAP_SECONDS` is imported inside C.3's function body**, not in the module import block. A
   module-level import would shift the file's one citation anchor (a line range inside
   `test_a_setsid_grandchild_is_reached_by_the_job_and_not_by_the_group`, cited from
   `tests/tools/test_bash_tool_containment.py`) — the same reason the design mandates appending the
   case. A comment at the import says so.
3. **That comment first named the anchor as `file:line` and `--check` went to `852 gated`.** A
   self-referential citation, correct but a new lock entry that no design step asked for. Rewritten to
   name the case by function (the repo's own rule); back to **851 gated, none drifted**.
4. **The ADR's Consequences paragraph is appended at the END of that section**, after the #226
   amendment bullet, which is the order every previous amendment used.
5. **CHANGELOG's flatten-and-grep found one more "cancelled turn" sentence**, at `CHANGELOG.md:543`.
   It is inside #222's bash-tool entry, reports a measurement at *that* site ("stopped with Esc or by a
   cancelled turn" — 8.02/8.03 s), and makes no unqualified claim that a cancelled turn ends the tree.
   §G assigns that entry's territory to #232, so it is **left alone**. Every `aelix.exec` sentence in
   `## [Unreleased]` now carries a lifetime qualifier.
6. **The §E live checks were NOT run** — this lane's instruction reserves rules 9 and 10 for the
   orchestrator.

### 🔴 Carry-forward for anyone re-taking §H rows 21/22/25

1. **The aborter thread must yield the GIL.** A `while …: pass` delay loop holds the GIL for its whole
   length (default switch interval 5 ms), starves the reaping thread's `abort._finish()`, and
   *manufactures the window under test*: it flipped `timeout=None` from ALIVE 6/6 to **DEAD 6/6** — a
   pure artifact, and a false positive both round-2 refuters hit and then corrected. Use `time.sleep()`
   increments. The branch's own probe (`…/scratchpad/230/probe_window_patched.py:90`) already does, so
   rows 21/22 were *not* taken under this artifact — but a fresh harness written from the design text
   alone will reproduce it. (It is also a live demonstration of the ADR's "0.055 ms median / 0.103 ms
   max when another thread is running Python" residue, amplified to the spin's full length.)
2. **`os.waitid` does not exist in CPython on darwin.** A probe that uses it dies in the aborter thread
   and reports a silently vacuous "helper ALIVE". Use the libc call through `ctypes`
   (`P_PID=1, WEXITED=0x4, WNOWAIT=0x20, WNOHANG=0x1`, `si_pid` at byte offset 12); `WNOWAIT` leaves
   the zombie so `Popen.wait` still reaps it.
3. **One trigger shape that does NOT work on darwin:** an aborter spinning on
   `handle._proc.returncode is not None` to land in the post-reap-pre-disarm residue came back
   **0/20** at `timeout=None` — the run thread wakes out of a GIL-released `waitpid` and
   publishes+disarms without yielding. This does **not** falsify row 25's 17/20; it means that
   trigger does not reproduce it on this host.
