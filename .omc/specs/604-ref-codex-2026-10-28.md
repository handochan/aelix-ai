Paths below are relative to `codex-rs/`. I only read the code; I did not build or run anything.

## Q1 Delegation model
There are two tool generations:
- **V1, feature `multi_agent`.** Stable and on by default (`features/src/lib.rs:1554-1559`). The tools sit in namespace `multi_agent_v1`:
  - `spawn_agent{message|items, agent_type, fork_context, model, reasoning_effort}` returns `{agent_id, nickname}`.
  - `send_input{target, message|items, interrupt}`
  - `resume_agent{id}`
  - `wait_agent{targets[], timeout_ms}`
  - `close_agent{target}`
  - Source: `core/src/tools/handlers/multi_agents_spec.rs:70-374,610-648`.
- **V2, feature `multi_agent_v2`.** Stable but off by default (`lib.rs:1560-1565`). Agents are addressed by path, e.g. `/root/worker`. The tools are:
  - `spawn_agent{task_name, message, agent_type, fork_turns, model, reasoning_effort}`
  - `send_message`, `followup_task`, `interrupt_agent`
  - `list_agents{path_prefix}`
  - `wait_agent{timeout_ms}`, which takes no targets.
- **`spawn_agents_on_csv` no longer exists.** Its flag `enable_fanout` is `Stage::Removed`, described as a "flag for the deleted agent-job tools" (`lib.rs:260-261,1614-1619`).
- **Children run in-process.** Each child is its own `CodexThread`/Session inside the same `ThreadManager` (`core/src/thread_manager.rs:2039-2045`, `spawn_child_thread`). It has its own rollout and shares the `AgentControl` runtime.
- **What a child gets:**
  - A clone of the parent's *current turn* config: model, provider, effort, developer instructions, token budget (`core/src/agent/child_config.rs:132-164`).
  - Permissions intersected with the parent's authority via `intersect_effective_permission_profiles` (`core/src/agent/control/spawn.rs:440-461`).
  - Optionally a fork of the parent's history (`spawn.rs:717-731`).
  - Roles from `[agents.<role>] config_file`.

## Q2 Waiting vs execution
- **No execution timeout or turn cap on children.** The only per-agent wall-clock limit was `agents.job_max_runtime_seconds`. It is now "Removed agent-job setting retained as a no-op" (`config/src/config_toml.rs:781-783`). This matches the owner's decision.
- **The wait timeout only ends the wait; it never kills.** Default 30 000 ms, minimum 10 000, maximum 3 600 000 (`handlers/multi_agents_common.rs:22-24`, `core/src/config/mod.rs:260-270`).
  - V1 clamps the value and returns `{status:{}, timed_out:true}` while children keep running (`handlers/multi_agents/wait.rs:95-102,181-206`).
  - V2 clamps the low end and tells the model: "Requested timeout of Xms was clamped to the minimum…" (`multi_agents_v2/wait.rs:56-65,150-180`). This came in PR #37357, after polling burned tokens (#39854 reports about 678M tokens).
- **`Interrupted` is not a final status** (`core/src/agent/status.rs:26-31`). A wait therefore never returns for a child that was interrupted.
- **There is no grace or final-summary turn.** The only control is cost-based: an opt-in `rollout_budget` (`core/src/rollout_budget.rs:1-110`).
  - Weighted tokens are counted once for the whole agent tree.
  - At configured thresholds, a model-visible "remaining tokens" reminder goes to each thread. It is acknowledged only after it has been inserted into history.
  - With `enforce_limit` set, it raises `SessionBudgetExceeded`, the turn aborts as `BudgetLimited`, and the status becomes Interrupted (`status.rs:13-17`).

## Q3 Partial results
- **The parent gets a status and nothing else.** Possible values are `Completed(last_agent_message)`, `Errored(msg)`, `Shutdown` and `NotFound` (`status.rs:6-24`).
- **Envelope contents** (`core/src/session_prefix.rs:9-14,20-42`):
  - Completed: the child's last message, verbatim.
  - Errored: the error cut to about 900 tokens, plus "This agent's turn failed. If you still need this agent, use the available collaboration tools to give it another task."
  - Shutdown: "Agent shut down."
  - Interrupted or Running: **no message at all**.
- **`close_agent` returns the previous status** (`core/src/agent/control/legacy.rs:52-108`). If the child was running, that is just "running".
- **No tool trail and no changed-file list.** The full transcript is only in the child's own rollout/thread, which a host can fetch with `thread/read`. aelix's Phase 0 return would carry more than Codex does.
- **The child's own history records `<turn_aborted>`** after an interrupt (`agents.interrupt_message`, default true, `config_toml.rs:784-786`).
- **Error masking:**
  - PR #28375 fixed `TurnComplete(None)` overwriting `Errored`, which had made a failed child look like `completed:null`.
  - #36799 (open): `wait_agent`/`close_agent` still report `completed:null` while the notification says errored. Status is derived on several paths and they disagree.

## Q4 Background completion reporting
- **Mechanism.** Each child gets a detached completion watcher that subscribes to its status. When the status becomes final (tree shutdown is ignored), it delivers the result (`core/src/agent/control.rs:436-581`):
  - V1 calls `inject_fragment_without_turn(<subagent_notification>{"agent_path","status"}</subagent_notification>)`, which writes into the parent's history without starting a turn.
  - V2 sends `InterAgentCommunication` mail with `trigger_turn=false` (`core/src/agent/control/completion.rs:26-155`) and records a `codex.multi_agent.result_delivery` metric of queued or failed.
- **Parent busy.** The mail is drained into the active turn at the next sampling boundary. V2 `wait_agent` wakes on mailbox activity *or* on user steer. It returns only "Wait completed." and the content arrives as mail (`multi_agents_v2/wait.rs:196-220`).
- **Parent idle.** By default the parent is *not woken*. `inter_agent_communication` starts a turn only if `trigger_turn || WakeOnAgentMessages || durable sleep` (`core/src/session/handlers.rs:80-101`, `core/src/tasks/mod.rs:470-520`).
  - `wake_on_agent_messages` is under development and off by default (`lib.rs:1596-1601`). PR #54961 added it, stating "A worker can finish after its parent has returned a final answer."
  - PR #56330 makes a pending wake recheck interrupt and Plan mode before it consumes mail. An interrupted session keeps its queued mail but does not wake on its own.
- **Fetching later:** V1 `wait_agent`/`close_agent` statuses, V2 `list_agents`, and `thread/read` on the child.

## Q5 Intervention
- **V1 `send_input`** (`handlers/multi_agents/send_input.rs:68-108`, `control.rs:140-160`):
  - `interrupt=true` interrupts the child's turn first, then submits.
  - Otherwise it calls `start_or_steer_turn`: a running child gets the input steered into its next model request; an idle child starts a new turn.
- **V2 splits this into three tools** (`multi_agents_spec.rs:204-262`, `multi_agents_v2/message_tool.rs`):
  - `send_message` only queues; its description says "Does not trigger a new turn."
  - `followup_task` triggers a turn if the child is idle. If it is running, delivery happens "at message boundaries while sampling, or after the pending tool call completes."
  - Both reload a child that has been unloaded.
- **`interrupt_agent`** stops the child's turn; the child stays addressable. It refuses to target root or self: "an agent cannot interrupt itself; return your result and let the parent interrupt you if needed" (`core/src/agent/control/interrupt.rs:8-52`).
- **No "wrap up now" primitive.** The closest is `interrupt_agent` followed by `followup_task`.
- **User intervention:**
  - In the TUI, a V1 child view has a live composer the user can type into.
  - V2 children are parent-owned and show "Viewing sub-agent — direct input is disabled" (`tui/src/bottom_pane/chat_composer.rs:1685-1688`).
  - Hosts treat a child as an ordinary thread and use `turn/start`, `turn/steer`, `turn/interrupt` (`app-server-protocol/src/protocol/common.rs:1076-1094`). A V2 child "must resume through [its] owner" (`app-server/src/request_processors/thread_processor.rs:4110`).

## Q6 Persistence and resume
- **Storage.** Each child has its own rollout JSONL plus a spawn edge in the agent-graph store marked `Open` or `Closed`. `close_agent` flushes the rollout and then persists `Closed` (`legacy.rs:8-90`).
- **V1 `resume_agent`** reopens a child only when its runtime is gone, via `resume_agent_from_rollout` (`core/src/agent/control/resume.rs:5-37`, `spawn.rs:920-1100`). It:
  - restores history, nickname and role from stored metadata;
  - reopens descendants whose edge is Open, breadth-first, and skips Closed ones;
  - re-attaches the completion watcher.
- **V2** does not reopen descendants on resume (PR #26997). It reloads them lazily when a message is delivered, and keeps their mail while they are unloaded (`core/src/agent/control/mailbox.rs`).
- **Crash or restart** uses the same rollout path; the test `cold_root_resume_restores_agent_identity_and_role_on_followup` covers it.
- **Restrictions are rebuilt from the *caller's* current turn config** (`child_config.rs:124-130`). Open issues show the consequence: #26718 and #36433, where resume restores history but changes the model and reasoning. Status is not persisted either: #34220, where a resumed child loses its completed status after a restart.

## Q7 Lifecycle and cancellation
- **Interrupting the parent's turn does not stop children.** I found no cascade from session or task code.
- **Root `suspend_turn_and_shutdown`** (a handoff) interrupts descendants, which are "not automatically recovered" (`core/src/codex_thread.rs:521-533`).
- **`close_agent` shuts down the subtree, but `wait_until_terminated()` has no bound** (`legacy.rs:8-48,111-127`). Open hangs and leaked MCP processes: #25426, #24389, #29937, #35435.
- **App exit** calls `shutdown_all_threads_bounded(timeout)`, which reports completed / submit_failed / timed_out (`thread_manager.rs:1478-1530`).
- **Concurrency limits:**
  - V1 `agents.max_threads` defaults to 6 and counts *open* agents. The tool text says "Completed agents remain open and count toward the concurrency limit until closed." See #22779, #39694, #50584.
  - V2 `max_concurrent_threads_per_session` defaults to 4 and counts *resident* agents, with LRU eviction of idle ones (PR #26632; `core/src/agent/control/residency.rs`). Related races: #47240, #52034, #50087 fixed; #32353 still open.
- **Depth.** `max_depth` defaults to 1, and the model sees "Agent depth limit reached. Solve the task yourself." (`handlers/multi_agents/spawn.rs:74-79`).

## Q9 Host/protocol exposure
- **Children are threads.** When any thread is created, the server attaches listeners for every initialized connection (`app-server/src/lib.rs:1326-1344`). Hosts therefore receive the child's `thread/started`, `turn/*` and `item/*` events keyed by its thread id.
- **Parent stream items:**
  - `ThreadItem::CollabAgentToolCall` with fields:
    - `id`
    - `tool`: spawnAgent | sendInput | resumeAgent | wait | closeAgent | sendMessage | followupTask | interruptAgent | listAgents
    - `status`
    - `senderThreadId`, `receiverThreadIds`
    - `prompt`, `model`, `reasoningEffort`
    - `agentsStates: {threadId: {status: pendingInit|running|interrupted|completed|errored|shutdown|notFound, message}}`
  - `SubAgentActivity{kind: started|interacted|interrupted|completed, agentThreadId, agentPath}` (`app-server-protocol/src/protocol/v2/item.rs:437-457,1195-1205,1330-1367`).
- **Discovery:**
  - `thread/list` with experimental `parentThreadId` / `ancestorThreadId` filters (`app-server-protocol/src/protocol/v2/thread.rs:1483-1491`).
  - Source kinds such as `subAgentThreadSpawn` (`thread.rs:1545-1549`), plus `thread/loaded/list` and `thread/read`.
- **Archiving.** `thread/archive` takes the lock on the whole spawn subtree (`thread_processor.rs:1862-1885`).
- **Hooks.** `subagent-start` and `subagent-stop` exist.

## Q10 Robustness lessons
1. **#47762 (open): steering before `wait_agent` means results never come back.** The parent finishes its turn and the children's completions never start a new one. Partial fixes: PR #54961 (wake behind a flag), #56330 (the wake rechecks interrupt and Plan mode), #55644 (injected input that is already pending also ends a wait).
2. **#24951 (open): `wait_agent(300 s)` returned after 7.5 h**, as did `spawn_agent`. A stall in the shared control plane blocked both, and nothing enforces an end-to-end deadline.
3. **Failures masked as successes.** PR #28375 fixed errors arriving as `completed:null`; #36799 (open) shows the status paths still disagree.
4. **Finished children hold concurrency slots** (#22779, #39694). V2 answered with a residency LRU (PR #26632), which then needed race fixes (#47240, "pin recipients with queued mail"; #50087).
5. **`close_agent` can hang forever** because the termination wait has no bound (#25426, #29937, open). MCP subprocesses leak (#35435).
6. **Resume uses the wrong config.** #26718 and #36433 change the model on resume, and #34220 loses the completed status. In #26822, children that inherited forked orchestration context behaved like orchestrators and shut down without delivering anything. #24225: the notification duplicates the result `wait_agent` already returned.

## Borrow, ranked
1. **(P0) Status enum and terminal envelope.** Use `PendingInit|Running|Interrupted|Completed(last)|Errored|Shutdown|NotFound`. Treat Interrupted as not final. Bound errors to about 1k tokens and append a next-action hint. Derive status in **one** place, or you get #36799.
2. **(P2) Mailbox delivery with a `trigger_turn` flag.** A busy parent receives at the next boundary. An idle parent wakes only through a policy that rechecks interrupt and Plan mode at admission (PR #56330). Count delivery outcomes as queued or failed. Keep mail for unloaded or stopped children.
3. **(P2) Wait semantics.** Never kill. Clamp to a 10 s minimum and tell the model when you do. Return early on user steer or on pending injected input. Return a summary, with the content delivered once.
4. **(P3) Three intervention verbs, borrowed directly.** Queue-only `send_message`, turn-triggering `followup_task`, and an `interrupt_agent` that leaves the child resumable. Refuse self-interrupt.
5. **(P1) Persisted spawn edges (Open/Closed) with breadth-first reopen of Open children.** Also persist the child's spawn config (tools, permissions, model) and restore *that*.
6. **(P1) Intersect child permissions with the parent's authority.**
7. **(P4) Child = first-class thread or session.** The parent stream carries `CollabAgentToolCall` items with `agentsStates` plus activity items. Support list-by-parent/ancestor, steer/interrupt by id, and automatic subscription to spawned children.
8. **(P2/P3) TUI collab rows and a switcher.**
9. **(P0/P2) Tree-wide token budget with reminders** instead of a wall clock.

## Avoid
- Unbounded waits for a child to terminate. aelix has real processes, so escalate SIGTERM→SIGKILL after a deadline.
- Counting finished children against concurrency.
- Leaving an idle parent un-woken, or delivering a result twice.
- Rebuilding a resumed child's restrictions from the caller.
- Keeping terminal status only in memory.
- Forking orchestration context into workers.
- Any wait deadline that depends on a shared control plane. Keep `wait` as an independent asyncio deadline.

## Value per phase
- **P0:** Moderate. It confirms that removing the timeout is sound, and the envelope and status model are reusable. Codex returns less than aelix plans to.
- **P1:** Moderate. Spawn edges, breadth-first reopen and permission intersection carry over. Its open config-restore bugs are a warning about what not to copy.
- **P2:** High. Mailbox, `trigger_turn` and the wake flag map directly, and its bug list is concrete.
- **P3:** High. The interrupt-versus-queue semantics are exact and tested.
- **P4:** High. The thread-per-child model and the item and status shapes map directly onto RPC and ACP.
