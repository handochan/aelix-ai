   - 다음 세션이 쓸 도구는 `.omc/` 아래에 지속 사본을 둔다. "재부팅하면 사라진다"는 틀렸다. **3일이면 사라진다.**
2. **`git rebase --continue`는 커밋 메시지에서 `#`로 시작하는 줄을 주석으로 지운다.**
   - #344 rebase에서 `#98…`, `#363…` 줄이 사라졌다.
   - rebase 뒤에는 메시지를 확인하고 `git commit --amend --cleanup=verbatim -F <file>`로 되살린다. `verbatim`은 파일 끝의 빈 줄까지 보존하므로 파일을 `rstrip()+"\n"`로 정리한다(한 번 빈 줄이 붙어 다시 amend했다).
3. **실제 agent dir로 라이브 확인을 하면 제품의 OAuth refresh가 `auth.json`을 다시 쓴다.**
   - #344 레인이 `openai-codex` 호출로 오너의 `~/.aelix/agent/auth.json`을 갱신했다(09-30 23:42:37). 브리프는 "쓰지 말 것"이었지만 제품 경로까지는 막지 못했다.
   - 라우팅 확인은 격리된 `AELIX_CODING_AGENT_DIR`, 가짜 키, 기록용 CONNECT 프록시로 한다. 드라이버는 `.omc/probes/344-live/`에 있다: `matrix.sh`는 fake 키 표, `real.sh`는 실제 키, `drive.py`는 TUI pty, `listeners.sh`와 `listener.py`. 스크립트 안의 `/tmp/344-work/main-live` 경로는 복사해 쓸 때 바꾼다. 실제 OAuth 호출은 토큰이 유효할 때 한 번만 하고, `find ~/.aelix/agent -newer <stamp>`로 확인한다. 메인 루프의 재확인에서는 쓴 파일이 0개였다.
4. **기록용 CONNECT 프록시는 실제 키를 내보내지 않고 누출을 증명한다.** `HTTPS_PROXY`를 로컬 리스너로 두면 https 요청은 CONNECT 단계에서 403을 받는다. 그래서 대상 host는 기록되고 키는 TLS 전에 멈춘다(`.omc/probes/344-live/listener.py`).
5. **Codex 2차 패스가 값을 했다.** 1차 교차 리뷰의 지적을 고친 상태를 다시 보냈더니 새 결함 둘이 나왔다: 명시한 `--provider`가 사용자 키를 벤더로 흘림, 늦은 대소문자 충돌이 RPC로 누출. 새 동기화 장치나 규칙을 넣은 라운드 뒤에는 Codex를 다시 돌린다(#334 때와 같은 교훈).
6. **"테스트가 한 번만 경고한다"는 단언도 사보타주로 확인한다.** #344 F3 interactive 행은 `is_runnable`을 고정하지 않아 #98 경고가 애초에 뜨지 않았고, "한 번"이 아무것도 잡지 못했다(S6). 단언이 나머지 전제에 기대는지 본다.
7. **zsh는 큰따옴표 안의 백틱을 명령 치환으로 실행한다.** 계획 문서에 넣던 `echo "… \`path\` …"` 줄에서 경로가 사라졌다. 문서에 쓸 때는 따옴표 붙인 heredoc(`<<'EOF'`)이나 python을 쓴다.
