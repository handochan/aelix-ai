## §1 설계와 다르게 한 것

### 레인 K (자세한 내용은 레인 K 노트 §3)

1. `tests/harness/test_session_stats.py`도 고쳤다 — pi_parity 핀과 같은 "Aelix 추가 필드 = {cost_known}" 핀이 있어서
   `{"cost_known", "tool_usage"}`로 같이 옮겼다.
2. `harness/core.py`와 `tui/commands.py`를 **줄 수 불변**으로 고쳤다(레인 D 파일의 인용이 밀리지 않도록).
3. 설계가 정하지 않은 fold 규칙은 전부 fail-closed: 모르는 `state`/객체 아닌 `data` → 건너뜀 + cost unknown,
   `cost_known` 없음 → unknown, `usage` 필드 누락 → unknown, `v`는 읽지 않음, key는 비어 있지 않은 문자열만,
   정수값 float 토큰 허용, 마지막 줄이 pending이면 앞선 final도 무효("last line wins"를 예외 없이).
4. `runs`는 pending인 것도 센다 → "(2 runs, 1 pending)".
5. `/cost`는 표라서 라벨 열(`tools & delegated agents`) + 값 열로 옮겼다. 세션 탭은 설계 예시 문장 그대로.
6. 토큰 표기 `_compact_count`(1,000부터 `k`)는 배치 `[total]` 줄·statusline과 같고, History 탭의
   `_compact_tokens`(10,000부터 `k`)와는 일부러 다르다.

### 레인 D (자세한 내용은 레인 D 노트 "편차")

1. **계약 필드 추가**: `SubagentResult.output_recorded: bool = False`(additive, `CONTRACT_VERSION` 유지). 배치
   렌더러가 재-cap한 마커가 "기록됨"을 주장해도 되는지 알 방법이 달리 없다. ADR-0243 §5에 적었다.
2. **기존 결함 수정**: `/new`·`/resume`·`/fork` 직후 첫 프롬프트 전의 `/agents run`이 stale `ExtensionContext`
   때문에 동의 전에 실패했다(`getattr` 기본값은 `AttributeError`만 잡는다). stale ctx = ctx 없음. ADR-0243 §9 +
   CHANGELOG Fixed에 적었다.
3. **루트 배치 판정**: 설계는 "sessions root 바로 아래"만 거부, 구현은 "부모 디렉터리가 bucket 모양(`--…--`)이
   아니면 거부"(확장은 `--session-dir`를 못 본다). 임의 위치의 부모(`--session /x/y.jsonl`)도 자식은
   `--no-session` + start `error: "parent outside a bucket"`. ADR-0243 §1에 결정으로, 넓히는 일은 "Not done here"에.
4. start 레코드에 `error` 키(설계 A.1/A.2가 요구), settle은 start의 모든 필드(error 제외)를 반복하는 완결 레코드.
5. `cost_known`의 네 번째 조건 `cost > 0`(주입 채널 대비), `--fork <자식 파일>`에도 경고.
6. `tests/agents/test_rpc_sprint_pins.py`의 `--no-session` 두 곳은 옮기지 않음(실제 rpc 자식을 띄우는 테스트용
   argv이지 제품 argv 핀이 아님). rpc argv의 세션 플래그 핀은 `test_child_argv_contract.py`에 추가.
7. `cli/entry.py` 헬퍼는 인용 drift를 줄이려고 모듈 끝에, `_build_session`은 줄 수 불변.
8. `roll_up_usage` = 커널 fold 동치 테스트는 레인 K가 썼다(레인 D는 docstring에 "display only"만).

## §3 리드에게 — 열린 질문과 아직 돌려야 할 것

1. **라이브(설계 §D) — 아직 아무도 안 돌린 것.** 레인 D가 돌린 것은 §D 1번의 single 위임 하나(openrouter,
   haiku-4.5, plan): 자식 파일 header+origin+transcript, 부모 start·pending·settle(`usage 5473/83`, `$0.005888`,
   레지스트리 fallback으로 `cost_known: true`)·final, `--continue`가 자식을 가장 최신으로 만들어도 부모를 이어받음,
   `--session <자식>` 경고 후 파일 무변경, `--export` 9,073바이트. **남은 것**:
   - §D 1 후반: 병렬 배치 3개(자식 파일 3개, start/pending이 섞여 쓰이는지, 호출당 64 KiB 예산).
   - §D 2 TUI(`uv run aelix --agents …`, 규칙 9): 위임 뒤 `/cost`와 `/stats` 세션 탭의 도구 줄, 진행 중 `≥ $X`와
     `(n runs, 1 pending)`.
   - §D 3 위임 중 Ctrl+C: settle `cancelled`, pending → final, `--continue`가 부모를 이어받음.
   - §D 4 위임 중 종료(quit): settle이 부모에 떨어지는지.
   - §D 5 `/new` 직후 `/agents run`: 기록되고, stale-ctx 수정 뒤 동의 전에 실패하지 않는지.
   - §D 6 `--no-session` 부모 + `AELIX_CODING_AGENT_SESSION_DIR` 설정: 어디에도 파일 없음.
   - §D 7 조기 종료 자식(잘못된 `--model`의 profile): 자식 파일은 header+origin, settle `error`.
   - rpc 채널은 실제 모델로 돈 적이 없다(#123) — stub·argv 테스트뿐.
2. **80열에서 `/cost` 도구 행 줄바꿈**(레인 K Q1): pending+floor 값(`12.3k in / 1.1k out · ≥ $0.0110 (3 runs,
   1 pending)`, 51자) + 라벨 열 24자 > 패널 안쪽 76자. 라벨을 `tools & agents`로 줄이면 들어간다. TUI 라이브 때 결정.
3. **"합계에 이미 포함" 표시**(레인 K Q2): `incl.` 같은 접두어를 붙일지 문구 결정. 지금은 설계 예시대로.
4. **푸터 cost 세그먼트(기본 OFF)는 `cost_known`을 읽지 않는다**(레인 K Q3, 기존 동작) — pending 중에도 `≥` 없이
   숫자. ADR-0243 "Not done here"에 적었다. 후속 이슈 후보.
5. **확장이 쓴 `aelix.usage`도 센다**(레인 K Q4) — ADR-0243 §4에 의도된 동작으로 적었다(`aelix.` 네임스페이스는
   ADR-0242 규칙 1.5상 관례일 뿐 강제되지 않음). 막아야 한다고 보면 결정 필요.
6. **루트 배치 규칙**(레인 D Q1): bucket 모양 규칙을 유지했다. "sessions root 바로 아래만 거부"로 넓히려면
