### Deviations from the spec — read these before slice 2
1. `common.py` NOT created. `fold()` has no caller in slice 1; it lands with powershell.py.
2. `POWERSHELL`/`UNKNOWN` are COMPOSED from the POSIX and CMD tables, not stored. The spec's
   literal "POWERSHELL: union(POSIX)" cannot produce the ADR's own verdict table
   (`sort /etc/hosts` ALLOW *and* `sort in.txt /o out.txt` ASK under POWERSHELL). The rule
   that does: refuse a write switch of ANY base dialect; then decide switch-vs-positional
   with POSIX's sigils under POWERSHELL and the UNION's under UNKNOWN.
3. Dash homoglyphs normalise only in the REFUSE direction (spec §B.6 rule 1 normalises
   unconditionally). Unconditional normalisation turns `date –u` from today's ASK into ALLOW,
   which is fail-open for a MUTATING-positional command.
4. No global casefold on POSIX switches (spec §B.6 rule 1). GNU short options are
   case-sensitive; casefolding drops `sort -V` (--version-sort) out of `short_bool`.
   Casefold is applied only to the `/x` cmd forms, where cmd itself is case-insensitive.
5. Detached short-option values (`-k 2`, `-T /tmp`) are NOT consumed; only attached ones
   (`-k2`). See the `_SwitchGrammar` docstring.
6. `shell_classifiers/__init__.py` imports powershell/cmd INSIDE `classify_for_shell`, not
   at module scope (spec §B.1) — the eager form is a measured ImportError.
7. `_CASES` moved from :43-50 to :44-51 (the test module gained a `Dialect` import). ADR-0237
   line 90 updated to say so.

1. `del/s /q C:\Windows` was ASK. `_cmd_basename` split the name on `/` the way
   a POSIX path does, so the name resolved to `s`. cmd needs no space before a
   switch (`dir/s`, `date/t`, `del/q/s` all run), so `_split_head()` now splits
   the head token on `\` ONLY and hands the `/…` remainder back as a switch
   token. `C:/Windows/cmd.exe` consequently resolves to `c:` and ASKs — the
   fail-safe answer for a spelling cmd itself would not run.
2. `time 12:00` was ASK, not DENY. `common.sensitive_read_target`'s last clause
   reads `<word>:` as a PowerShell provider drive, which is right for
   `Get-Content Env:\Path` and wrong here (`12` parsed as the drive). The check
   is now scoped to `_READS_A_PATH` and runs only on a row that was about to
   ALLOW, so a DENY row can never be raised to ASK by it.

### Deviations from spec §A/§D/§G, each measured, each argued
1. `sort in.txt /o out.txt` is **ASK**, not §G's DENY. §D.4/§D.5 never put it in
   a DENY row; §G alone does, and DENYing an overwrite of `out.txt` while §G
   pins `echo x > out.txt` ASK and `del x` ASK is incoherent. `/o` and `/t` now
   go through the same protected-target predicate a redirect target gets, so

   `test_sort_writes_are_asked_not_denied`.
2. §A.3's "unparsed → an explicit early return to ASK" is implemented as an
   ALLOW-FLOOR, not an early return. §G pins
   `icacls C:\Windows /deny Everyone:(F)` DENY and `(`/`)` is on §A.3's own
   unparsed list; an early return loses that DENY and hands the user a prompt to
   click through. The floor is strictly stricter than either rule alone, and it
   is what makes `de^l /s /q C:\Windows` DENY instead of ASK.
3. `len(_CMD_ALLOW) == 18`, not §D.4's prose "14 rows" (the block names 18

5. `del erase rd rmdir reg icacls takeown cipher schtasks` are in NO tier

6. `<` drops the statement out of the ALLOW tier as "any redirect operator"

7. `_switch_keys` splits a `/`-sigil token on the inner sigil, so `del /q/s x`
