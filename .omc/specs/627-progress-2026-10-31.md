## What changed (final)

- `aelix_coding_agent/agents/sendable.py` (new, product core so `/agents run`,
  RPC and the profile parser can use it without importing the extension):
  `unsendable_character` / `unsendable_refusal` (the TEXT rule: no NUL, no lone
  surrogate), `unencodable_character` / `unencodable_refusal` (the OS rule for a
  string the OS is handed as it stands: no NUL, nothing `os.fsencode` refuses),
  `sendable` (U+FFFD for both), `join_surrogate_pairs`. With `'task'` and "the
  instruction" the refusal is #610's resume sentence, byte for byte.
- `aelix_agents/tool.py`: `parse_agent_call` refuses either character in
  `profile`, `task`, each `tasks[i]`, `cwd` and a resume's `id` before any
  lookup, dialog, budget, record or file; `mode`/`action` keep their value
  checks. `_RESUME_TASK_NOT_TEXT` / `_RESUME_TASK_HAS_NUL` gone.
- `aelix_agents/chain.py`: `render_step` makes a previous step's summary and
  trail sendable (U+FFFD) before the fence.
- `aelix_agents/runtime.py`: `spawn` (before its dialog), `spawn_granted` (before
  the budget) and `resume_granted` (before the target lookup) refuse such a task
  or instruction and an extension-built profile that would break its launch
  (`_launch_refusal`).
- `aelix_agents/print_channel.py`: `resolve_child_cwd` gives a `cwd` the parser's
  sentence under the OS rule.
- `tui/commands.py`, `rpc/control.py`: `/agents run` and RPC `agents/run` refuse
  such a task before they resolve the profile.
- `aelix_coding_agent/agents/profile.py`: `parse_profile` joins escaped
  surrogate pairs after the YAML load and refuses either character in every
  known value and in the body; `unlaunchable_profile` refuses what breaks the
  launch of a profile built in code (the six command-line fields under the OS
  rule, a lone surrogate in the body).
- Tests: `tests/agents_ext/test_agent_unsendable_text_627.py` (94),
  `tests/tui/test_agents_run_unsendable_627.py` (3),
  `tests/rpc/test_agents_run_unsendable_627.py` (5).
- Docs: ADR-0277 header line, amendment section and Limits; the ADR index row;
  a CHANGELOG Fixed entry. `agent-profiles.md` lists no parser refusal, so it
  did not change.

## Reviews

- **Verifier** (lane): no blocker. F1 (low): a profile file's `model:` holding
  either launched after the budget, 4 records and a child file. F2 (low): RPC
  `agents/run` (and `/agents run`) asked a project profile's confirmation before
  refusing the task. F4 (nit): a test cited `/tmp`. F7 (info): an extension's
  `cwd` got the codec's message.
- **Codex** (lane): P2 profile-derived strings (= F1, plus a profile built in
  code); P2 the handlers' order (= F2); P3 `resume_granted` lacked the belt.
- **Fix round 1** fixed all of them: `parse_profile` diagnostics and
  `unlaunchable_profile`; the handlers refuse first; the `resume_granted` belt;
  the `cwd` sentence; the citation.
- **Round-1 delta check:** all items fixed, one regression and three notes. F1
  (medium, regression): `resolve_child_cwd` held a path to the text rule, so on
  Linux every resume under a non-UTF-8 directory was refused ("no longer
  exists"), and an extension's spawn there; measured on Linux in docker,
  simulated on APFS. F2 (nit): the `resolved.name` refusal was untested and
  refused a launch that ran. F3 (info): PyYAML does not join an escaped pair,
  so `description: "smile \ud83d\ude42"` was refused. F4 (info): the ADR said
  round 1 was not run live.
- **Fix round 2** fixed all four: the OS rule for `cwd` (`unencodable_*`); only
  what breaks a launch is refused (name and description not; the body for a
  lone surrogate only); pairs joined after the YAML load; the live runs cited.
- **Round-2 delta check:** no must-fix; R1–R6 below.
