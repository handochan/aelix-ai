## 수정 라운드 1 — 목록

판정 근거: Codex 결과는 위협 모델을 따져 나눴다. 부모 세션 파일이나 세션 폴더에 쓸 수 있는 공격자는 이미 사용자 권한이므로, 그런 반례는 "새 위임보다 넓어지지 않는다"(지금 부모와의 교집합)가 실제 경계다. 그래도 싸게 막을 수 있는 것은 막고, 남는 틈은 Limits에 적는다.

### 코드와 테스트 (레인 R1-code)

- **F1 (스위트).** `tests/cli/test_withdrawn_default_sweep_434.py`의 `_EXPECTED`에 `("aelix_coding_agent/agents/resolver.py", "model_pin_route_moved", "resolve_route")`를 `typed`로 넣는다. 근거: 핀의 문자열은 자식이 argv로 받아 입력값 그대로 해석하는 값이고, 부모의 사전 점검에는 settings seed가 없다. 모듈 관례가 요구하면 "제거된 id를 가리키는 핀도 typed로 해석되어 자식과 같은 답을 낸다"를 구동하는 테스트를 더한다.
- **F2 (Codex 1, 검증 M1).** 천장은 첫 key의 **start 기록**의 `limits`다. `find_resume_target`은 key별 fold(마지막 줄 우선)가 아니라 첫 key의 start 기록에서 `limits`(와 `profile`, `task_preview`)를 읽는다. 같은 key의 다른 기록이 다른 `limits`를 실으면 `resume_damaged(...)`로 거부한다. 테스트: (a) 첫 key에 `granted_mode: yolo`인 settle을 덧붙이면 거부되고 프로세스가 없다. (b) 첫 실행 auto-accept-edits(bash, read, write) → 좁은 부모(plan, read)에서 resume → 넓은 부모에서 다시 resume하면 auto-accept-edits와 bash/read/write로 돌고, 대화상자의 "Earlier task"는 첫 task다(`data = latest.data` 변이를 잡는다).
- **F3 (Codex 3, 검증 m4).** 실행 시점에 대상 전체를 다시 검증한다. `resume_granted`는 `_run` 전에 hook이 쓴 것과 같은 함수로 id를 다시 찾고, 같은 `first_key`·`path`·`limits`를 가진 대상이 나올 때만 진행한다. 아니면 그 조회가 주는 RESUME_* 이유(또는 damaged)로 거부한다. 헤더·origin이 바뀐 파일, 다른 세션으로 바꿔치기한 파일, branch 이동으로 첫 영수증이 사라진 경우가 여기서 걸린다. 자식 파일 점검은 sessions 루트에서 파일까지 **어느 디렉터리 구성요소에도** symlink가 없음을 확인한다(예: 부모의 실경로에서 유도한 `path`에 대해 `os.path.realpath(path) == path`). 테스트: hook 뒤에 파일을 다른 유효 세션으로 바꾸기, 디렉터리를 symlink로 바꾸기, `session.move_to(None)` — 셋 다 거부되고 프로세스가 없다. 마지막 점검과 자식 자신의 open 사이 틈은 남는다(자식은 경로로 연다. `JsonlSessionStorage.open`에는 O_NOFOLLOW가 없다) — 문서 D8.
- **F4 (Codex 4).** 자식 파일의 `st_nlink != 1`이면 거부한다(하드링크 별칭). 테스트.
- **F5 (Codex 5).** cwd 정체성: resume 때 `os.path.realpath(stored_cwd) != stored_cwd`이면 거부한다(RESUME_CWD_GONE 또는 "옮겨졌다"는 변형. 모델에게 새로 위임하라고 말한다). 첫 실행 때 `fresh_limits`가 정규 경로(realpath)를 저장하는지 확인하고, 아니면 정규 경로를 저장한다. 테스트: 디렉터리 이름을 바꾸고 옛 이름에 형제 디렉터리로 가는 symlink → 거부, 프로세스 없음.
- **F6 (Codex 8).** 사전 점검이 자식의 로더와 같은 규칙으로 헤더를 본다: `type == "session"`, `version == 3`, 비지 않은 `id`(요청 id와 같음), 비지 않은 `timestamp`. 규칙은 `aelix_agent_core/session/jsonl_storage.py`의 `_parse_header_line`과 한곳에서 나와야 한다(공유 상수나 helper를 쓰고, 그럴 수 없으면 둘이 같음을 고정하는 테스트를 둔다). 실패는 admission 전에 `resume_damaged(...)`. 테스트: version 999 → 거부, 프로세스·예산·기록 없음.
- **F7 (Codex 9).** resume 파서는 NUL(U+0000)이 든 지시를 lone surrogate처럼 거부한다(모델이 할 일을 말하는 문장). 테스트. `run` 경로의 NUL·lone surrogate는 기존 결함이라 별건 이슈로 간다.
- **F8 (Codex 10, 검증 D11 문서).** resume을 못 하는 채널이면 admission **전에** 거부한다(예산·기록 없음). 채널에 능력 표시(예: PrintChannel `True`, RpcChannel `False`)를 두고 `resume_granted` 또는 `_run`의 admission 앞에서 본다. RpcChannel 자체 거부는 안전띠로 남긴다. 테스트: RpcChannel runtime에서 resume → 거부, 예산 그대로, 기록 없음.
- **F9 (라이브 6, 사용자 의도).** 문구:
  - `RESUME_GUIDANCE`를 조건부로: "…Check the changed files and its tool calls; if it should go on, continue it with agent(action=\"resume\", profile=…, id=…, task=…)." 첫 문장과 `call_literal` 값은 그대로.
  - `CANCEL_REPORT_HEAD`(aggregate.py)에 한 문장: 멈춤은 의도된 것이고, 사용자가 요청할 때만 resume한다. 단일·배치 보고 모두에 맞는 말로. 핀(`test_stopped_child_reports_604.py` 등)을 고친다.
- **F10 (라이브 3).** resume의 disclosure 줄이 resume임을 말한다: 예 "resuming <name> at <mode>, from <source>"("1 task" 없음). `build_disclosure_line`에 keyword 인자, `_grant_for`의 resume 경로에서 사용. 테스트 핀.
- **F11 (라이브 10).** resume 대화상자의 Permission 행은 첫 실행의 grant가 그 행의 모드보다 높을 때 같은 행에 그것을 적는다. 예 `Permission: plan (first run: auto-accept-edits)`. 행 수는 그대로. 테스트 핀.
- **F12 (검증 m5).** id가 "the Session line of its result"에 있다고 말하는 모델용 문장(tool.py의 `action`·`id` 설명과 description head)이 배치 멤버(heading의 `· session <id>`)도 덮게 고친다. 2048바이트 head 예산 안에서. head 예산·action 핀을 고친다.
- **F13 (검증 m6).** `RESUME_NO_SESSION`, `RESUME_UNREADABLE`, `RESUME_LOCK_ERROR`, `RESUME_CONVERSATION_CHANGED`에 모델이 할 다음 일을 붙인다(다른 거부처럼 "Delegate the task anew." 또는 다시 시도할 때). 핀을 고친다.
- **F14 (검증 m1, m2).** 테스트: (a) `sub-[0-9a-f]{12}`가 아닌 첫 key(`..` 포함)는 경로를 만들기 전에 거부된다(`if False:` 변이를 잡는다). (b) resume의 registry 행은 insert 때 `session_id`를 갖는다(`session_id=None` 변이를 잡는다). (b)가 동시성 장치를 요구하면 insert된 행을 직접 보는 단위 테스트면 된다.
