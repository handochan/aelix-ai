## §1 Deviations from the design

1. **The interleaving test yields in the middle of each line, not only before it.**
   §A.6 says the `append_file` subclass does `await asyncio.sleep(0)` "before
   writing". With only that yield, each line is still written by one uninterrupted
   call, so the test passes with the lock removed — it would not pin the lock.
   `_YieldingFs` yields before AND between two halves of the line. Mutation
   measured: `self._lock = contextlib.nullcontext()` →
   `FAILED …::test_concurrent_appends_are_serialized_whole_lines_in_call_order`
   (`JSONDecodeError`), `1 failed, 100 passed`.

2. **An extra test pins "a fork is one publish":**
   `test_a_fork_is_one_publish_never_an_append_loop[fork|fork_from]` (a counting
   `LocalFileSystem`; exactly `[write_file <name>.tmp, rename_file <name>]`, no
   `append_file`). Needed because the design's injections (half `write_file`,
   failing `rename_file`) fail inside `create`'s publish, and the OLD fork shape
   (header, then `append_entry` per entry) also starts with that publish. Measured:
   reverting `fork` to the append loop left every §A.6-listed test green (pytest
   rc 0); with the spy test, `FAILED …::test_a_fork_is_one_publish_never_an_append_loop[fork]`.

3. **The fork tests use short synthetic cwds (`/src`, `/dst`),** as
   `tests/test_jsonl_repo_fork.py` does. Found while writing the success-path test:
   `find_most_recent` sniffs only a file's first 512 bytes, and a fork's header
   carries its cwd AND `parentSession` (which embeds the encoded source cwd again).
   Under a long `tmp_path` a complete fork's header passed 512 bytes, so
   `find_most_recent` returned `None` for a successful fork — which would also make
   the failure tests' `find_most_recent(dst) is None` pass for the wrong reason. The
   success test (`recent.path == path`) proves the chosen setup IS found. The
   underlying defect is pre-existing and not fixed here — §3.1.

4. **Torn-tail sweep — which offsets.** The load half runs at every cut
   `c ∈ [1, len(J)-1]` of every entry line of the catalogue session (full sweep,
   0.79 s locally). The append-then-reload half runs at five offsets per line
   (1, 2, middle, len-2, len-1). The design allowed sampling and asked to say which.

5. **Pins beyond §A.6, each for a claim the design makes without a test:**
   `create(entries=…)` writes the same bytes as header-then-append (only the header
   timestamp may differ — the critic had checked this with a patched probe); the
   string `"false"` for `display` reads as `True` (§A.1.3b); a header `version` of 4
   refuses the whole file (§A.1.3); a write that makes no progress raises `EIO`
   (§A.3); an `asyncio.CancelledError` twin next to the `KeyboardInterrupt` one
   (§A.3 names both). The unknown-key fork pin checks all five rows of the §A.1.3
   table (header, entry, message and content-block keys dropped; `data` kept), for
   `fork` and `fork_from` both.

6. **`O_BINARY` also on `copy_file`'s fsync reopen.** §A.4 lists `append_file`,
   `write_file` and the temp's creation; the reopen is also a write descriptor
   (used only for `fsync`). Harmless, and keeps "every write descriptor is binary"
   literally true.

7. **The citation fixer touched two files outside the change list:**
   `packages/aelix-coding-agent/src/aelix_coding_agent/_export_html/format.py` and
   `tests/coding_agent/test_export_html.py`, both `session/fs.py:27-28` → `28-29`

   `session_cwd.py` was re-derived by hand, `session/fs.py:57-81` → `86-117`

   `compaction.py`'s `session/entries.py:64-80` did not move.

8. **Probe output format.** On the branch, `[2]`'s error line prints the file's

9. **The ADR quotes §0 verbatim and says separately** that the committed probe adds

## §3 Open questions for the lead

1. **Pre-existing, not fixed: `find_most_recent` cannot see a session whose header
   is over 512 bytes.** `JsonlSessionRepo._is_valid_session_file` reads 512 bytes
   and parses the first line; a fork's header holds its `cwd` plus a
   `parentSession` path that embeds the encoded source cwd again, so in a deep
   project directory `--fork` then `--continue` resumes the older source session
   instead of the fork. Measured identically on `main` `e1fef5f` and the branch
   (scratch probe: 120-char cwd → fork header 671 bytes, `find_most_recent(dst)` =
   `None`; the 316-byte source is found), and live in §2 item 4 (fork header 571
   bytes). pi's current reader takes the whole first line (`readJsonlHeader`,
   `jsonl/io.ts`). Follow-up candidate; it also means the `is None` assertions in
   any future fork test need short cwds (§1.3).
2. **Pre-existing, not fixed: a foreign session file torn inside a multi-byte UTF-8
   character fails the whole load with `UnicodeDecodeError`** (`read_text` is
   strict, and the loader catches only `OSError`) instead of skipping the torn line.
   Aelix's own files cannot hit it — `json.dumps` writes ASCII — but a pi export is
   raw UTF-8, so `/import` of a torn one does. Measured with a hand-made file: same
   error on `main` and the branch. Follow-up candidate.
3. **Windows is verified by CI only.** The `O_BINARY` change is asserted by
   `test_every_write_is_one_append_file_call_holding_one_line` (`b"\r" not in raw`),
   which on POSIX passes with or without the flag; only the windows-latest leg
   proves it. Same for `copy_file`'s `O_EXCL` / `fsync` / `os.replace` on NTFS. I
   have no Windows box — please read those legs. The torn-tail sweep writes about
   6k small files; 0.79 s here, expect a few seconds on Windows.
4. **Codex cross-review (CLAUDE.md rule 8)** was not done in this lane; this is the
   implementer pass. The full suite was not run here, by instruction.
5. **Widen `invalid_entry` to `entry_to_json`?** A `MessageEntry` whose `message`
   is not a dataclass still raises a raw `TypeError` from `asdict` (nothing written,
   state unchanged). The design scoped the translation to `json.dumps`; I kept to it.
6. **Follow-up candidates carried from the design's §C, not verified here:**
   `!cmd` output recorded as a `bash_execution` CustomEntry that
   `build_session_context` skips, while `handle_user_bash`'s docstring says it is in
   context; `AgentSessionRuntime.fork(<root user msg>, position="before")` passes
   `entry_id=None` and gets a full copy; `flush_pending_session_writes` swaps its
   queue out before draining, so one failing write drops every queued write after
   it; `PendingCustomMessageWrite.content` holding dataclasses fails to persist (now
   `invalid_entry` rather than a raw `TypeError`); keeping unknown entry types as
   opaque nodes (pi v3's `active_tools_change` makes `/import` of such a pi session
   prune today).
