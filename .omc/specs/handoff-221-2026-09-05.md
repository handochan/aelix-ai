- #220의 §A.3(b)(print 자식 exit 143), Codex 리뷰 부채, `taskkill` 5 s, #204 편차, #110, `powershell -enc` — 그대로.

## 3. 이 레포에서 이번에 물린 것

1. **`process_group=0` 자식은 tty를 열 수는 있어도 읽을 수 없다.** 읽으면 SIGTTIN, `tcsetattr`이면 SIGTTOU로 그룹 전체가 **정지**(`ps stat T`), 프롬프트는 출력조차 안 된다. ADR-0238의 `HAVE_TTY`는 open만 잰 것. #226.
2. **"헬퍼는 파이프 EOF로 알아서 죽는다"는 거짓.** `git remote-http`는 libcurl에서 블록된 채 git의 죽음을 모른다 — 3 s 후에도 `ppid 1`로 생존(§5).
3. **`asyncio.to_thread` 워커의 `run_contained`에는 어떤 시그널도 취소도 닿지 않는다.** 봉쇄가 tty의 ^C까지 막으면 프로세스가 명령의 남은 수명을 기다린다. `CancelledError`를 잡아 다른 스레드에서 트리를 죽이는 핸들(`AbortHandle`)이 답이고, "kill만 보내고 기다리지 않는다"가 핵심.
4. **pytest 기본 `--capture=fd` 아래서 fd 0은 `/dev/null`이다.** fd 0에 읽을 바이트를 심어야(`os.pipe`+`dup2`) 상속이 관측된다. **CI 러너에는 controlling terminal이 없어** `/dev/tty` ENXIO는 세션 판별자가 아니다 — `getsid`로 판별한다.
5. **post-kill drain의 재무장은 동기 write로는 못 핀한다.** kill 20–50 ms 뒤 스레드에서 쓰고 grace를 넓혀야 결정적.
6. **대칭 slack은 상수 차이를 못 잡는다.** 바닥(`>= 0.3`)이 주장이고 천장은 스케줄링 몫.
7. **`_run_bounded`의 bound에 `REAP_GRACE`를 더하면 rev-1 회귀(6 s)가 통과한다.** bound는 `timeout + KILL_DRAIN + 1.5`.
8. **워크플로우 레인이 세션 리밋으로 파일을 반쯤 쓰고 죽는다** — 반쯤 된 상태를 그 레인의 프롬프트에 적고 `resumeFromRunId`로 재개. 템플릿 리터럴 안에 백틱 금지.
9. **haiku는 툴 두 개를 병렬로 부른다** — 라이브 프로브는 한 툴 호출 안에서 순차 실행.
10. **`ruff format --check .`는 main에서도 588파일 빨감** — CI는 `ruff check`만 돈다.
11. **`git show main:<f> | ruff format --check --stdin-filename`** 로 "이 브랜치가 만든 포맷 hunk"만 골라낼 수 있다.
12. **win32 텍스트 레이어는 `print`·`sys.stdout.write` 둘 다 `\r\n`을 쓴다.** 실제 자식의 출력 바이트를 정확히 단언하려면 자식이 `sys.stdout.buffer`로 쓰거나 같은 argv의 `subprocess.run`과 비교한다. 첫 CI run이 정확히 이걸로 빨갰다(§10.1). `python -c "sys.stdout.reconfigure(newline='\r\n'); sys.stdout.buffer.write(b'x\n'); print('y')" | od -c`가 메커니즘.
13. **`gh run view --log`는 run 전체가 끝나기 전엔 잡 로그를 안 준다** — `gh api repos/<o>/<r>/actions/jobs/<id>/logs`는 끝난 잡이면 준다. windows 한 레그가 죽었는데 다른 레그가 15분 더 돌 때 그 15분을 아낀다.
14. **`/clear`는 백그라운드 작업을 안 죽인다** — 이전 컨텍스트의 `gh run watch`가 같은 `claude` PID 아래 살아 있었고, 스크래치패드 경로는 project-memory의 `test=` 줄에 남는다. handoff에 `__MAIN__`/`__CI__` 자리표시자가 있으면 마감 단계 전부가 안 된 것이다.
15. **`_PipeReader`를 반환 뒤에도 그냥 두면 메모리가 홀더 수명만큼 자란다** — "리더는 EOF까지 블록될 뿐"이라는 §A.5의 가정은 *조용한* 홀더에서만 참. detach는 읽기를 멈추지 않는다(멈추면 64 KiB 파이프가 차서 그 헬퍼가 정지 — M1b 변이가 `BrokenPipeError`로 빨감).
16. **스폰 직후 ~첫 `try` 사이의 마이크로초는 비어 있지 않다** — SIGALRM으로 40 µs 전에 `KeyboardInterrupt`를 넣으면 12/12 트리 누수, 50 ms 뒤(덮인 `try` 안)면 0/6. 벨트는 트리가 생기기 전엔 root-only가 전부다.
17. **"5 s 안에 죽었다"는 5 s 자는 자식으론 못 잰다** — 폴 창과 자식의 수명이 같으면 kill 없이도 초록(R3). 자식은 폴보다 훨씬 오래 살아야 하고, `strays` 픽스처가 그 자식을 거둔다.
18. **auto-mode 분류기는 `sed && git add && git commit --amend` 체인을 막는다** — add / commit / push를 각각 한 명령으로.
19. **Workflow 규모**: 첫 컨텍스트 — 설계 반박 88 agent·7.1M·55 min, 구현 4·0.72M·66 min, 구현 리뷰+변이 47·3.95M·52 min, 수정 4(+재개)·0.9M·78 min. 이어받은 컨텍스트 — 병합 전 리뷰 44·4.2M·42 min(BLOCKING 2·MAJOR 4·MINOR 3 성립, 11건 반박됨), 수정 3·0.46M·30 min. BLOCKING/MAJOR는 이번에도 전부 opus 반박 레인에서. 모델을 내려 쓰지 말 것.

## 4. 반증된 것 — 다시 믿지 말 것

- ❌ "ADR-0238이 잰 `HAVE_TTY`는 credential helper가 tty에서 프롬프트할 수 있다는 뜻" — open만 됐다; 읽기는 정지(§3-1).
- ❌ "`git remote-http`/ssh 헬퍼는 git이 죽으면 파이프 EOF로 곧 죽는다" — 3 s 후에도 생존(§5).
- ❌ "`GIT_TERMINAL_PROMPT=0`이면 clone이 즉시 실패한다"(rev 1) — git은 `GIT_ASKPASS`/`core.askPass`/`SSH_ASKPASS`를 **먼저** 보고 마지막에 그 변수를 본다.
- ❌ "idle 타이머는 마지막 청크부터 재면 된다"(rev 1) — Pi는 exit에서 무장한다.
- ❌ "kill 뒤 리더를 `reap_grace` 남은 만큼 join하면 꼬리를 모은다"(rev 1) — 트리 밖 holder가 있으면 5 s를 헛되이 쓰고 바이트 0.
- ❌ "Pi의 SIGTERM→5 s→SIGKILL이라 1 s 타임아웃이 6 s에 돌아온다"(rev 1) — Node는 **보내는** 순간 `killed`를 세우므로 에스컬레이션이 아예 안 뜬다.
- ❌ "git이 끝난 뒤 살아 있는 멤버는 정의상 stray"(rev 1) — `git credential-cache--daemon`은 `setsid` 없이 스폰되어 그룹 안에 남는다.
- ❌ "`kill_on_close=True`가 없으면 win32 누수가 돌아온다"(PI-4) — 이슈의 누수는 타임아웃 경로.
- ❌ "`subprocess.run`의 POSIX 타임아웃은 partial output을 싣고 win32는 `None`"(rev 2 §A) — 반대다.
- ❌ "인터럽트 레그가 `aelix -p`의 exec에 닿는다"(rev 2 §A.3.2) — 워커 스레드에는 시그널이 안 온다; `AbortHandle`이 답.
- ❌ "git의 no-tty 메시지는 `No such device or address`" — darwin은 `Device not configured`.
- ❌ "이 명령들은 비대화형이다"(무조건) — **POSIX 문장이다.** win32는 세션이 없어(`CREATE_NEW_PROCESS_GROUP` + job) 자식이 콘솔을 그대로 물고, git은 `CONIN$`를 읽는다(R4). 첫 컨텍스트가 코드 주석 두 곳에는 맞게 썼는데 사용자 표면 다섯 곳에 전파하지 않았다.
- ❌ "`DRAIN_CAP_SECONDS`가 수다스러운 홀더의 비용을 bound한다" — 호출자의 대기만 bound했고 리더는 반환 뒤에도 append했다(R1).
- ❌ "인터럽트 레그가 스폰 이후 전부를 덮는다"(rev 2 docstring) — attach~리더 시작 창이 비어 있었다(R2).
- ❌ "handoff-221이 적은 '10207 passed'는 최종 트리의 수" — `e0ffeae`의 수였고 최종 트리는 10212(테스트 5건 추가).
- ❌ "이 머신에 fd가 있다" — 없다(`fd`, `fdfind` 둘 다). TUI가 `_fd_enumerate`를 타게 하려면 PATH에 넣어야 한다.
