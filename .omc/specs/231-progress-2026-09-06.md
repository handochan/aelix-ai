## 5. Deviations from the design

1. **Case 5 needed a second seam.** §C names `monkeypatch.setattr(cli.config, "get_bin_dir", …)` as
   the one seam for cases 1–5. It is not enough for case 5: the repo-wide autouse
   `_no_real_tool_downloads` in `tests/conftest.py` replaces `tools_manager._bin_dir` with a
   per-session temp dir, so `get_tool_path("fd")` never sees the patched `cli.config`. Measured —
   `_bin_dir()` returned `…/pytest-2702/aelix_bin0`, `get_tool_path("fd")` `None`. Case 5 therefore
   also does `monkeypatch.setattr(tools_manager, "_bin_dir", lambda: str(bin_dir))`. `monkeypatch`
   is function-scoped and the last write wins, so this re-stub overrides the session fixture for
   this case and is undone with it. (Corrected 2026-09-06 in §8: the original wording here claimed
   "that fixture's own docstring licenses" the re-stub and quoted it — that docstring does not
   exist and no fixture carries that wording.) The pin is unchanged: same bin dir on both sides,
   a decoy `fd` on PATH, and it was RED on `main`.
2. **`ruff format` on the two named files touched pre-existing lines.** Neither file was
   `ruff format`-clean on `main`, so §F's format line reformatted 8 hunks that have nothing to do
   with #231 (collapsed multi-line signatures in `FileMentionCompleter.__init__`,
   `_list_directory`, `_complete_union`, and four `assert […] == […]` blocks). The design names
   exactly these two files, so the churn was kept rather than reverted; it is confined to files only
   this issue touches. If the orchestrator prefers a clean diff, reverting those 8 hunks is safe —
   CI does not enforce `ruff format`.
3. **The §H M4b symlink arm ran with real symlinks** on this box, so case 8's
   `warnings.warn` fallback branch is unexercised here; it exists for the Windows leg and is
   **not measured** on any platform yet.
4. Nothing else. §B's code is as drafted (the `# noqa: PLC0415` dropped, `# noqa: BLE001` kept),
   §D's load-bearing sentences are copied, and no `file:line` citation was added.

### 8.4 Behaviour note the orchestrator should carry into the commit message

Item 2 changes a real behaviour, deliberately: **a managed `fd` that exists but cannot be spawned
now wins over a PATH `fd`, and the menu falls back to the walk.** That is contract-consistent —
the `find` tool fails on the same copy, which is the whole point of the two resolvers agreeing —
and it is already pinned by `test_fd_failure_falls_back_to_walk`. Silently running a *different*
`fd` from PATH was the old behaviour and was the defect.

### 8.5 §5 addendum — CM-5 (ii) accepted as a perf-only gap

Deleting the walk's `dirs[:] = [d for d in dirs if d not in _EXCLUDE_DIRS]` prune leaves every
shipped case green, because the shared post-filter in `_enumerate_tree` removes the same paths from
the returned set. That surviving mutation is **accepted, not closed**: the prune's value is that
`os.walk` never DESCENDS an excluded tree, which is a cost property (walk time, inodes touched, and
the `_TREE_ENUM_CAP` budget) and not an observable property of the answer. Closing it would mean
lowering `_TREE_ENUM_CAP` to make the cap-spend observable, which trades a real contract pin for a
mutation score. Left as-is.
