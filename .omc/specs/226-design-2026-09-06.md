## §A. Decision

**`process_group=0`은 그대로 두고(ADR-0238의 결정 유지, 근거 교체), 정지를 탐지해서 이름 붙여 실패한다.**

1. **근거 교체 — 세 다리.** ADR-0238과 두 docstring은 "`setsid`는 tty를 잃으니 `process_group=0`"이라
   적혀 있다. 측정이 좁힌다: `process_group=0` 자식은 `/dev/tty`를 **열 수 있을 뿐 읽을 수
   없다**(§H #4·#6). 옳은 근거는 세 개다.
   (a) tty를 **controlling terminal로** 유지해 실패가 **관측 가능한 정지**가 된다.
   (b) `setsid`는 정지 대신 **조용한 절도**를 만든다(§A.2).
   (c) **kwarg를 아예 빼면(그룹 상속) SIGTTIN이 그룹 전체에 배달되어 Aelix 자신이 멈춘다** —
   실측(darwin, 실제 pty, 클린 `main`): 백그라운드의 Aelix + 헬퍼 그룹 상속 → 둘 다 `T`,
   **20 s 뒤에도 `T`**, `_COMMAND_TIMEOUT`은 영영 안 뜬다(정지된 프로세스에는 폴 스레드도 없다).
   `SIGCONT`으로도 안 돌아온다 — 재개 즉시 다시 읽어 다시 정지. `fg`를 치는 사람만 끝낼 수 있다.
   같은 조건에서 `process_group=0`은 Aelix가 `S`로 살아 있고 실패는 10.01 s에 바운드된다
   (탐지기와 함께 0.06 s). §H #30·#31. **다만 Aelix가 포그라운드면** 같은 mutant는 안 멈추고
   헬퍼가 사용자가 친 줄을 먹는다(§H #32) — "항상 더 나쁘다"가 아니라 "실패할 때 가장 나쁘다"이다.
2. **옵션 1(`setsid`) 기각 — 측정으로.** `setsid` 자식은 `/dev/tty`에 즉시 실패하지만(§H #5·#7),
   **경로로 여는 헬퍼**(`$GPG_TTY`, `/dev/ttysNNN`)에겐 job control이 아예 안 걸린다. 측정: `Ss`로
   조용히 기다리다 **사용자가 터미널에 친 줄을 자기가 먹었다**(§H #10); 같은 명령이
   `process_group=0`에서는 `T`이고 아무것도 못 가져간다(§H #11). #222 §3-1과 같은 모양 —
   **정지는 보이고 절도는 안 보인다.**
3. **옵션 2(`tcsetpgrp`) 기각 — 이제 논증이 아니라 측정으로.** 프롬프트는 실제로 산다: foreground를
   헬퍼 그룹에 넘기면 `read x < /dev/tty`가 사용자가 친 줄을 받고 터미널도 되돌아온다(rc 0, 1.026 s,
   §H #46). 그런데 넷이 딸려 온다. (a) **1 ms 미만의 경쟁이다** — 1 ms만 늦어도 헬퍼는 이미 `T`이고
   foreground를 줘도 안 깨어난다; `SIGCONT`를 같이 보내야 하는데 **언제 보낼지 아는 방법이 곧 옵션 3의
   탐지기다**. 실제 여유는 `attach`+`thread.start` 중앙값 0.089 ms(§H #47). (b) **버려진 프롬프트가
   이 이슈의 10 s를 도로 불러온다** — handover 아래서는 `stty -echo`가 **성공**해 정지가 없다: 이름
   없이 풀 타임아웃 + 잡히지 않는 `SIGKILL` → **터미널이 echo 꺼진 채 남는다**(§H #48). 옵션 3에서는
   같은 헬퍼가 `tcsetattr` 적용 전에 0.020 s에 멈추고 터미널은 멀쩡하다. (c) **TUI에서는 "의미가
   없는" 게 아니라 Aelix가 멈춘다** — 3단 job control에서 aelix 자신의 stdin read가 SIGTTIN 0.021 s,
   prompt_toolkit raw-mode `tcsetattr`가 SIGTTOU 0.021 s(§H #49). 인증은 세션 중간에 스트림마다
   풀리므로 살아 있는 경로다. (d) background에서의 `tcsetpgrp`는 우리를 0.052 s에 멈춘다(§H #50).
   🔴 **`^C`가 자식으로 간다는 원래 반대 이유는 틀렸다** — 실측: `^C`는 프롬프트만 끊고 에이전트는
   산다. 그 문장은 지운다. 기각의 근거는 (b)와 (c)다.
4. **옵션 3 채택.** `reader.join(_COMMAND_TIMEOUT)`를 50 ms 폴 루프로 바꾸고 폴마다
   `os.waitpid(pid, WNOHANG|WUNTRACED)`로 `WIFSTOPPED`를 본다. `WSTOPSIG`이 `SIGTTIN`/`SIGTTOU`면
   즉시 `tree.hard_kill()` + **이름 붙은 원인**. 실측 **10.0 s → 0.054 s**(darwin, §H #8·#15),
   **0.052–0.059 s**(linux/dash, py3.11·3.12 × root/비루트 × aarch64/amd64, §H #38).
5. **파이프라인은 놓치지 않는다.** 두 신호는 프로세스가 아니라 **그룹**에 배달된다.
   `sh -c "read x </dev/tty | cat"`에서 리더 `sh`도 `T`가 되고 리더의 `waitpid`가 본다(§H #8).
   이게 **dash에서 특히 중요하다**: dash는 `-c`의 단일 명령을 exec하지 않으므로 게이트 레그에서
   헬퍼는 **항상** 리더 쉘의 자식이다(§H #40). 그래도 탐지된다(§H #38의 파이프라인 수).
6. **프로브가 지불하는 두 가지 대가 — 둘 다 적는다.** 이미 EXIT한 자식에 `waitpid`를 부르면
   (a) `Popen`이 가져갈 상태를 우리가 먹고 `Popen._try_wait`가 `ChildProcessError`를 `sts = 0`으로
   삼킨다 — 실측 **exit 7이 exit 0으로 보고**(§H #12). 그래서 exit를 보면
   `proc.returncode = os.waitstatus_to_exitcode(status)`로 돌려준다(§H #13). **이 절도는 아무 때나
   닿지 않는다**: `!exit 7`처럼 리더 exit와 리더 EOF가 같은 틱에 오면 루프가 프로브 전에 깨진다
   (실측 probes=0). 손자가 파이프를 쥔 채 루트만 exit하는 모양에서만 열린다(§H #36).
   (b) **좀비를 소비하므로 pgid 핀이 풀린다.** 그룹의 마지막 산 멤버가 리더였으면 첫 폴(실측
   0.055 s)에 그룹이 비고, `hard_kill`이 `_COMMAND_TIMEOUT`에 쏘는 `killpg`는 **주인 없는 번호**를
   겨눈다 — darwin `ESRCH`/멤버 `EMPTY`, linux 동일(§H #22·#23). 소비자는 **프로브이지 handoff 줄이
   아니다**(handoff를 지워도 ESRCH, §H #24). 그 모양에서 `killpg`는 `main`에서도 이미 무의미했고
   (자손이 양쪽 arm 모두 생존), 잃는 것은 없고 **생기는 것은 ADR-0238이 이미 수용한 재사용 위험의
   ~9.95 s 창**이다. 그룹 안에 남은 자손이 있으면 여전히 핀된다(실측 `CLAIMED`).
   `os.waitid(…, WNOWAIT)`는 좀비를 안 먹고 정지도 반복 통보하지만 **darwin에 없다**(§H #25).
   **플랫폼 분기를 하지 않는다**: 게이트 POSIX 레그가 linux뿐이라 분기하면 위험한 쪽(darwin의
   reap-repair)이 CI에서 한 번도 안 돌게 된다. 하나의 경로, 두 레그에서 같은 테스트. 대가는
   `_process_tree.py`와 ADR-0238의 문장 하나씩을 고쳐 적는 것이다(§B.2, §D.3).
7. **비용 없음.** 프로브 0.20 µs/call(10 s 명령 전체에 40 µs), 해피 패스 main 3.13/3.56 ms vs
   proto 3.03/3.60 ms(n=200 ×2) — 노이즈 안(§H #16·#17).
8. **바뀌지 않는 것:** 터미널과 무관한 정지(`kill -STOP $$`)는 이름 없이 타임아웃 그대로(§H #19).
   **gpg-agent가 중재하는 passphrase 프롬프트도 그대로다**(§A는 이걸 못 본다 — §G). win32는
   `WUNTRACED`도 background group도 없어 탐지기가 **무동작**이다.

## §B. Code changes

### B.1 `packages/aelix-ai/src/aelix_ai/oauth/_resolve_config.py`

```python
_STOP_POLL_SECONDS = 0.05           # 측정: 탐지 0.052–0.059 s = 1 quantum (darwin·linux)
_TERMINAL_STOP_SIGNALS = {          # signum -> (이름, 무엇을 하다 멈췄나). win32엔 둘 다 없다
    int(sig): (name, what)
    for name, what in (("SIGTTIN", "reading the terminal"),
                       ("SIGTTOU", "changing the terminal's settings"))
    if (sig := getattr(signal, name, None)) is not None
}
_WAIT_STOP_OPTIONS = (
    (os.WNOHANG | os.WUNTRACED)     # pyright: ignore[reportAttributeAccessIssue]
    if hasattr(os, "WUNTRACED") else 0
)

@dataclass(slots=True)
class _Failure:
    """NAMED 원인이 `None`을 세 번 반환하는 경로를 통과해 돌아올 자리."""
    reason: str | None = None
    returncode: int | None = None    # 정지 분기에서만 채운다 (실측 -9 = -SIGKILL)

class _StoppedByTerminal(subprocess.CalledProcessError):
    # 기존 `except CalledProcessError`가 전부 그대로 잡는다. `__str__`가 원인을 잇는다.
    # `__all__`에 넣지 않는다: 새 공개 타입이 아니라 메시지가 늘어난 것이다.
    def __init__(self, returncode, cmd, reason): ...   # self.reason = reason
    def __str__(self) -> str: return f"{super().__str__()} {self.reason}"

def _stopped_by_the_terminal(proc, *, platform=None) -> tuple[str, str] | None:
    """`proc`를 STOP시킨 job-control 신호의 (이름, 서술), 아니면 None. POSIX 전용."""
    if _resolve_platform(platform) == "win32" or _WAIT_STOP_OPTIONS == 0:
        return None
    try:
        pid, status = os.waitpid(proc.pid, _WAIT_STOP_OPTIONS)
    except (ChildProcessError, OSError):
        return None
    if pid == 0:
        return None
    if os.WIFSTOPPED(status):        # pyright: ignore[reportAttributeAccessIssue]
        return _TERMINAL_STOP_SIGNALS.get(
            os.WSTOPSIG(status)      # pyright: ignore[reportAttributeAccessIssue]
        )
    if proc.returncode is None:      # ← 훔친 reap을 돌려준다 (§A.6-a, §H #12/#13)
        proc.returncode = os.waitstatus_to_exitcode(status)
    return None
```

🔴 **세 개의 `# pyright: ignore[reportAttributeAccessIssue]`는 선택이 아니다.** `os.WNOHANG` /
`WUNTRACED` / `WIFSTOPPED` / `WSTOPSIG`은 Windows typeshed에 없고, `pythonPlatform`은 호스트를
따르므로 darwin의 `uv run pyright`는 **구조적으로** 이걸 못 본다 — 게이트하는 windows 레그에서만
4 errors로 빨강이고, 그것도 pytest 전 3/4단계에서 터진다(§H #34). `_process_tree.py`가 아홉 개의
POSIX 전용 호출에 쓰는 것과 같은 규칙·같은 철자다. `os.waitpid`와 `os.waitstatus_to_exitcode`는
Windows typeshed에 있으므로 억제 불필요.

`_run_shell_command(cmd, *, failure: _Failure | None = None)` — `reader.join(_COMMAND_TIMEOUT)`
**한 줄만** 교체하고 kill 분기는 하나로 합친다:

```python
deadline = time.monotonic() + _COMMAND_TIMEOUT
stopped: tuple[str, str] | None = None
while True:
    reader.join(_STOP_POLL_SECONDS)
    if not reader.is_alive() or overflow or time.monotonic() >= deadline:
        break
    stopped = _stopped_by_the_terminal(proc)
    if stopped is not None:
        break

if stopped is not None or reader.is_alive() or overflow:
    if stopped is not None and failure is not None:
        name, what = stopped
        failure.reason = (
            f"The command stopped {what} ({name}): a !command runs in a process group of "
            "its own, which is never the terminal's foreground group, so the kernel stops "
            "it the moment it touches the terminal — it cannot prompt you. Use a helper "
            "that needs no terminal: an askpass program, a GUI pinentry, or the OS keychain."
        )
    tree.hard_kill(); ...                 # 기존 타임아웃 분기 그대로 (bounded wait + join)
    if stopped is not None and failure is not None:
        failure.returncode = proc.returncode      # 실측 -9
    return None
```

🔴 **문자열이 이 이슈의 산출물이다. 세 가지가 실측으로 정해졌다.** (i) `models.json`을 이름으로
부르면 안 된다 — **캐시 경로(`resolve_config_value`)의 유일한 프로덕션 호출자는
`auth_storage.py`의 `get_api_key`/`get_api_key_cascade`, 즉 `auth.json`의 `key`다**(실측: 레포
전체에 호출자 둘, 둘 다 그 파일). (ii) "터미널이 없다"고 하면 안 된다 — 같은 커밋의 ADR이
"controlling terminal로 **유지**한다"고 적는다. 있는데 못 읽는 것이다. (iii) "process group of its
own"은 남긴다 — 그룹이 왜 거기 있는지 유지보수자가 읽을 유일한 문장이고, "foreground process
group"만으로는 사용자에게 은어다.

나머지 세 홉은 **선택적 키워드 하나씩**만 는다(공개 시그니처 하위호환):

- `_execute_command_uncached(value, *, failure=None)` → 그대로 전달.
- `resolve_config_value_uncached(value, *, failure=None)` → 그대로 전달. "절대 raise 안 함" Pi 계약 유지.
- `resolve_config_value_or_throw` → `failure = _Failure()`를 넘기고 Pi-verbatim 메시지를
  **접두사로 유지**한 뒤 `f"{msg} — {failure.reason}"`로 잇는다. 원인이 없으면 오늘 문자열 그대로.
- `resolve_config_value`(캐시 경로) → `failure.reason`이 있으면
  `_StoppedByTerminal(failure.returncode, …)`, 없으면 오늘과 같은 `CalledProcessError(… else -1)`.
  🔴 **정지 분기에서만 returncode가 `-9`가 된다.** 오늘 그대로면 렌더가
  `died with <Signals.SIGHUP: 1>. The command stopped … (SIGTTIN)` — 한 숨에 신호 두 개를 부른다
  (실측, §H #45). `-signal.SIGKILL`은 `hard_kill`이 실제로 보낸 것이라 장식이 아니다.
  일반 타임아웃/오버플로 분기는 오늘의 `-1` 그대로.

### B.2 `packages/aelix-ai/src/aelix_ai/utils/_process_tree.py` — 주석만

세 곳을 §A의 교정된 근거로 바꾼다. 코드 변경 없음.
1. 모듈 docstring의 "The second is what `!command` credential helpers need — … `sh: /dev/tty:
   Device not configured`" 문단. 🔴 **`Device not configured` 문자열을 그대로 옮기지 말 것** —
   darwin 전용이고 dash는 `cannot open /dev/tty: No such device or address`다(실측). ADR-0238의
   #221 amendment가 이미 같은 이유로 인용을 피한다. 동작을 적고, 문자열을 인용하려면 플랫폼을 붙인다.
2. `containment_spawn_kwargs` docstring의 "so a credential helper behind `!command` can still open
   `/dev/tty`" 문장, 그리고 같은 shorthand를 쓰는 모듈 docstring의 "so the terminal survives" /
   "SAME session, tty kept"에 같은 한정어를 단다.
3. 🔴 **THE PID/PGID HAZARD 문단**("``!command`` is the one site where the literal claim holds:
   a synchronous ``Popen`` nothing has waited on, so the zombie pins the number.") — §A.6-b가
   이 문장을 거짓으로 만든다. 교체 취지: *#226까지는 그랬다. 터미널 정지 탐지기가
   `waitpid(WNOHANG|WUNTRACED)`로 폴하고, 이미 exit한 리더를 **reap한다** — 그룹의 마지막 산 멤버가
   리더였으면 그 exit 뒤 첫 폴(실측 0.055 s)부터 `hard_kill`의 `_COMMAND_TIMEOUT`까지 ~9.95 s 동안
   pgid가 비어 있다. 이 사이트는 이제 asyncio 사이트들을 바운드하는 쪽이 아니라 그들과 같은 편이다.
   그룹에 남은 자손이 있으면 여전히 핀된다(실측).*

     `!command` cannot prompt you. It runs in a process group of its own — never the terminal's
     foreground group — so the kernel stops it the moment it reads the terminal or turns echo off,
     and Aelix ends it and tells you why instead of waiting out its ten-second timeout (the resolver
     detects the stop in about 0.05 s, measured under a real pty on macOS and Linux; what you wait
     is that plus Aelix's own startup). This is a deliberate difference from Pi, which runs the
     helper in its own foreground group."*
   - **가족별로 갈라 적는다.** askpass는 **ssh의** 해법이고 gpg의 해법이 **아니다**(gpg는
     `SSH_ASKPASS`를 안 본다 — 에이전트에게 묻는다). ssh/sudo/git 계열: askpass, OS 키체인. gpg/pass
     계열: Aelix 밖에서 키를 한 번 풀어 에이전트 캐시가 답하게 하기(실측 0.115–0.118 s),
     `gpg-preset-passphrase`, passphrase 파일과 함께 `--pinentry-mode loopback`, 또는 GUI
     pinentry(`pinentry-mac`, **미측정이라고 적는다**). 어느 가족이 빠른 이름 붙은 실패를 받고 어느
     가족이 여전히 10 s를 기다리는지 분명히 적는다.
   - 답 없는 askpass/GUI 프롬프트는 **여전히 풀 타임아웃을 태운다**(§G).
   - `!command`는 읽지는 못해도 **터미널에 쓸 수는 있다**(실측: `sudo`·`openssl`은 프롬프트를 찍고
     실패했다). `!command`가 echo를 끈 채 죽었으면 `stty sane`(또는 `reset`)으로 복구한다.
   - `models.json`뿐 아니라 `auth.json`의 `key`도 같은 규칙이라고 적는다.
   - win32 조항: 콘솔을 직접 읽는 헬퍼는 거기서 프롬프트를 띄울 수 있고, 답이 없으면 10 s를 태운다 —
     아무도 본 적 없다.

**봐야 하는 것.** `main`: ~10 s 무반응 뒤 원인 없는 `Failed to resolve …`; 다른 페인의
`ps -o stat=,comm= -g <pgid>`가 `T sh`. 브랜치: 1 s 안에 같은 접두사 + ` — The command stopped
reading the terminal (SIGTTIN): …`. `time`의 실수를 둘 다 기록한다(이게 CHANGELOG에 쓸 end-to-end
숫자다 — 리졸버 내부 0.054 s와 구분해서 적는다).

1. **SIGTTOU — 두 arm 다 돌린다.** 각 arm 전후로 `stty -a | grep -o -- '-\?echo'`를 찍는다.
   (a) `"apiKey":"!sh -c 'stty -echo </dev/tty; echo x'"` → 이름 붙은 SIGTTOU 실패, echo **켜진 채**
   (실측: 0.051 s에 정지, 터미널 무사).
   (b) `"apiKey":"!sh -c \"trap '' TTOU; stty -echo </dev/tty; echo x\""` → **이름 붙은 실패 없음**,
   resolution이 `x`로 **성공**하고 터미널에 `-echo`가 남는다(실측 rc 0). 이건 예상된 결과다;
   `stty sane`으로 되돌린다. 🔴 revision 1의 "자식은 tcsetattr가 적용되기 전에 멈춘다"는 기본
   disposition에서만 참이라 삭제했다.
2. **gpg-agent 중재의 NEGATIVE를 기록한다.** passphrase 걸린 키에 `!gpg -d …`(에이전트 캐시 비운
   상태, tmux) → **~10 s, 이름 없는 원인**을 기대하고 그대로 적는다. 이어서 캐시를 데운 뒤 같은
   명령 → 빠른 성공. 가이드의 새 문장이 주장이 아니라 측정이 되게 하는 케이스다.
3. **캐시 경로(`auth.json`) — 이 예외가 실제로 서비스하는 경로.** §E의 나머지는 전부 uncached라서

## §G. Risks / open questions / out of scope

- **`!command`는 더 이상 자기 pgid를 핀하지 않는다.** 정지 프로브가 exit한 리더를 reap한다. stdout
  보유자가 그룹을 떠난 모양(`setsid`)에서는 ~0.055 s부터 `hard_kill`의 10 s까지 그룹이 비고
  `killpg`는 주인 없는 번호를 겨눈다(실측 darwin·linux 모두 ESRCH). 그 모양에서는 `main`에서도
  `killpg`가 아무것도 못 했으므로(자손이 양쪽 arm 다 생존) **잃는 것은 없고**, 생기는 것은 ADR-0238이
  수용한 재사용 위험의 ~9.95 s 창이다. 그룹에 남은 자손이 있으면 여전히 `CLAIMED`.
- **`SIGTTOU`를 블록/무시하는 헬퍼는 POSIX가 허용하고 탐지되지 않는다.** 이어서 읽으면 SIGTTIN으로
  멈추고 우리 `SIGKILL`이 복원 루틴을 못 돌게 하므로 **터미널이 echo 꺼진 채 남을 수 있다**(실측
  darwin + linux/dash: `trap '' TTOU; stty -echo`는 rc 0 + echo off; ignore-then-read는 0.051 s에
  탐지되지만 그때 이미 echo off). 복구는 `stty sane`. 반대로 **CAUGHT** SIGTTOU(`tcsetattr`가 EINTR로
  실패)와 **무시된** SIGTTIN(read가 EIO)은 똑같이 안 보이지만 무해하다 — 둘 다 스스로 즉사한다.
  미측정: 출하되는 신용 헬퍼 중 실제로 이렇게 하는 것이 있는지. 시험한 실물 다섯(pinentry-tty,
  pinentry-curses, ssh readpassphrase, sudo, git+stty)은 전부 기본 disposition이고 전부 탐지됐다.
  🔴 **spawn 전후로 termios를 스냅샷/복원하지 않기로 한다** — 실패 경로에서 되돌리면 이 구멍이 닫히지만,
  성공한 `!command`가 **의도적으로** 바꾼 설정까지 되돌리게 되고 이 이슈의 메시지 delta 범위를 넘는다.
- **gpg-agent가 중재하는 passphrase 프롬프트는 탐지기에 안 보인다** — pinentry는 우리 그룹도 우리
  세션도 아니다. `!gpg -d`/`!pass show`는 여전히 풀 10 s. 정직한 절반: 그 pinentry는 우리 kill보다
  오래 살지 않는다(35–37 ms 뒤 사라지고 ECHO 복구).
- **답 없는 askpass/GUI 프롬프트도 타임아웃을 태운다** — 터미널을 읽지 않아 정지하지 않는다.
  가이드·CHANGELOG가 그렇게 적는다. 🔴 **원인 문자열에는 이 단서를 넣지 않는다**(이미 ~250자이고
  §E.5-c가 화면 도달을 의심한다) — 가이드와 CHANGELOG가 진다.
- **POSIX 전용 `os`/`fcntl`/`termios`/`pty` 이름은 제품 코드에서 `# pyright:
  ignore[reportAttributeAccessIssue]`를 달아야 한다.** darwin의 호스트 pyright는 빠진 것을 못 잡는다.
  `tests/`는 pyright `include` 밖이라 §C의 pty 레시피는 무관하다.
- **`refute-PRODUCT-3/refute3b.py`의 3단 레시피(shell → aelix → helper)가 이 표면의 올바른 계측기다.**
  `pty.fork`한 부모는 고아 세션 리더라 SIGTTIN이 EIO(errno 5)로 바뀐다 — 앞으로 이 표면을 테스트할 때
  조용히 잘못 재는 함정.
- **win32 절반은 사람이 본 적 없다.** ADR·가이드·README가 미검증이라고 적는다(#221/#222와 동일).
- **hooks 사이트(`subprocess_hooks.py`)는 같은 정지 모양 — 포팅은 범위 밖.** 자기 asyncio 사다리를
  쓰고(`ThreadedChildWatcher`가 `waitpid(pid, 0)`로 블록 — 정지에는 영영 안 돌아온다) 탐지기는 동기
  코드다. 규모는 이 사이트보다 크다: 기본 60 s(최대 600 s), 이벤트마다 발화. 이번 커밋은 **주석 한 줄
  (§D.8)과 ADR "What stays open" 불릿(§D.3)**만 하고, **후속 이슈를 그 문장으로 판다**.
- **#227이 같은 파일을 만진다** — 같은 배치에 넣지 말 것(handoff §2).
- **오너에게 물을 것 (셋).**
  (1) 타임아웃(정지가 아닌)에도 이름 붙은 원인을 줄 것인가? 이번에는 안 준다 — Pi-verbatim 문자열을
  그대로 두기 위해서.
  (2) §A.6-b의 pgid 창을 닫기 위해 `os.waitid(…, WNOWAIT)` 플랫폼 분기를 넣을 것인가? 실측으로
  linux에서 동작하고 §G의 "정지 통지는 한 번뿐" 단서까지 없앤다. 이번에는 **거절** — 게이트 POSIX
  레그가 linux뿐이라 분기하면 darwin의 reap-repair 경로가 CI에서 한 번도 안 돈다.
  (3) `SIGTTOU`를 무시하는 헬퍼가 남긴 echo-off를 termios 스냅샷/복원으로 닫을 것인가? 위 이유로 거절.
