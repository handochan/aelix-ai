# Aelix Trademark and Brand Policy

The Aelix **software** is Apache-2.0 and you may do anything the licence allows
with it. The Aelix **name and logo** are a separate thing, and this file says
what you may do with those.

That separation is not a trick — it is written into the licence you already
have. Apache-2.0 §6: *"This License does not grant permission to use the trade
names, trademarks, service marks, or product names of the Licensor, except as
required for reasonable and customary use in describing the origin of the
Work."* This policy grants more than §6 does, not less.

## What is claimed here

- The word **Aelix**, used for agent-runtime and developer-tooling software.
- The **A×X mark**, the **Aelix wordmark**, and the lockups built from them —
  the vectors in [`docs/assets/brand/`](docs/assets/brand/), described in
  [`BRAND.md`](docs/assets/brand/BRAND.md).

**Aelix is an unregistered mark.** There is no registration in any country, so
it is written **Aelix™**, never *Aelix®* — using ® for an unregistered mark is
itself a false statement and this project does not make it. The claim rests on
use: the name has been used publicly and continuously for this software since
**16 May 2026**, the date this repository was first published.

Other, unrelated parties use the word "Aelix" in other fields — pharmaceuticals,
energy, consulting, and more. Nothing here claims the word globally or against
them. This policy is about this software and the goodwill attached to it.

## You do not need permission to

- **Use, run, fork, modify and redistribute the software** under Apache-2.0.
  The licence governs; this file does not add conditions to it.
- **Say true things about Aelix**, including in the name of your own project:
  "works with Aelix", "an Aelix extension", "built on Aelix", "Aelix-compatible",
  "a Python SDK for Aelix". Descriptive, truthful reference is fair use and is
  explicitly welcome — an extension ecosystem cannot exist without it.
- **Name your extension package** `aelix-<something>` on PyPI or elsewhere, as
  long as the name describes what it does and does not read as an official
  first-party release. `aelix-snowflake-tools` is fine. `aelix-official` is not.
- **Redistribute unmodified builds** under the name Aelix — a distro package, a
  container image, a mirror. Keep the version identifiable.
- **Use the mark and wordmark** to link to or illustrate the project: articles,
  talks, comparison tables, screenshots, course material, a "runs on Aelix"
  badge. Use the files as published; see the rules in `BRAND.md` (no stretching,
  no recolouring, no re-spacing, clear space of two mark modules).

No permission request, no attribution boilerplate, no fee. If your use is
covered above, stop reading.

## Please ask first before

- **Shipping a modified build under the name Aelix.** Patch it, rename it, and
  say it is derived from Aelix — that is the ordinary open-source convention and
  it is what keeps "Aelix" meaning one thing. If you need the name on a patched
  build (a distro often does), ask; it is usually granted.
- **Naming a company, product, service or domain** Aelix or something close
  enough to be mistaken for it.
- **Using the mark as your own icon** — app icon, org avatar, package logo,
  favicon — where a reader would take it as the source of *your* thing.
- **Anything that states or implies endorsement, affiliation, certification or
  partnership**, including "official", "certified", "powered by the Aelix team".
- **Merchandise** carrying the name or mark.

## Not permitted

- Registering **Aelix**, or a confusingly similar mark, as a trademark, company
  name, or domain in the software field.
- Using the name or mark on anything that misrepresents its origin — a fork
  presented as the upstream project, a modified binary presented as an official
  release, a paid service presented as run by this project.

## Asking

Open an issue on
[github.com/handochan/aelix-ai](https://github.com/handochan/aelix-ai/issues)
titled *Trademark request*, describing the use. There is no e-mail alias and no
form; the issue tracker is the route that actually works. Expect a plain yes or
no.

## For maintainers of this project

Keep this file accurate as facts change. In particular: the moment a
registration issues anywhere, update the "unregistered" statement above and only
then start using ® — and only in the jurisdiction where it registered.
